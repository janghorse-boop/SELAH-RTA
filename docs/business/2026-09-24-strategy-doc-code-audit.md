# 가격·구독 전략 문서를 코드에 비춰 본 결과

날짜: 2026-09-24
대상: [2026-09-24-pricing-subscription-strategy.md](2026-09-24-pricing-subscription-strategy.md) (문서 0.1)

전략 문서는 **결제 구현 지시가 아니다**(문서 8장). 그래서 결제·요금제·기능
잠금은 **아무것도 만들지 않았다.** 대신 그 문서가 **지금 코드에 요구하는
것**만 골라 반영하고, 확인한 것과 못 한 것을 여기 적는다.

## 고친 것

### 1. 마법사 1단계가 EMM-6 만 가정하고 있었다

문서 3장 「측정 마이크 표현 원칙」은 **iMM-6C 와 EMM-6 을 둘 다 정식 측정용**
으로 다루라고 한다. 그런데 1단계는 팬텀전원(+48V) 확인을 **모두에게** 요구하고,
확인하지 않으면 **막았다**(`equipmentGate`).

USB 직결 마이크에는 그 스위치가 없다. 즉 iMM-6C 사용자는 **자기 장비에 없는
스위치를 켰다고 체크해야만** 다음으로 갈 수 있었다. 거짓을 체크하게 만드는
관문은 관문이 아니다.

`ReferenceHookup`(XLR+인터페이스 / USB 직결)을 물어보고, **XLR 일 때만**
+48V 를 확인한다. 품질 등급이 아니라 **확인할 것이 다를 뿐**이라고 화면에
적는다. XLR 경로의 기존 안전장치는 그대로다.

### 2. 기준 마이크를 EMM-6 으로 못박아 부르던 문구

「EMM-6 CAL 파일을 불러오지 않았습니다」, 「기준(EMM-6)」, 「EMM-6 에서 신호가
들어오지 않습니다」 등. 전부 **기준 마이크**로 바꿨다. 단계 이름도
「장비 · CAL · +48V」 → 「장비 · CAL · 연결 확인」.

### 3. 품질 등급 표현

**찾아봤으나 하나도 없었다** — 「간편형/정밀형/입문용/전문용/보급형/고급형」
어느 것도 코드·문서에 쓰인 적이 없다. 10장 체크리스트의 해당 항목은
지울 것이 없어 통과다. 다시 들어오지 못하게 `CLAUDE.md` 6장에 못박았다.

## 확인만 한 것 (이미 맞았다)

| 문서가 요구한 것 | 코드 상태 |
|---|---|
| 권장범위의 **가중치** 표시 | 「dBA」로 표시. **A 가중일 때만 판정**하고, C·Z 일 때는 색을 칠하지 않고 까닭을 글자로 적는다(`MeasureScreen.canJudge`) |
| 권장범위 **현장별 조정** | 구간마다 「고치기」로 수정·초기화 가능(`SegmentRangeCard`) |
| 권장범위가 **공식 기준이 아님** 명시 | 화면과 코드 주석 모두에 있다(`SEGMENT_CAUTIONS`, 명세 18장) |
| MAX 와 PEAK 를 섞지 않음 | 「짧은 최대(MAX)」로 이름을 못박았다 — PEAK 는 가중 전 파형이라 dBA 가 아니다(독립 검증 R10) |
| RTA 와 전달함수를 혼동하지 않음 | 전달함수·위상·코히어런스를 구현한 적도, 약속한 적도 없다. UI 문구에 없다 |
| 보정파일 적용 ≠ 절대 SPL 교정 | 갈라져 있다. 2026-09-24 에 곡선을 1kHz 에 못 박아 **둘이 서로 독립**이 되었다([결정](../decisions/2026-09-24-curve-anchored-at-1khz.md)) |

## 찾았지만 **고치지 않은 것** — 다음에 판단할 것

### 권장 「평균」 범위를 순간값과 견주고 있다

코드의 정의는 분명하다 — `ReferenceRange.avg` 는 **시간평균(LAeq) 기준**이다
(`Measurement.kt`). 그런데 화면은 **순간 시간가중 음압**(`meter.currentSpl`)을
그 범위와 견주어 계기 색을 칠한다(`MeasureScreen.kt`).

순간값은 Leq 보다 훨씬 크게 출렁이므로, 실제 Leq 가 범위 안에 얌전히 있어도
말 한마디에 계기가 빨개진다. 카드도 「권장 평균 78~85 dBA」라고만 적고
**어느 숫자와 견주라는 말이 없다.**

문서 3장이 「평균시간 표시」를, 10장이 「권장범위의 근거와 조건을 명확히
표시」를 요구한 자리가 바로 여기다.

**고치지 않은 까닭**: 계기 색은 이 앱의 주된 실시간 되먹임이다. Leq 기준으로
바꾸면 반응이 Leq 창(예: 1분)만큼 느려진다. 어느 쪽이 현장에 맞는지는
**담당자가 정할 일**이고, 가격 문서를 근거로 혼자 바꿀 일이 아니다.

선택지는 셋이다:

1. Leq 타일을 평균 범위로 판정하고, 계기는 색을 빼거나 다른 기준으로 칠한다
2. 계기는 그대로 두되 **「지금 값」과 「권장 평균」이 다른 잣대임을 화면에 적는다**
3. 범위를 두 벌로 둔다 — 순간값용과 평균용

## 만들지 않은 것 (의도적으로)

- 결제·구독·요금제 분기·기능 잠금·체험 기간 계산 — **하나도 없다**
- 4,900원·49,000원·14일·5,900원·8,900원 같은 숫자를 코드에 넣지 않았다
- 스토어 상품 ID, 구매 복원, 자동 갱신 처리 — 없다

문서 8장이 「확정 요구사항으로 하드코딩하지 않는다」고 한 그대로다.
출시 결정과 승인된 상품 설정이 나온 뒤에 별도 지시로 한다.

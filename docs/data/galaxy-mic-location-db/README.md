## 2. 완료 범위와 미완료 범위

문서에서 위치를 확인한 제품명 기준 **25종**: 스마트폰 15종, 태블릿 10종. 마이크 위치 상세 행은 **67개**다.
통신사·국가별 SKU 개수가 아니라 제품명별 레코드 수다.

스마트폰: S20/S20+/S20 Ultra, S21/S21+/S21 Ultra, S23/S23+/S23 Ultra, S24/S24+/S24 Ultra, S25/S25+/S25 Ultra.

태블릿: Tab S6 Lite(2022), Tab S7 FE, Tab S8/S8+/S8 Ultra, Tab S9/S9+/S9 Ultra, Tab S10+/S10 Ultra.

**S22 시리즈는 이번 판에서 위치 확인을 완료하지 못했다.** Tab S7/S7+, S9 FE 계열, A9 계열, S6 Lite 다른 연식,
S10 FE 계열, S11 계열 등을 포함한 16개 모델은 `pending_models`와 ‘조사대기’ 시트에 분리했다.
이 밖의 모델도 모두 지원한다는 의미가 아니다. 조사대기 항목은 지원 완료 목록에 포함하지 않는다.

실기기 실험은 수행하지 않았다. ‘확인’은 문서의 마이크 라벨·지시선·적용 모델코드 확인을 뜻한다.

## 3. 반드시 구분해야 하는 세 가지 숫자

1. `documented_mic_location_count`: 검토한 삼성 도면에 마이크로 명시된 **외관상 위치의 수**.
2. `physical_microphone_capsule_count`: 기기 내부 마이크 부품 총수. 이번 DB는 전 모델 `null`.
3. 활성 입력 마이크 수: 실행 중 Android가 보고하는 값. 정적 DB에서 제공하지 않는다.

예를 들어 Tab S8 기본형·Plus 도면에는 마이크 위치가 2곳 표시되고 Ultra에는 3곳 표시된다.
그 이유만으로 기본형·Plus의 내부 마이크 부품이 반드시 2개라고 단정해서는 안 된다.
Tab S9/S10 도면에 없는 후면 마이크를 제3자 사양이나 외관의 점을 보고 추정해서 추가하지 않는다.

S20 Ultra 도면에는 한 Microphone 라벨에서 두 위치로 지시선이 분기된다.
따라서 라벨 단어 수가 아니라 실제 지시선 끝 위치를 세었다.

**앱 문구:** “공식 도면에서 확인된 마이크 위치: N곳”  
**피해야 할 문구:** “이 기기의 전체 마이크: N개”, “현재 N개 마이크로 측정 중”을 이 DB만으로 표시.

## 4. 출처와 적용 국가

삼성전자서비스의 한국어 안내와 삼성전자가 작성한 사용설명서를 사용했다.
일부 설명서는 삼성 다운로드 서버 대신 Argos, Croma, Geizhals, Manuals+의 **외부 미러에서 열람**했다.
‘삼성이 작성한 문서’와 ‘삼성 사이트에서 직접 내려받은 파일’은 다른 속성이다.

`sources[].hosting`이 `official`인지 `external_mirror`인지 보존한다.
`url`은 실제 열람한 근거이고 `related_official_support_url`은 관련 공식 제품 지원 페이지다.
후자를 실제 PDF 다운로드 원본이라고 표시하지 않는다.

유럽/기타 지역 문서의 B/F/U1/E형 코드가 확인됐다고 국내 N형까지 확인됐다고 처리하지 않는다.
S23 서비스 안내는 국내 제품명별 위치를 확인할 수 있지만 해당 페이지에서 기기 모델코드를 대조 완료한 것은 아니다.
따라서 S23 3종의 `documented_model_codes`는 빈 배열이고 자동 매칭을 비활성화했다.
수동 제품명 선택을 통한 참고 안내는 가능하며, 실제 사용자의 한국형 기기와 코드 일치를 추가 확인하면 별도 개정한다.

매뉴얼에 적힌 `/DS`, `UD` 등의 표기는 그대로 기록했다. 이것이 실제 Android `Build.MODEL` 반환값과
모든 기기에서 똑같다는 뜻은 아니다.

## 5. 앱 통합 지시

### A. 기존 오디오 기능과 분리

DB는 위치 안내 계층에만 사용한다. 기존 DSP, 녹음, 입력 선택, 캘리브레이션 동작을 이 DB 때문에 변경하지 않는다.
DB 레코드의 `location_key`는 UI용 고유 키이며 Android `MicrophoneInfo.getId()` 값이 아니다.

### B. 정확한 모델코드만 자동 조회

`Build.MANUFACTURER`가 Samsung인지 확인하고 `Build.MODEL`의 앞뒤 공백 제거 및 대문자 변환만 허용한다.
`documented_model_codes`와 정확히 일치할 때 문서 기반 안내를 불러온다.

접미사를 삭제하거나, `SM-S9` 같은 접두사로 여러 세대를 묶거나,
Plus/Ultra/FE/연식이 비슷하다는 이유로 다른 레코드를 적용하지 않는다.
국내 코드가 없는 경우 ‘해당 모델의 위치 정보 미확인’을 표시한다.

모델명 수동 선택은 “참고 도면”으로 구분하며 자동 검증 상태를 바꾸지 않는다.
`pending_models`는 자동 매칭 대상에 넣지 않는다.

### C. 방향 기준

스마트폰: 세로로 세워 화면을 정면에서 본 기준.
대부분의 탭: **가로, 전면 카메라 위, USB-C 오른쪽** 기준.
S6 Lite(2022): **세로, 전면 카메라 위, USB-C 아래** 기준.

화면 회전과 물리적 위치 정의를 혼합하지 않는다. 도면을 회전해서 표시할 경우 해당 좌표계도 함께 변환해야 한다.
이번 DB의 `normalized_diagram_coordinates`는 전부 `null`이다.
텍스트 설명만 보고 픽셀 좌표를 임의 생성하지 않는다. 오버레이 제작은 별도 원본 검토가 필요하다.

### D. 실제 활성 마이크는 실행 중 조회

Android `AudioRecord.getActiveMicrophones()`는 API 28 이상에서 사용한다.
권한을 확인하고 실제 녹음을 시작한 후 조회하며 `IOException`, 불충분한 제조사 정보 등을 안전하게 처리한다.
활성 마이크는 녹음 도중 변경될 수 있으므로 장치 라우팅 변경, AudioRecord 재생성, 입력 설정 변경 후 다시 확인한다.
매 오디오 프레임마다 조회하지 않는다. 제조사 제공 정보만으로 물리 홀 대응이 완전히 검증됐다고 표시하지 않는다.

`AudioManager.getMicrophones()`의 `channelMapping`이 비어 있는 것은 무조건 오류가 아니다.
실제 녹음 채널 매핑은 `getActiveMicrophones()`에서 얻은 `MicrophoneInfo`를 확인한다.
`PROCESSED` 매핑에는 여러 마이크의 조합이 포함될 수 있다.
`DIRECT`라고 해도 이 DB의 특정 위치와 자동으로 동일시하지 않는다.

입력 장치를 선호 장치로 지정하는 기능과 물리 마이크 한 개를 독립 선택하는 기능을 혼동하지 않는다.
‘하단/상단/후면 개별 선택’ 버튼은 실기기에서 별도로 검증하기 전까지 생성하지 않는다.

### E. 캘리브레이션 연결

기기 모델별 공통 `+2.6 dB` 같은 값을 만들지 않는다.
캘리브레이션은 실제 입력 장치, AudioSource, 채널, 샘플레이트 및 처리 상태를 포함한 **녹음 경로**를 기준으로 관리한다.
위치 DB의 마이크 수나 위치 변화만으로 음압 보정값을 산출하지 않는다.
`default_spl_offset_db = null`은 0 dB 보정 완료가 아니라 교정값을 제공하지 않는다는 뜻이다.

물리 위치 안내, 실행 중 마이크 진단, SPL 교정 프로파일의 UI와 데이터 모델을 분리한다.
휴대폰 구멍에 핀을 삽입하거나 일반 측정마이크용 음압 교정기를 억지로 밀폐 결합하도록 안내하지 않는다.

## 6. 표시 예시

```text
내장 마이크 위치 안내
Galaxy S23 Ultra
공식 도면에서 확인된 마이크 위치: 3곳
- 상단 프레임
- 하단 USB-C 주변
- 후면 상단 카메라 렌즈 테두리

자료: 삼성전자서비스 / 제품명 수동 선택 참고
현재 기기 모델코드와의 자동 일치: 미확인
현재 녹음에 사용되는 마이크: 실행 중 확인
```

도면의 에어벤트를 마이크로 표시하지 않는다.
S23은 하단 에어벤트, 검토한 S24/S25 도면은 상단 에어벤트를 표시하므로 세대 간 복제하지 않는다.
원본 이미지 자체를 이 파일 묶음에 재배포하지 않았다. 앱에 원본 도면을 포함할 경우 사용 조건을 별도 검토한다.

## 7. 개발 완료 기준

- JSON 로드 및 스키마/교차 참조 검증 성공.
- 제품 ID·코드·위치 ID 중복 없음. count와 locations 길이 일치.
- `SM-X710`은 `tab_s9`의 문서 기반 참고 정보와 일치.
- `SM-S921B`는 `s24`와 일치하나 `SM-S921N`은 이 판에서는 미확인.
- `SM-S918N`은 이 판에서는 자동 일치하지 않으며 S23 Ultra 수동 참고만 가능.
- Tab S8 기본형의 상단 위치는 카메라 오른쪽, Plus/Ultra는 왼쪽으로 서로 다르게 유지.
- Tab S8/Plus에 Ultra 후면 위치를 추가하지 않음.
- 모든 미검증 런타임/교정 필드를 null로 유지.
- 에어벤트·스피커·SIM 트레이 배출구를 마이크로 오인하지 않음.
- 미일치·API 실패 시 추정 ID, 추정 위치, 기존 다른 모델의 보정값을 대신 사용하지 않음.

검증 예시:

```bash
python validate_db.py ToneVista_Galaxy_Microphone_DB_v0_1.json
python validate_db.py ToneVista_Galaxy_Microphone_DB_v0_1.json --model SM-X710
python validate_db.py ToneVista_Galaxy_Microphone_DB_v0_1.json --model SM-S918N
```

마지막 명령의 예상 상태는 `unknown`이다. 이는 버그가 아니라 미검증 국내 코드에 대한 보수적 처리다.
검증 스크립트는 데이터 무결성을 검사할 뿐, 모든 기기의 실제 마이크 위치를 물리적으로 입증하지 않는다.

## 8. 개정 절차

새 모델은 조사대기에 먼저 추가한다.
모델별 원본 도면에서 마이크 라벨/지시선/기준방향을 확인하고, 표지의 적용 코드와 함께 근거를 기록한 후에만
`models`로 이동한다. 같은 모델의 국가형 확장도 별도 코드 대조가 필요하다.
출처 URL, 도면 인쇄 페이지, PDF 0기준 페이지 인덱스, 검토일, 외부 미러 여부를 보존한다.
이번 문서들의 인쇄 페이지와 PDF 인덱스는 `index = page - 1`이지만 새 문서에 무조건 적용하지 않는다.

JSON이 원본이므로 개정 후 엑셀과 요약 counts를 함께 갱신하고 검증 스크립트를 실행한다.

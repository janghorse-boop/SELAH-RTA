## 1. 목적과 최상위 원칙

악기별로 어떤 주파수 영역을 들어볼지 설명하고, RTA 위에 참고 영역을 겹쳐 보여주며, 사용자가 믹서에서 조정한 전후 변화를 비교한다. 사용자가 “왜 이 부분을 조정하는가”를 이해하고 전체 합주에서 판단하도록 돕는다.

**고정 EQ 처방, 자동 음질 판정, 자동 믹서 제어 기능이 아니다.** 같은 주파수가 바디를 만들기도 하고 먹먹함을 만들기도 한다. 음색, 음역, 연주법, 마이킹, 공간, 스피커, 편곡에 따라 적절한 선택이 달라진다. 악기 스펙트럼을 평탄하게 만드는 것을 목표로 삼지 않는다.

필수 원칙:

1. 내장 마이크와 USB 측정 마이크를 모두 정식 지원한다. USB가 없어도 가이드·측정·비교·프리셋을 사용할 수 있다.
2. 입력이 없으면 측정값과 탐지 결과를 만들지 않는다. 정적 가이드는 마이크 권한 없이 열람 가능하다.
3. 객석에서 측정한 신호는 악기, PA, 공간, 다른 악기의 합이다. 선택한 악기의 분리 신호라고 표현하지 않는다.
4. RTA만으로 좋은 소리, 음원별 마스킹, 피드백, 고장, EQ 원인을 확정하지 않는다.
5. EQ 변경은 외부 믹서·악기에서 사용자가 한다. 앱의 영역 선택·프리셋 불러오기는 오디오를 변경하지 않는다.
6. 기준 마스터 명세의 보정, 녹음 동의, lifecycle, 단일 PCM 입력 원칙을 유지한다.
7. 구현 완료와 독립 검증 완료를 구분한다. Critical/High 미해결 상태에서는 이 기능의 릴리스를 승인하지 않는다.

## 3. 안내 문구와 EQ 사용 원칙

첫 진입 및 도움말 고정 문구:

> 이 가이드는 들어볼 주파수 영역을 안내합니다. 표시된 영역이 높거나 낮다고 반드시 문제가 있는 것은 아닙니다. 같은 위치·입력으로 비교하고, 마지막에는 전체 합주를 들으며 판단하세요. EQ는 믹서에서 직접 조정합니다.

| 표현 | 의미 및 제한 |
|---|---|
| 바디 | 두께와 무게감. 과하면 먹먹하거나 다른 악기를 가림 |
| 펀치 | 타격의 무게와 순간적 힘. 평균 RTA만으로 시간적 펀치를 평가할 수 없음 |
| 명료도 | 음정·음형·리듬이 구분되는 느낌. 저중역 정리로도 개선 가능 |
| 어택 | 피킹·비터·스틱 등 시작 부분. 주파수뿐 아니라 시간 포락선 영향 |
| 존재감 | 전체 믹스에서 잘 들리는 성질. 무조건 전체 볼륨/고역 증가를 뜻하지 않음 |
| 공기감 | 상부 배음·잔향·개방감. 모든 악기에 필요한 목표가 아님 |

초기 청취 실험 제안은 넓은 bell, Q 약 0.7~1.4, ±1~3 dB 정도의 작은 변화로 시작한다. 이는 제품의 안내값이며 최적값·안전 한계·자동 적용값이 아니다. 좁은 공진 컷은 실제로 귀로 찾은 경우에만 별도 설명하고 31밴드 결과로 정확한 중심/Q를 산출하지 않는다. 보컬이 묻히면 악기 존재감 부스트보다 편곡·페이더·겹치는 영역 정리를 먼저 비교한다.

HPF는 저음을, LPF는 고음을 점진적으로 줄인다. 차단주파수가 완전 제거 경계인 것처럼 그리지 않는다. 기본 안내 기울기는 12 dB/oct, 필요 시 6/18/24 dB/oct와 차이를 설명하되, 필터 유형마다 차단점·공진·위상 특성이 다름을 명시한다. 처음에는 bypass에서 출발하고 원하는 두께/선명함이 줄면 되돌린다. 큰 부스트, 여러 밴드 누적 부스트, 저역 부스트는 헤드룸을 줄인다. 실연 PA에서 큰 부스트로 주파수를 훑는 절차는 기본 안내에 넣지 않는다.

아래 수치는 통용되는 EQ 개념을 참고해 만든 **제품용 청취 탐색 범위**이며 표준·정상범위·자동 판정 임계값이 아니다. 영역은 의도적으로 겹친다. 모든 특성을 인위적으로 모든 악기에 할당하지 않는다. 출처와 편집 원칙은 17장을 참조한다.

## 4. 악기별 주파수 가이드

단위는 별도 표기가 없으면 Hz. “문제”는 사용자가 해당 증상을 들을 때 조사할 범위다. 실제 좁은 공진 주파수는 악기와 공간에 따라 달라진다.

### 4.1 신디사이저

필수 세부 선택: 피아노/EP, 패드/스트링, 리드/브라스, 신스 베이스, 기타/복합. 신디사이저 전체에 단일 EQ를 적용하는 기본 프리셋을 만들지 않는다. 피아노와 EP의 차이는 설명 카드와 사용자 변형으로 제공한다.

| 세부 음색 | 주요 영역·성격 | 문제를 들을 때 조사할 영역 | HPF / LPF 청취 시작점 |
|---|---|---|---|
| 피아노/EP | 60~200 바디, 200~500 온기, 1~3 kHz 명료도, 2~5 kHz 건반 어택, 8~12 kHz 개방감 | 150~500 먹먹함, 500~1 kHz 상자 느낌, 2~5 kHz 딱딱함 | HPF 30~60(독주·저음 유지), 70~120(합주 역할에 따라); LPF bypass, 거칠거나 잡음이 있을 때 12~16 kHz |
| 패드/스트링 | 150~500 두께, 1~3 kHz 존재감, 6~12 kHz 밝기/공기감; 펀치·어택은 보통 주목표 아님 | 150~400 저중역 누적, 1~4 kHz 보컬과 충돌 가능, 6~10 kHz 거친 질감 | HPF 100~200(저역 역할 없음); LPF 8~14 kHz 또는 bypass |
| 리드/브라스 | 150~600 바디, 700~2 kHz 음형, 2~5 kHz 어택/존재감, 8~12 kHz 밝은 배음 | 300~800 답답함/콧소리, 2~6 kHz 날카로움 | HPF 70~150; LPF 8~12 kHz 또는 bypass |
| 신스 베이스 | 25~80 서브, 60~150 무게/펀치, 150~350 바디, 700~2 kHz 음정 식별, 2~5 kHz 질감 | 40~120 붕붕거림, 150~400 먹먹함, 의도적 공진을 문제로 오인 | HPF bypass 또는 20~30; LPF 3~8 kHz는 질감 선택용 |
| 기타/복합 | 패치에 따라 전대역. 두 겹 이상의 역할을 사용자가 기록 | 범용 정상 곡선 없음 | 두 필터 모두 bypass, 역할 확인 후 선택 |

패치·옥타브·레이어·필터 resonance·내장 EQ/리버브를 먼저 확인한다. 패드의 고역이 적거나 필터 스윕 피크가 이동하는 것은 정상 표현일 수 있다. 패치 변경 시 누적 탐지와 A/B 재측정을 요구한다. 스테레오 패치를 모노 마이크로 측정한 결과는 스테레오 이미지나 전기적 L/R 합산 응답이 아니다.

### 4.2 어쿠스틱 기타

선택: 마이크 / 픽업·DI를 PA로 재생 / 혼합, 스트로크 / 핑거스타일, 독주 / 합주.

| 영역 | 청취 포인트 | 조정 주의 |
|---|---|---|
| 80~150 | 낮은 현의 무게·바디 | 붕붕거림과 필요한 기음을 구분 |
| 150~350 | 풍성함·바디, 과하면 먹먹함 | 지나친 컷은 얇은 소리를 만듦 |
| 350~800 | 나무 울림, 박스톤 후보 | 마이크 위치·몸통 공진을 먼저 확인 |
| 1~2.5 kHz | 음형 명료도·존재감 | 픽업 질감과 보컬 간섭을 함께 청취 |
| 2~5 kHz | 피크/손톱 어택, 단단한 질감 | 과하면 까칠함·피에조 특유의 거친 느낌 |
| 6~10 kHz | 현 마찰·밝기 | 손가락 잡음도 함께 커짐 |
| 10~14 kHz | 공기감 | 픽업 신호에 없는 공기감을 부스트로 복원하려 하지 않음 |

HPF: 60~80(낮은 현·독주 보존), 80~120(합주), 120~150은 저역 역할이 불필요한 경우에만 시험. 표준 튜닝 최저 E가 약 82 Hz이므로 이 부근 필터도 음색을 바꾼다. 드롭 튜닝은 더 낮다. LPF: 기본 bypass, 잡음/거친 최상단을 줄일 때 10~14 kHz 시험. 펀치는 별도 고정 대역보다 스트로크 어택과 바디의 균형으로 설명한다.

부밍은 사운드홀 정면 근접 배치·모니터·공간의 영향일 수 있다. EQ보다 마이크를 약간 옮기는 비교가 효과적일 수 있다. 컷 전후 전체 합주에서 두께가 유지되는지 듣는다.

### 4.3 일렉기타

선택: 클린 / 크런치 / 하이게인, 앰프 마이킹 / 모델러·캐비닛 시뮬레이션을 PA로 재생. 캐비닛 처리 없는 DI는 정상 앰프 음색 기준과 비교하지 않는다.

| 영역 | 청취 포인트 | 문제 후보·주의 |
|---|---|---|
| 80~180 | 저음현·팜뮤트 무게/펀치 | 킥·베이스와 저역이 겹침 |
| 150~400 | 바디 | 과하면 뭉침, 과도한 컷은 빈약함 |
| 400~900 | 중역 질감 | 박스톤/콧소리 후보이면서 필요한 개성 |
| 800~2 kHz | 음정·코드 명료도 | 전체 믹스에서 식별 여부 확인 |
| 2~4 kHz | 피킹 어택·존재감 | 보컬과 충돌하거나 귀를 찌를 수 있음 |
| 4~8 kHz | 디스토션 질감·거친 고역 | fizz 후보. 마이크 각도·캐비닛 IR도 확인 |
| 8~12 kHz | 클린/효과음의 개방감 | 일반 기타 캐비닛에서 약해도 정상, 고역 부족 자동 판정 금지 |

HPF: 60~90(저음·다운튜닝 유지), 80~120(합주 출발). LPF: 하이게인 6~10 kHz, 클린 10~14 kHz 또는 bypass. LPF는 필요할 때만 사용하며 앰프/캐비닛의 자연 감쇠를 보상하려 하지 않는다. 팜뮤트의 순간 과다는 정적 EQ만으로 해결되지 않을 수 있다. 프리앰프 게인·연주 세기·채널 레벨도 비교한다.

### 4.4 베이스기타

선택: 4현 / 5현·저음 튜닝, 핑거 / 피크 / 슬랩, DI / 앰프 마이킹을 PA로 재생.

| 영역 | 청취 포인트 | 문제 후보·주의 |
|---|---|---|
| 30~60 | 최저음 기반 | 저 B 약 31 Hz, 저 E 약 41 Hz. 큰 부스트가 필요한 것은 아님 |
| 60~120 | 무게·펀치 | 붕붕거림·킥과 충돌 가능 |
| 120~250 | 바디·온기 | 과하면 뭉침 |
| 250~500 | 저중역 연결 | 먹먹함 후보, 과도한 컷은 작은 스피커에서 식별 저하 |
| 700~1.5 kHz | 음정 명료도·존재감 | 콧소리처럼 느껴질 수도 있음 |
| 2~5 kHz | 피크·슬랩 어택 | 프렛/현 잡음도 증가 |
| 5~8 kHz | 슬랩의 밝기·금속 질감 | 공기감은 선택 사항, 핑거 톤의 필수 목표 아님 |

HPF: 4현 25~35, 5현·저음 튜닝은 bypass 또는 20~30부터 청취. LPF: 핑거 톤 4~8 kHz, 피크/슬랩 8~12 kHz 또는 bypass. 저역이 적은 재생 장치에서 기음만 부스트하지 말고 배음·중역 식별을 듣는다. 킥과 “항상 특정 주파수를 나눠야 한다”는 규칙을 만들지 않는다. 연주 패턴과 서로의 중심 역할을 함께 조정한다.

### 4.5 전자드럼

선택: 전체 키트(모듈 출력), 킥, 스네어, 하이햇, 탐, 심벌. 모듈의 파트 solo 또는 분리 출력 없이 전체 키트를 측정하면 개별 파트 자동 원인 지목을 금지한다.

| 파트 | 주요 영역·성격 | 문제 후보 | HPF / LPF 출발점 |
|---|---|---|---|
| 전체 키트 | 30~16 kHz 이상까지 음색에 따라 분포. 50~120 무게, 150~300 바디, 2~5 kHz 어택, 8~14 kHz 공기감 | 200~500 뭉침, 3~8 kHz 자극 | HPF bypass 또는 20~30; LPF bypass. 파트 설정 먼저 확인 |
| 킥 | 35~90 기반/펀치, 90~180 바디, 2~5 kHz 비터/클릭 | 180~450 답답함, 지나친 클릭 | HPF 20~35(서브 포함 여부 확인); LPF 6~10 kHz 또는 bypass |
| 스네어 | 120~250 바디, 1~3 kHz 명료도, 2~5 kHz 어택, 6~12 kHz 스냅 | 300~800 상자 느낌·울림, 3~6 kHz 날카로움 | HPF 70~100; LPF 10~14 kHz 또는 bypass |
| 탐 | 50~200 음고/몸통, 2~5 kHz 어택 | 200~600 뭉침 | HPF 30~50(플로어), 40~70(랙); LPF 8~12 kHz 또는 bypass |
| 하이햇 | 3~8 kHz 리듬/어택, 8~14 kHz 밝기 | 3~7 kHz 거침 | HPF 150~300; LPF 12~16 kHz 또는 bypass |
| 심벌 | 300~1 kHz 금속 몸통, 3~8 kHz 어택, 8~16 kHz 공기감 | 3~7 kHz 자극, 긴 잔향 누적 | HPF 100~250; LPF 12~16 kHz 또는 bypass |

전자드럼은 이미 EQ·압축·리버브가 적용된 샘플일 수 있다. 샘플 선택, 튜닝, decay, velocity curve, 모듈 파트 볼륨을 먼저 확인한다. 전자패드의 생타격 소리는 모듈의 전자 음색이 아니다. 마이크로 패드를 직접 때리는 소리만 측정하면 이 가이드를 적용하지 않는다. 모듈에서 PA로 재생되는 소리를 측정한다고 명시한다. 전자드럼 USB-MIDI 연결을 USB 마이크 입력으로 취급하지 않는다.

### 4.6 리얼드럼(어쿠스틱 드럼)

선택: 전체 키트, 킥, 스네어, 하이햇, 랙탐, 플로어탐, 오버헤드/심벌, 룸. 소스 태그: 생음 / PA 증폭 / 생음+PA.

| 파트 | 주요 영역·성격 | 문제 후보 | HPF / LPF 출발점 |
|---|---|---|---|
| 전체 키트 | 킥 저역부터 심벌 고역까지. 파트별 역할로 설명 | 혼합 신호로 개별 드럼 원인 확정 불가 | 기본 bypass / bypass |
| 킥 | 45~100 무게/펀치, 100~200 바디, 2~5 kHz 어택 | 200~500 박스톤·먹먹함 | 25~40 / 8~12 kHz 또는 bypass |
| 스네어 | 120~250 바디, 1~3 kHz 명료도, 2~5 kHz 어택, 6~12 kHz 스네어 와이어 | 300~900 울림/박스톤, 3~6 kHz 자극 | 60~100 / 12~16 kHz 또는 bypass |
| 랙탐 | 80~180 몸통, 2~5 kHz 스틱 존재감 | 250~600 먹먹함, 긴 공진 | 40~60 / 8~12 kHz 또는 bypass |
| 플로어탐 | 50~120 몸통/펀치, 2~4 kHz 어택 | 150~400 붕붕거림 | 25~40 / 8~12 kHz 또는 bypass |
| 하이햇 | 3~8 kHz 리듬, 8~14 kHz 밝기 | 3~7 kHz 날카로움 | 150~300 / 12~16 kHz 또는 bypass |
| 오버헤드/심벌 | 200~800 키트 몸통, 3~8 kHz 스틱, 8~16 kHz 공기감 | 3~7 kHz 자극, 다른 파트 누음 | 60~100(키트 전체 역할), 150~250(심벌 중심 역할) / bypass |
| 룸 | 전대역 공간·지속음; 펀치는 직접음과의 관계 | 저중역 잔향·반사 누적 | 30~60 또는 bypass / bypass |

위 범위는 드럼 크기·튜닝·헤드·뮤트·마이크 위치에 따라 크게 바뀐다. 공진이 곧 결함은 아니다. 멀티 마이크 드럼의 필터 변경은 다른 마이크와의 합산에도 영향을 주므로 전체 키트를 들으며 확인한다. 객석 마이크 RTA로 각 채널 위상·극성을 확정하지 않는다. 튜닝·댐핑·마이크 위치를 먼저 점검한다.

## 5. 측정 절차

### 5.1 공통 절차

1. 악기·세부 음색·역할·측정 경로를 선택한다. 경로는 `PA 단독 소스`, `PA 전체 믹스`, `생음`, `생음+PA` 중 선택한다.
2. 입력 배지에서 실제 PHONE MIC/USB MIC, 보정 여부, AGC/NS 등 알려진 처리 상태를 확인한다. 처리 상태를 모르면 “알 수 없음”으로 표시한다.
3. 악기 채널·모듈 패치·앰프·게인·마이크 위치·스피커 방향을 기록한다. 자동 위치 검증을 가장하지 말고 사용자 체크와 메모로 남긴다.
4. 가능한 경우 연주를 멈추고 5초 배경 소음을 측정한다. 입력 또는 배치 변경 시 다시 받는다.
5. 단독 연주 또는 해당 채널만 PA에서 재생한다. 동일 리프·템포·음역·강도를 유지한다. 드럼은 같은 패턴을 10초 이상 반복하고 파트 검사에서는 해당 파트만 반복한다.
6. 10초를 기본값으로 Before를 저장한다. 5/10/20초 선택 가능. 원래 시간 길이와 유효 연주 시간은 별도 기록한다.
7. 사용자가 증상/목표를 선택하고 1개 영역을 듣는다. 믹서에서 작은 조정 후 동일 조건으로 After를 저장한다. 조정 내용을 메모한다.
8. 원본 레벨과 상대 음색 비교를 번갈아 확인한다. 최종적으로 전체 합주를 들으며 유지·되돌리기를 판단한다.

RTA 가이드에 분홍잡음으로 악기를 평가하는 절차를 넣지 않는다. 분홍잡음은 시스템 응답 조사에 쓰는 별도 절차다. 입력 마이크와 스피커 위치를 옮겨 얻은 큰 차이는 EQ 효과의 증거가 아니다.

### 5.2 상태와 중단

`BROWSE → READY → CAPTURING_BEFORE → BEFORE_SAVED → CAPTURING_AFTER → COMPARISON`.

- 권한 거부·입력 없음: BROWSE 유지, 정적 안내만 제공.
- 캡처 취소·화면 종료·권한 회수·입력 중단: 진행 중 스냅샷을 미완료로 처리하고 저장본과 분리.
- USB 전환·보정 변경: 진행 중 캡처 중단, 누적 상태 폐기, 새 조건에서 재시작. Before 보존 가능하나 호환성 재판정.
- Pause 구간을 유효 측정 길이에 포함하지 않는다. 임의로 이어 붙인 재개 자료는 같은 10초 측정으로 숨기지 않는다.
- 입력 재개 후 필요한 FFT/분석창이 채워지기 전 “측정 준비 중”. 이전 후보를 현재 결과처럼 유지하지 않는다.

## 6. UI/UX 명세

진입: 기존 RTA 화면의 `악기 EQ 가이드` 버튼 또는 분석 메뉴. 기존 SPL 화면의 가중치·모드 설정을 바꾸지 않는다.

```text
악기 EQ 가이드             PHONE MIC · 주파수 미보정
[어쿠스틱 기타 ▾] [스트로크 ▾] [PA 단독 소스 ▾]
목표  [바디] [명료도] [어택] [공기감]
증상  [먹먹함] [붕붕거림] [날카로움] [직접 선택]

RTA: Z/무가중 · 실제 입력의 밴드 레벨
┌ 주파수 로그축 · 선택한 참고 영역 음영 ┐
│  실측 막대 / Before 점선 / After 실선 │

150~350 Hz · 바디 / 먹먹함 확인 영역
두께가 충분한데 답답하게 들릴 때만 작은 컷을 비교하세요.
[Before 측정] [After 측정] [비교] [가이드 저장]
```

### 6.1 오버레이와 카드

- 주파수 영역의 가로 범위만 나타낸다. 정상 dB 높이·목표 곡선으로 보이는 띠를 그리지 않는다.
- 한 번에 활성 목표/증상 1개를 기본으로 하고 관련 영역 최대 3개 표시. 전체 카탈로그 보기에서 겹침을 설명한다.
- 참고 영역은 청록/보라와 텍스트, 문제 후보는 황색과 `확인 후보`, Before/After는 선 스타일과 라벨로 구분한다. 초록=좋은 음질, 빨강=나쁜 음질 판정 금지.
- 탭/키보드/접근성 선택으로 범위, 특성, 조사 조건, 변경의 부작용, 필터 출발점을 펼친다.
- 31밴드의 막대 중심값만 보고 정확한 EQ 중심주파수를 추천하지 않는다. 표기는 “약 250~500 Hz 확인”처럼 범위로 한다.
- 측정 불가능한 영역은 회색·`입력/분석 해상도 제한`으로 표시한다. 고역 끝과 저역의 신뢰도를 동일하게 가장하지 않는다.
- HPF/LPF 출발점은 보조 마커다. 활성 필터·실제 적용 EQ 곡선이라고 표시하지 않는다.

### 6.2 후보 카드 예시

> 250~500 Hz를 들어보세요. 반복 측정에서 이 영역이 주변보다 두드러졌습니다. 먹먹하게 들리는 경우 믹서의 작은 컷을 비교할 수 있습니다. 악기의 원래 음색이나 공간 영향일 수도 있습니다.

함께 표시: 유효 분석 시간, 기준(주변 대비/사용자 Before 대비), 상대 차이, 입력 처리·보정 제한, `청취 확인 전`. 확률형 “문제일 확률 92%” 금지. 증상을 확인하면 `사용자 확인` 배지를 붙이며 알고리즘이 확진한 것으로 변경하지 않는다.

### 6.3 비정상 상태 문구

- 전체 합주: “여러 소리가 섞여 있습니다. 선택 악기만의 문제로 판단할 수 없습니다.” 자동 악기 후보 탐지는 비활성, 수동 오버레이는 유지.
- 배경 대비 약함: “연주 소리가 충분히 분리되지 않아 자동 분석을 보류합니다.”
- 클리핑/드롭: “입력 왜곡 또는 누락이 있어 다시 측정해 주세요.”
- 입력 변경: “마이크가 바뀌었습니다. 같은 입력으로 Before를 다시 측정해 주세요.”
- 비교 조건 불일치: “조건이 달라 참고용으로만 나란히 표시합니다.”
- 데이터 없음: 0 dB 막대나 이전 그래프 대신 빈 상태. 오래된 스냅샷은 저장 시각과 `저장된 측정` 표기.

## 7. 분석 데이터와 수학 정의

### 7.1 공통 입력 계약

가이드 분석은 기존 RTA의 **무가중/Z 주파수 파워**를 사용한다. A/C 가중된 스펙트럼이나 Peak Hold를 사용하지 않는다. 기존 화면의 A/C SPL 선택과 독립적이다. 같은 캡처 스트림과 기존 FFT/밴드 집계를 재사용한다.

프레임 계약: 각 밴드의 선형 평균제곱 `P_b`, 분석 프레임의 고유 hop 시간 `dt`, 단조 시각, generation, FFT/밴드 정의 버전, clipping/drop/valid mask, 보정 메타데이터. 겹치는 FFT의 창 길이를 매번 dt로 누적해 실제 시간보다 길어지지 않게 한다. 화면 갱신용으로 생략된 프레임만 받아 정확한 시간평균이라 주장하지 않는다. 필요하면 UI throttle 전 집계 지점을 추가한다.

주파수 보정이 dB로 `C_b`인 경우:

```text
P_corrected,b = P_raw,b × 10^(C_b / 10)
P_mean,b = Σ(P_corrected,b,t × dt_t) / Σ(dt_t)
L_b = 10 log10(P_mean,b / P_ref)
```

`P_ref`는 dBFS/정규화 파워 계약에 맞게 정의한다. SPL로 변환하려면 별도 유효 global calibration이 필요하다. 미보정 자료는 `밴드 dBFS` 또는 `상대 dB`로 표기하고 절대 SPL로 오인시키지 않는다. 주파수 보정의 적용 부호·주파수 보간·기기 키는 기존 검증된 구현을 따른다. UI에서 다시 보정하지 않는다. 보정된 RTA 합을 기존 LAeq/LCeq 값으로 대체하지 않는다.

SPL 보정과 주파수 보정은 별도 상태다. 주파수 보정만 있어도 절대 SPL 보정 완료가 아니다. 주파수 보정 파일의 범위 밖은 표시 가능하더라도 탐지에 쓸 수 있는 유효 범위를 별도로 표시한다. 미보정 내장 마이크도 기능을 열되 고유 응답과 AGC 가능성에 대한 제한을 알린다.

### 7.2 영역과 31밴드 매핑

UI 좌표:

```text
x(f) = width × ln(f / f_min) / ln(f_max / f_min)
```

0 이하·NaN 주파수는 거부하고 화면 범위에 clip한다. 밴드 경계는 기존 `ThirdOctave`의 실제 경계를 사용한다. 명목 중심 숫자에 임의 공식으로 새 경계를 만들어 기존 집계와 다르게 하지 않는다.

영역과 밴드가 겹치면 해당 영역을 음영으로 표시한다. 수치 후보 계산은 MVP에서 중심이 영역 안에 있는 완전 유효 밴드만 사용한다. 부분 겹침 면적을 정밀 파워로 해석하지 않는다. 포함 밴드가 2개 미만이면 자동 후보를 만들지 않고 수동 가이드만 표시한다.

FFT 4096/48 kHz의 bin 간격은 약 11.72 Hz이므로 최저 1/3옥타브 밴드는 충분히 분해되지 않을 수 있다. 자동 분석용 밴드는 `밴드 폭 >= 3 × Fs/N` 및 상·하 경계가 유효 분석 범위 안이라는 보수적 초기 조건을 적용한다. 이는 분해능 보증이 아닌 제품의 제한 정책이다. 고역은 나이퀴스트를 걸치는 부분 밴드를 제외한다. 낮은 신스 베이스를 정적 카드로 안내할 수 있지만 해당 저역을 정밀 판정했다고 표시하지 않는다. 해상도 개선 FFT는 별도 DSP 변경/검증으로 다룬다.

### 7.3 탐지 가능성과 금지된 추론

자동 기능은 좁거나 중간 폭의 **지속적 상대 돌출 후보**만 제시한다. 넓은 음색 선호, 공기감 부족, 펀치 부족, 마스킹, 악기 고장은 MVP 자동 판단 대상이 아니다. 카탈로그의 문제 영역을 탐지 threshold와 혼동하지 않는다. 신호가 없거나 고역이 약하다는 이유로 부스트를 제안하지 않는다.

입력 하나에서 어떤 악기가 문제를 만들었는지 분리할 수 없다. 단독 소스 선택은 사용자의 선언이며 보증이 아니다. 앱은 이를 메타데이터로 저장한다.

### 7.4 후보 탐지 v1: 명시적 실험 알고리즘

아래 임계값은 규격이 아닌 개발 초기값이다. 버전 관리하고 12장의 데이터로 튜닝한다.

1. 연주 전 5초의 밴드별 배경 파워 `N_b`와 전체 유효 대역 합을 수집한다. 없으면 자동 후보를 보류하고 수동 카드만 제공한다. 배경 파워를 빼서 새로운 음압을 계산하지 않는다.
2. 0.5초 비중첩 시간 블록을 만든다. 기존 FFT 프레임을 hop 시간 기준 에너지 평균한다. 시작 시 불완전 블록은 제외한다.
3. 동일 generation/config/profile, clipping 없음, 샘플 누락 없음인 블록만 사용한다. 전체 유효 대역 파워가 배경보다 10 dB 이상인 블록을 연주 활성으로 본다. 이 조건은 진정한 SNR 측정값이라고 부르지 않는다.
4. 후보 대상 밴드 각각이 배경보다 10 dB 이상이며 해상도·보정 범위 조건을 만족해야 한다. 둘 중 하나라도 미달하면 해당 영역 분석을 보류한다.
5. 선택된 문제 영역의 포함 밴드 집합을 T라고 한다. T 바로 아래/위의 유효 밴드를 각각 2개씩 모아 비교 집합 R을 만든다. 양쪽 2개가 확보되지 않으면 보류한다. R도 배경 조건을 통과해야 한다.
6. 각 블록에서 `q_b = 10 log10(P_b / bandwidth_b)`로 파워 밀도에 대응하는 dB 값을 구한다. 이는 UI 밴드 레벨과 별개 분석량이다. 불균등 밴드 폭을 무시하고 원래 밴드 파워끼리 비교하지 않는다.
7. R에 대해 `x = log2(centerHz)`와 q의 최소제곱 직선을 적합한다. T에서 실제 q와 직선 추정값의 차를 구하고 중앙값을 prominence로 사용한다. 넓은 기울기만 있는 신호의 오탐을 줄이는 장치이지, 음악적 정상 모델은 아니다.
8. 최근 10초 안에 유효 활성 블록이 10개(5초) 이상이고 이들의 70% 이상에서 prominence >= 6 dB이면 후보를 노출한다. 밴드가 많은 영역도 1개 피크로 후보화하지 않는다. 최소 표본이 모일 때까지 “분석 중”.
9. 후보가 나온 뒤 유효 블록 기준 prominence < 3 dB 상태가 3초 연속이면 해제한다. 무음/invalid가 2초 지속되면 현재 후보를 숨기고 누적 상태를 초기화한다. 입력·패치·보정 변경은 즉시 초기화한다.
10. 동시에 최대 3개, 겹치는 영역은 하나로 합쳐 원래 rule ID를 유지한다. 순위는 prominence와 지속 시간으로만 정하고 “심각도”나 음질 점수로 이름 붙이지 않는다.

단일 음·오르간 sustain·드럼 고유 공진도 조건을 통과할 수 있다. 그래서 **이 값만으로 컷을 권장하지 않는다.** 카드에서 “해당 증상이 들리는지” 사용자가 확인한 후에만 작은 조정 실험을 안내한다. 지속 신스 음색에서 오탐이 높으면 해당 subtype의 자동 규칙을 꺼도 정적 가이드는 유지한다.

드럼은 무음 때문에 활성 블록이 부족할 수 있다. 시간이 모자라면 반복 연주를 요청하며 threshold를 자동으로 낮추지 않는다. 미래 onset 기반 분석은 별도 버전으로 한다. 기존 FeedbackDetector의 좁은 톤 경고와 합치지 않는다. 동일 구간에 두 카드가 있더라도 의미가 다름을 표시한다.

## 8. Before/After 비교

### 8.1 저장값과 표시

스냅샷에는 주파수 보정 전·후의 밴드 에너지 평균, 유효 시간, 전체 경과시간, noise/quality mask, 모든 비교 조건을 저장한다. 표시 smoothing과 Peak Hold는 계산에 들어가지 않는다.

비교 화면은 다음을 제공한다.

- 원본 레벨: `Δ_b = L_after,b − L_before,b`. 동일 입력에서 실제 레벨 변화 포함.
- 상대 음색: 두 스냅샷에서 공통 유효 밴드 집합 V를 고정하고 각 시료의 `T = 10 log10(Σ P_b)`를 계산한다. `S_b = L_b − T`, `Δshape_b = S_after,b − S_before,b`.
- 정규화는 표시용이며 원본/음압/녹음을 변경하지 않는다. EQ가 넓은 대역 에너지를 바꾸면 다른 밴드의 상대값도 달라질 수 있다. 실제 청감 loudness matching과 같지 않다.
- V는 두 시료 모두 배경 대비 조건과 해상도 조건을 통과한 밴드의 교집합이다. 6밴드 미만이면 상대 비교를 보류한다. 사용된 주파수 범위와 밴드 수를 표시한다.
- 차트와 함께 선택 영역별 변화 표, 연주 시간, 원본 전체 레벨 차, 사용자 메모·주관적 선호를 표시한다. “개선 +20점”은 만들지 않는다.

예: 같은 파워 스펙트럼 전체가 +6 dB이면 원본 변화는 모든 밴드 +6 dB, 상대 음색 차는 0 dB여야 한다. dB 산술평균으로 파워 평균을 대신하지 않는다.

### 8.2 호환성 판정

| 조건 | 처리 |
|---|---|
| 실제 입력 기기/경로, rate, channel, encoding, 입력 처리 설정 불일치 | 정량 Δ·정규화 비교 차단, 참고용 나란히 보기만 |
| calibration ID/version/hash/적용 범위 또는 global offset 불일치 | 정량 비교 차단. 원본으로 동일 설정 재분석이 가능한 별도 기능이 있을 때만 새 비교 생성 |
| DSP/밴드 정의/분석 알고리즘 버전 불일치 | 기본 차단, 호환성 명시된 migration만 예외 |
| 악기/subtype/패치/측정 경로 불일치 | 정량 비교 차단 |
| generation만 다르고 나머지 입력 fingerprint 동일 | 새 시작 사실을 표시, 배치·게인 유지 사용자 확인 후 비교 |
| 마이크 위치/방향·재생 레벨·연주 패턴 변경 또는 확인 안 됨 | 참고용 나란히 보기. 정량 변화의 EQ 해석 보류 |
| 클리핑/샘플 손실 있는 캡처 | 품질 불합격, 정상 Before/After로 사용 불가 |
| 캡처 길이가 다르지만 각각 유효 활성 5초 이상 | 평균 비교 허용, 길이 차이 표시 |

입력 fingerprint의 자동 검증 항목과 사용자 확인 항목을 구분한다. USB device ID가 재연결 때 달라질 수 있으므로 현재 프로젝트의 물리 장치/경로 키를 사용하고, 동일 장치임을 확인할 수 없으면 같다고 추정하지 않는다.

### 8.3 들어보기

녹음이 없으면 그래프 비교만 제공한다. `듣기` 버튼으로 마이크 캡처를 실시간 스피커에 되돌리는 기능은 만들지 않는다. 기존 REC를 사용자가 켰고 각 스냅샷과 연결된 RecordingAsset 구간이 있을 때만 그 실제 구간을 재생한다. 재생 시 자동 후보 분석과 신규 A/B 캡처를 정지하여 재생 소리를 다시 분석하지 않게 한다. seek와 시간축은 기존 monotonic timeline 계약을 따른다. 서로 다른 연주 녹음을 동일 연주에 EQ만 적용한 비교처럼 표현하지 않는다.

## 9. 사용자 프리셋

UI 이름은 `가이드 프리셋`. 저장 내용은 악기·subtype·연주 역할·목표/증상·선택 영역·필터 출발점 메모·사용자 EQ 메모·장소 메모·카탈로그 버전이다. 프리셋 적용은 안내 화면만 바꾼다.

- 만들기, 이름 변경, 복제, 수정, 삭제, 즐겨찾기, 마지막 선택 복원.
- 기본 카탈로그는 읽기 전용. 수정 시 사용자 복사본 생성.
- “주일 2부 어쿠스틱 스트로크” 같은 이름 허용. 이름 최대 80자, 메모 2,000자, 악기별 최대 100개를 초기 저장 정책으로 둔다.
- 악기 EQ 메모는 `filterType, frequencyHz, gainDb?, q?, slopeDbOct?, bypass` 형태로 선택 저장. 자동 계산된 처방과 구분하여 `사용자가 기록한 믹서 설정` 표시.
- 마이크 보정값·절대 정상 레벨·다른 장치의 검증 결과를 프리셋으로 자동 적용하지 않는다.
- snapshot 연결은 별도 선택. 스냅샷 삭제 시 프리셋의 텍스트 정보는 유지하고 연결 없음으로 처리.
- 저장 실패 시 성공 알림 금지, 기존 프리셋 원자적 보존. DB migration 및 앱 재시작 시험 필수.
- 파일 import/export는 후속 선택 기능. 추가한다면 SAF로 JSON을 다루고 schema/크기/배열 개수/유한 숫자/외부 URI를 검증한다. 기본 프리셋에 클라우드 계정이나 녹음 업로드를 요구하지 않는다.

## 11. 아키텍처와 동시성

```text
기존 AudioSource → 단일 PCM → 기존 DSP/RTA
                                 ├─ 기존 SPL/RTA/Feedback UI
                                 ├─ 기존 녹음·기록 경로(있을 때)
                                 └─ GuideFrame Adapter
                                      → GuideAccumulator
                                      → CandidateAnalyzer / SnapshotComparator
                                      → GuideRepository
                                      → InstrumentGuideViewModel → Compose
CatalogRepository ────────────────────────────────────────┘
PresetRepository / SnapshotRepository ────────────────────┘
```

권장 배치:

- `dsp`: 파워 집계·상대 차 계산처럼 Android 비의존 순수 수학만. 악기 한국어 설명을 넣지 않는다.
- `domain/instrument`: 가이드 모델, 후보 규칙, 비교 가능성, use case.
- `data/instrument`: 내장 JSON 카탈로그, 프리셋/스냅샷 저장, migration.
- `ui/instrument`: 화면, overlay, card, ViewModel.
- 실제 `CaptureViewModel`, `RtaEngine`, `RtaView` 연결은 착수 시 전체 구현을 확인해 최소 adapter로 한다. 거대한 기존 ViewModel에 카탈로그와 탐지 상태를 모두 추가하지 않는다.

캡처를 새로 열지 않는다. 기존 capture owner가 lifecycle을 소유하고 화면은 구독/해제한다. 분석 worker는 bounded queue를 사용하고 오디오 스레드에서 DB·파일 I/O를 하지 않는다. queue overflow는 조용히 버리지 말고 gap/invalid를 기록한다. UI는 최신 상태로 합쳐도 되지만 측정 집계는 그 이전에 수행한다. 가이드 OFF 시 분석 worker를 중단하고 불필요한 계산을 없앤다.

`generation + input fingerprint + calibration version`을 원자적 컨텍스트로 전달한다. 장치 전환 후 늦게 도착한 이전 프레임은 폐기한다. 취소된 job이 새 상태를 덮어쓰지 못하게 토큰을 확인한다. 초기화, 저장, 목록 수정은 단일 소유자/직렬 상태 갱신으로 race를 방지한다. 화면 회전은 캡처 중복 시작을 일으키지 않는다. 오래된 버퍼 참조를 DB coroutine에 넘기지 않는다.

10초 후보창은 0.5초 요약 20개 등 고정 크기로 유지한다. 전체 세션의 프레임을 메모리에 누적하지 않는다. UI 목표 갱신은 기존 10~20 FPS 안에서, 후보 갱신은 2 Hz면 충분하다. 표준 입력에서 가이드 분석의 0.5초 블록 처리 p95 < 10 ms를 초기 목표로 측정하되 기기·build 조건을 보고한다. 가이드 때문에 생긴 capture drop은 허용하지 않는다.

## 12. 테스트 및 검증 기준

### 12.1 수학·데이터 단위 시험

| ID | 입력/조건 | 기대 결과 |
|---|---|---|
| T01 | 1 kHz 알려진 sine 및 기존 FFT 기준 fixture | 기존 DSP값 재사용, guide ON/OFF 원본 값 동일 |
| T02 | 파워 1과 0.01을 동일 시간 평균 | 10log10(0.505) ≈ -2.9671 dB. -10 dB 산술평균이면 실패 |
| T03 | 동일 파워에 frequency correction +6 dB | ×10^0.6 파워, dB +6. 중복 +12 발생 금지 |
| T04 | 전체 레벨 +6 dB인 After | 원본 Δ +6, shape Δ 0; 계산층 오차 <= 0.01 dB |
| T05 | 일부 영역만 +3 dB | 원본 변화 정확, shape 변화는 정규화 수식과 일치; 무변경 밴드 shape=0을 강제하지 않음 |
| T06 | dt가 다른 2프레임, FFT overlap | 독립 계산 시간가중 평균과 일치, 실제 hop 시간만 누적 |
| T07 | 0/음수/NaN/Inf/누락/길이 오류 | crash/가짜 정상값 없음, invalid 상태 유지 |
| T08 | 경계 걸침·범위 외·Nyquist 부분 밴드 | UI clip 정확, 탐지 유효 mask 조건 일치 |
| T09 | 같은 파워밀도의 서로 다른 밴드 폭 | 밀도 비교 prominence 0에 근접, 폭 때문에 돌출하지 않음 |
| T10 | fingerprint·보정 hash 하나씩 변경 | 정해진 비교 차단 이유, 자동 재보정 없음 |
| T11 | 6 악기와 모든 subtype 데이터 | 범위 low<high, 유한수, 태그·출처·주의사항·필터 조건 유효 |
| T12 | 후보 진입/해제 경계 6/3 dB, 70%, 5초 | 정확한 경계·히스테리시스, 무음 2초 reset |

계산층의 폐쇄형 기대값은 구현 함수를 다시 호출해 만들지 않는다. PCM→FFT 수준은 창/주파수 정렬/신호 길이에 따른 별도 허용 오차를 문서화한다. 0.01 dB를 실제 마이크 음향 측정 정확도 목표로 해석하지 않는다.

### 12.2 후보 탐지 시험

- seeded white/pink noise와 매끈한 기울기: 광대역 기울기를 지속 돌출로 오인하는지 확인.
- 대역 제한 잡음에 bell형 상승을 주입: ±0/3/6/9 dB 조건, 영역 중심 및 경계, 배경 레벨 변화. 주입 EQ gain과 분석 prominence는 같다고 가정하지 않는다.
- 무음·낮은 입력·ADC clipping·샘플 누락: 후보 없음, 보류 사유 정확.
- sine, 화음, 장음 오르간/신스 베이스, 필터 스윕, 디스토션 기타: 자연 배음/의도적 피크가 컷 지시나 하울링 확정으로 바뀌지 않음.
- 드럼 정상 반복·다이내믹한 필인·잔향: 연주/무음 구분과 후보 지속 시간 확인.
- 동일 파일의 전체 gain만 변경: 배경 조건을 모두 통과한 경우 prominence/shape의 gain 불변성 확인.
- `FULL_MIX`/전체 키트에서 파트 분리 미확인: 특정 악기/파트 자동 원인 지목 없음.

실험적 탐지 공개 전 평가 세트: 악기별 최소 10개 클립(총 60개), 서로 다른 음역·강도·음색 포함. 정상 의도 음색과 인위적 변화 자료를 구분하며 원본 클립 단위로 튜닝/검증 세트를 분리한다. 같은 원본의 EQ 변형이 양쪽에 섞이지 않게 한다. 권리 확보된 자료를 사용하고 전체 믹스 보류 사례도 추가한다.

음향 담당자 2인이 “청취 확인 후보로 유용한지” 평가한다. 의견 불일치는 별도 표기하며 정답으로 강제하지 않는다. 공개 초기 게이트: 합의된 비문제 검증 클립에서 후보가 한 번 이상 뜬 비율 <= 10%; 충분한 SNR·해상도를 가진 주입 사례에서 실제 분석 prominence >= 9 dB가 10초 지속되면 탐지율 >= 90%. 보류율과 악기별 표본 수를 함께 보고하여 모두 보류하는 방식으로 게이트를 통과하지 못하게 한다. 유효 조건이 충족된 주입 사례의 보류율 목표 <= 10%. 이는 제품 출시 기준 제안이며 검증 완료 성능이 아니다. 미달 subtype은 자동 탐지를 보류하고 수동 가이드를 유지한다.

### 12.3 Android·저장·UI 시험

- 내장/USB 각각 동일 기능 흐름, 권한 최초/거부/회수, USB attach/detach, fallback 정책, 실제 routed device 확인.
- 캡처 중 악기·패치·보정 변경, 빠른 페이지 왕복, 연속 Start/Cancel, 회전, background/foreground.
- 이전 generation 프레임을 전환 후 인위적으로 전달: 새 후보·새 스냅샷에 섞이지 않아야 함.
- 재사용 배열을 생산자에서 수정: 이미 저장한 스냅샷 값이 변하지 않아야 함.
- 저장 중 앱 종료/디스크 오류/DB migration: 기존 자료 보존, 부분 저장 성공 표시 금지.
- 마이크 없이 가이드 열람, 모든 6종 선택, 큰 글씨 200%, 좁은 화면, 색각 대체 라벨, TalkBack.
- 색상뿐 아니라 영역명·Hz·선 스타일로 A/B 식별. 범위 끝 라벨·한글 줄바꿈 잘림 검사.
- 가이드 ON/OFF 및 기존 녹음 ON과 결합하여 60분 시험. crash/ANR/새 drop 없음, worker·AudioRecord 수 누수 없음, warm-up 뒤 지속 메모리 증가 없음. heap 추세·스레드 수·온도·배터리 결과를 기록.
- 최소 내장 마이크 실제 Android 1대와 실제 USB 측정 마이크 1종. 기기가 없으면 해당 시험을 “미실행”으로 명시하고 USB 검증 완료라고 보고하지 않는다.

### 12.4 현장 검증

같은 장소·마이크 배치에서 각 악기 Before/After를 3회 반복한다. 변화 없는 A/A를 먼저 얻어 연주·공간에 의한 차이를 확인한다. 앱이 믹서의 +3 dB와 객석 +3 dB가 항상 같다고 주장하지 않는지 본다. 내장/USB 결과가 다르면 각 입력 응답·처리 제한을 기록하고 어느 한쪽을 자동 정답으로 지정하지 않는다. 객석 합주 결과로 개별 채널 문제를 확정하지 않는 UI를 검증한다.

## 13. Claude Code 구현 단계

기존 마스터 Phase 번호에 덮어쓰지 않고 `EQ-A`부터 별도 workstream으로 관리한다. 각 단계는 build → 관련 test → 가능한 실기기 확인 → 결과 보고 순서다.

| 단계 | 작업 | 종료 조건 |
|---|---|---|
| EQ-A | 현재 repo/명세/ADR/테스트 분석, 연결 구조·입력 계약·비교 정책 확정 | 실제 HEAD·baseline·최소 변경 계획·ADR |
| EQ-B | 6종 카탈로그·모델·정적 선택 화면·주의 카드 | 마이크 없이 사용 가능, 데이터 검증 통과 |
| EQ-C | 기존 RTA 연결·오버레이·입력/보정/해상도 상태 | 별도 AudioRecord 없음, UI·generation 시험 통과 |
| EQ-D | 스냅샷 캡처·호환성·원본/shape 비교 | 수학 fixtures·불일치 차단·내장 실기기 통과 |
| EQ-E | 버전형 후보 알고리즘, 증상 확인, 실험실 설정 | 합성/음성 사례·abstain·오탐 평가 보고 |
| EQ-F | 프리셋·영속화·기존 녹음 연결(있을 때) | 재시작/migration·저장 실패·재생 오염 방지 |
| EQ-G | 실제 USB·60분·접근성·6악기 현장 확인 | 한계 포함 증거, 독립 검증 요청서 |
| EQ-H | Codex 리뷰 반영·재검증·문서/릴리스 | 미해결 Critical/High 없음, 기능별 게이트 기록 |

18장의 게이트·컴프레서 가이드는 EQ-B에서 악기별 추천 설정표와 설명 카드로 구현한다. 별도 DSP, PCM 통계, 측정·A/B, 다이내믹스 프리셋 확장은 구현하지 않는다. EQ-G/H에서는 DYN-01~02와 18.7의 정적 안내 검증만 추가한다.

각 단계 보고: 구현 항목, 변경 파일, 설계 결정, 실행한 명령·시험 수·실패, 실기기/미실행 항목, 알려진 제한, 다음 단계. 기본 DSP 문제가 발견되면 재현을 먼저 분리하고 기능 추가 명목으로 광범위하게 고치지 않는다. 실제 source 구조가 제안과 다르면 adapter 설계 이유를 ADR에 남긴다.

## 14. Codex 독립 검증 기준

Claude Code가 `docs/review/YYYY-MM-DD-instrument-eq-review-request.md`에 실제 base/head SHA, `git diff --stat`, 변경 요약, 시험 결과, 미실행 항목, 자신 없는 다섯 곳을 기록한다. Codex는 그 다섯 곳 밖의 결함도 확인한다.

필수 검토:

1. 무가중 파워 사용, 에너지 평균, 보정 1회, dBFS/SPL 구분, FFT hop과 경과시간의 일치.
2. 내장/USB feature parity, 실제 route 키, generation·profile mismatch, cancellation·buffer ownership.
3. 정상 음색과 후보 탐지의 구분, 무음/노이즈/장음/드럼 오탐, full mix에서 분석 보류.
4. Before/After normalization 공식, 공통 mask, 조건 불일치 차단, 재측정의 불확실성.
5. UI 오버레이가 정상 곡선·실제 EQ로 보이지 않는지, 프리셋이 믹서 변경으로 오인되지 않는지.
6. Room/저장 migration·원자성·지속 메모리·녹음 privacy와 재생 분석 혼입.
7. 테스트의 독립 기대값, 편향된 검증 세트, 실패 사례 누락, 실제 USB 검증 여부.

문제별 보고 형식:

```text
ID / Severity: Critical | High | Medium | Low
제목:
파일·검증한 커밋·위치:
위반 요구사항 ID:
재현 절차 또는 수학/논리적 근거:
예상 결과 / 실제 결과:
사용자 영향:
권장 최소 수정:
필요한 회귀 테스트:
검증 상태: 재현됨 / 정적 근거 / 실기기 미확인
```

Critical: 중대한 데이터/프라이버시 침해 등. High: 장치·보정 혼입, 잘못된 Δ, 반복 crash, 자동 처방으로 오인시키는 핵심 오류. Medium: 일부 조건 오탐·품질/UX 오류. Low: 경미한 문구·표시 결함. severity는 구체적 영향과 발생 조건으로 정하고 취향 차이로 높이지 않는다.

Codex는 리뷰 단계에서 production 코드를 직접 광범위 수정하지 않는다. 최소 재현 시험과 발견사항을 우선 제시하고 Claude Code가 수정한 커밋을 재검증한다. Critical/High가 없으면 “검토 범위에서 발견하지 못함”과 남은 실기기·음향 위험을 함께 보고한다.

## 15. 최종 수용 체크리스트

- [ ] 6종 악기 및 명시된 subtype/드럼 파트를 선택할 수 있다.
- [ ] 모든 카드에 조건·부작용·필터 bypass 선택이 있다.
- [ ] 내장 마이크만으로 전체 흐름이 동작한다.
- [ ] USB 실제 연결·해제·fallback과 보정 격리를 검증했다.
- [ ] 권한 없이 정적 가이드만 정상 동작한다.
- [ ] RTA는 관측값, 음영은 청취 참고 범위로 분명히 구분된다.
- [ ] 보정·가중치·smoothing·Peak Hold가 비교 수학을 왜곡하지 않는다.
- [ ] 후보 탐지의 조건 미달·전체 믹스·범위 제한에서 적절히 보류한다.
- [ ] Before/After 조건 불일치 차단과 원본/상대 차이가 검증되었다.
- [ ] 프리셋은 안내만 복원하며 녹음·보정·외부 EQ를 자동 변경하지 않는다.
- [ ] 기존 SPL/Feedback/선택적 녹음의 회귀·성능 시험을 통과했다.
- [ ] 탐지 평가 결과와 미검증 subtype이 공개 문서에 있다.
- [ ] Codex 독립 검증에서 미해결 Critical/High가 없다.
- [ ] 게이트·컴프레서 안내가 6종 악기 및 필요한 드럼 파트를 포함한다.
- [ ] 마이크 dBFS를 믹서 Threshold로 복사하거나 실제 GR로 표시하지 않는다.
- [ ] 게이트·컴프레서는 추천값·설명만 제공하고 RTA 분석·시간 분석·전후 비교 기능을 추가하지 않는다.

## 18. 게이트·컴프레서 가이드 확장 — 필수 포함

### 18.1 목적과 기능 범위

EQ는 주파수별 크기를, 게이트/익스팬더는 작은 소리의 감쇠를, 컴프레서는 주로 큰 소리의 레벨 변동을 다룬다. 악기 소리가 답답하거나 튀는 원인이 항상 EQ는 아니므로 사용자가 세 도구의 역할을 구분하게 한다.

**평균 RTA로 attack, release, threshold, 실제 gain reduction(GR)을 결정할 수 없다.** 객석 마이크 하나는 외부 컴프레서의 처리 전후 신호를 동시에 갖고 있지 않다. 이 앱은 믹서의 GR 미터나 게이트 개폐 상태를 읽는 장치가 아니다. 아래 설정은 외부 믹서에서 청취하며 시험할 참고값이며 자동 적용·자동 역추정하지 않는다.

게이트·컴프레서는 추천 설정값과 조정 시 주의사항만 안내한다. RTA를 통한 설정 효과 판단, 별도 시간 분석, 측정, Before/After 비교를 제공하지 않는다. 마이크 연결·권한·보정 없이도 동일하게 열람할 수 있다. 이 문서의 RTA·탐지·측정·비교 요구사항은 EQ 기능에만 적용한다.

### 18.2 기본 파라미터 설명

| 도구/파라미터 | 의미 | 조정할 때 들을 것 |
|---|---|---|
| Gate Threshold | 소리가 통과하도록 여는 기준 | 약한 연주까지 잘 열리는지, 무음 잡음으로 열리지 않는지 |
| Gate Attack | 열리는 속도 | 너무 느리면 첫 피킹·스틱이 잘림 |
| Gate Hold | 닫힘 조건 뒤 열린 상태를 유지하는 시간 | 타격 직후 떨림·급한 개폐 방지 |
| Gate Release/Decay | 닫히며 감쇠되는 속도 | 너무 짧으면 꼬리 잘림·클릭, 너무 길면 누음 지속 |
| Gate Range/Depth | 닫혔을 때 최대 감쇠량 | 완전 mute보다 부분 감쇠가 자연스러울 수 있음 |
| Gate Hysteresis | 열림과 닫힘 Threshold 차이 | 경계에서 chatter를 줄임. 닫힘 기준은 열림보다 낮게 |
| Downward Expander | 작은 소리를 비례적으로 더 줄임 | hard gate보다 연주 끝을 자연스럽게 남길 수 있음 |
| Compressor Threshold | 압축이 시작되는 기준 | 큰 음에서 원하는 정도로만 GR이 생기는지 |
| Ratio | 기준 위 입력 증가량과 출력 증가량의 비율 | 높은 값은 더 강하게 레벨 차를 줄임 |
| Attack | 압축 반응 속도 | 빠르면 어택 억제, 느리면 타격 보존 가능 |
| Release | 압축이 풀리는 속도 | 너무 빠르면 펌핑·왜곡, 너무 느리면 다음 음까지 눌림 |
| Knee | 압축 시작의 점진성 | soft knee는 경계를 부드럽게 만들 수 있음 |
| Makeup/Output Gain | 처리 뒤 출력 보정 | 더 커졌다는 이유로 더 좋다고 판단하지 않기 |
| Sidechain filter | detector가 주로 반응할 주파수 조절 | 메인 오디오 EQ와 다른 경로임을 이해 |

기기마다 attack/release 측정 정의, RMS/peak detector, soft knee, hold 기능이 다르므로 동일 ms·ratio라도 같은 소리가 아니다. attack 시간은 단순히 그 시간 동안 아무 동작도 하지 않는 지연이 아니다. gate range는 이 앱에서 양수 `감쇠량 dB`로 저장하고 믹서의 음수 표기와 혼동하지 않는다. 익스팬더 ratio의 제조사 표기 방향 차이도 설명한다.

### 18.3 게이트·익스팬더 악기별 출발점

기본은 **bypass**. 잡음·누음이 실제 문제일 때만 시도한다. Threshold 고정값은 제공하지 않는다. 다음 수치는 가이드 편집용 초기 범위이며 제조사 표준이 아니다. Attack/Hold/Release 단위는 ms, Range는 닫혔을 때의 감쇠량이다.

| 악기/파트 | 우선 판단 | Attack / Hold / Release | Range 출발점 및 주의 |
|---|---|---|---|
| 신디 피아노/EP | 보통 bypass, 출력 잡음이 있을 때만 약한 expander | 1~5 / 80~150 / 200~500 | 6~12 dB. 페달·약한 건반·잔향 손실 확인 |
| 신디 패드/스트링 | 원칙적으로 bypass | 숫자 프리셋 비활성 | 느린 fade-in과 긴 release를 gate가 잘라버릴 수 있음 |
| 신디 리드/베이스 | 의도한 sustain·필터 꼬리 먼저 확인 | 필요 시 1~5 / 50~100 / 150~300 | 6~12 dB. 부드러운 시작과 낮은 음의 끝 보존 |
| 어쿠스틱 기타 | gate보다 bypass 또는 약한 expander 우선 | 1~5 / 80~150 / 200~400 | 6~12 dB. 핑거스타일·현 울림·룸톤이 잘릴 수 있음 |
| 일렉기타 클린 | bypass/약한 expander | 1~3 / 50~100 / 150~300 | 6~12 dB. sustain 손상 확인 |
| 일렉기타 하이게인 | 쉼표의 hiss가 문제일 때 | 0.5~2 / 30~80 / 80~180 | 12~24 dB. 롱톤은 release를 늘리거나 bypass; riff용 값을 모든 곡에 고정하지 않음 |
| 베이스기타 | 대개 bypass | 필요 시 1~5 / 80~150 / 150~350 | 6~12 dB. 약한 음·긴 저음 sustain을 잘라먹지 않음 |
| 전자드럼 전체 키트 | 모듈은 이미 편집된 음색일 수 있어 bypass | 숫자 프리셋 비활성 | 전체 출력 gate가 심벌 꼬리·고스트노트를 함께 자름 |
| 전자드럼 개별 킥/스네어/탐 | 필요하면 먼저 모듈 decay/noise 설정 | 리얼드럼 해당 파트를 참고하되 자동 복사하지 않음 | 6~12 dB부터, 파트 solo 확인 |
| 리얼드럼 킥 | 누음/긴 꼬리가 문제일 때 | 0.5~2 / 40~80 / 80~180 | 10~20 dB. 빠른 더블킥·저역 끝이 자연스러운지 |
| 리얼드럼 스네어 | 고스트노트 보존이 우선 | 0.5~2 / 50~100 / 100~200 | 6~12 dB. 약한 stroke 때문에 bypass가 나을 수 있음 |
| 리얼드럼 랙탐 | 타격 간 누음 정리 | 0.5~3 / 80~150 / 150~300 | 10~20 dB. 작은 탐까지 열리는지 |
| 리얼드럼 플로어탐 | 긴 몸통 울림 보존 | 0.5~3 / 100~200 / 200~450 | 10~20 dB. 저역 decay를 과도하게 끊지 않음 |
| 하이햇·심벌·오버헤드·룸 | 전자/리얼 모두 일반적으로 bypass | 숫자 프리셋 비활성 | 지속음·공간감이 끊기기 쉬움 |

Threshold 설정 절차: 외부 믹서의 해당 채널에서 잡음/누음 구간과 **가장 약하게 살려야 할 연주**를 번갈아 듣는다. 열림 threshold를 두 수준 사이에서 조정하고, 약한 연주가 열리지 않으면 낮추거나 bypass한다. 두 수준이 겹치면 gate로 깨끗하게 분리하기 어렵다. hysteresis가 있으면 2~6 dB 차이를 시험할 수 있으나 이것도 고정값이 아니다. 최대 attenuation 대신 작은 Range에서 시작한다.

게이트는 열린 동안 섞인 누음·hiss를 제거하지 못한다. 발진 방지 장치나 불량 케이블의 해결책으로 설명하지 않는다. 전자/리얼드럼의 detector key filter는 해당 킥/탐에 반응하도록 외부 장비에서 시험할 수 있지만, 혼합 입력 RTA가 그 설정을 자동 산출하지 않는다.

### 18.4 컴프레서 악기별 출발점

Threshold는 아래 GR 청취 출발 범위가 **외부 믹서의 GR 미터**에서 큰 연주 때 나타나는 정도로 사용자가 조정한다. 앱 마이크 dBFS를 Threshold로 복사하지 않는다. 모든 행의 bypass 선택을 유지한다. GR은 강제 목표가 아니며 이미 일정한 소스에는 0 dB가 적절할 수 있다.

| 악기/파트 | Ratio | Attack ms | Release ms | 큰 음에서 GR 참고 | 청취 목표와 부작용 |
|---|---|---|---|---|---|
| 신디 피아노/EP | 2:1~3:1 | 15~35 | 100~250 | 1~3 dB | 건반별 편차 완화. 빠르면 건반 터치가 둔해짐 |
| 신디 패드/스트링 | bypass 또는 1.5:1~2:1 | 30~80 | 200~600 | 0~2 dB | 느린 swell을 누르지 않기. 이미 평탄하면 불필요 |
| 신디 리드/브라스 | 2:1~3:1 | 10~30 | 80~200 | 1~3 dB | 프레이즈 유지, 의도한 어택·필터 움직임 보존 |
| 신스 베이스 | 2:1~4:1 | 15~40 | 100~250 | 1~4 dB | 서브 펌핑·왜곡과 패치 내 압축 중복 확인 |
| 어쿠스틱 스트로크 | 2:1~3:1 | 15~35 | 80~180 | 2~4 dB | 강약 완화, 피크 어택과 리듬 유지 |
| 어쿠스틱 핑거스타일 | 2:1~3:1 | 5~20 | 100~250 | 1~3 dB | 돌출 피킹 완화. 손가락 잡음·잔향이 커질 수 있음 |
| 일렉 클린 | 2:1~3:1 | 10~30 | 80~200 | 2~4 dB | 터치 편차, sustain. 어택 손실·노이즈 확인 |
| 일렉 하이게인 | bypass 또는 1.5:1~2:1 | 15~40 | 100~200 | 0~2 dB | 왜곡 자체로 압축된 경우가 많아 추가 압축 최소화 |
| 베이스 핑거/피크 | 3:1~4:1 | 15~40 | 80~200 | 3~5 dB | 음정별 레벨 정리, 펀치 유지. 저음에서 너무 빠른 release의 거침 확인 |
| 베이스 슬랩 | 3:1~5:1 | 5~15 | 60~150 | 3~6 dB | 돌출음을 줄이되 타격을 모두 없애지 않기 |
| 전자드럼 전체 키트 | bypass 또는 1.5:1~2:1 | 20~40 | 100~250 | 0~2 dB | 이미 처리된 키트 중복 압축·심벌 펌핑 주의 |
| 전자드럼 개별 파트 | 리얼드럼 해당 파트 범위에서 약한 쪽 | 파트별 | 파트별 | 0~3 dB | 샘플/모듈 처리 확인, 단순 동일값 자동 적용 금지 |
| 리얼드럼 킥 | 3:1~4:1 | 15~35 | 60~150 | 2~4 dB | 펀치/일관성. 비터가 사라지면 attack 재검토 |
| 리얼드럼 스네어 | 3:1~4:1 | 10~30 | 80~180 | 2~4 dB | 타격/바디 균형, 하이햇 누음 증폭 확인 |
| 리얼드럼 탐 | 2:1~4:1 | 15~35 | 120~300 | 2~4 dB | 몸통 유지, 다음 타격 전 회복 여부 |
| 하이햇·오버헤드·심벌 | bypass 또는 1.5:1~2:1 | 20~40 | 150~350 | 0~2 dB | 잔향 펌핑·킥/스네어에 끌리는 압축 확인 |
| 리얼드럼 룸/전체 버스 | bypass 또는 1.5:1~2:1 | 20~40 | 100~300 | 1~3 dB | 의도적인 효과가 아니라면 공간 과장 최소화 |

초기 knee는 soft/medium 안내, makeup은 0 dB에서 시작하여 bypass와 청감 레벨을 비슷하게 맞춘다. Auto makeup이 켜져 있는지 사용자가 확인한다. 저음 한 주기와 비슷하게 매우 빠른 시간 설정을 하면 waveform을 따라 gain이 흔들리며 거칠어질 수 있다. release를 템포와 비교할 수는 있지만 `60,000/BPM`을 곧바로 최적 release로 추천하지 않는다.

신스와 전자드럼 패치에는 자체 압축·리미터가 있을 수 있다. EQ에서 저역을 부스트하면 compressor detector 반응이 달라질 수 있다. EQ → compressor, compressor → EQ 중 무조건적인 정답을 만들지 않는다. Gate를 compressor 앞에 두면 makeup으로 커진 잡음에 반응하는 일을 줄일 수 있으나 실제 믹서의 삽입 구조·내장 sidechain에 따라 달라진다. 처리 순서는 메모로 저장하고 바뀌면 A/B 조건에 표시한다.

### 18.5 UI와 사용 절차

기존 악기 가이드 화면에 `[EQ] [게이트] [컴프레서]` 탭을 둔다. 악기·subtype 선택은 공통으로 유지하고 게이트·컴프레서 탭은 정적 추천 설정표와 설명 카드만 표시한다. 측정 시작, RTA 오버레이, 시간 그래프, Before/After 버튼을 이 두 탭에 배치하지 않는다.

- 게이트 카드: 사용 권장 여부/bypass, Attack, Hold, Release, Range, Threshold 조정 방법, 주의사항.
- 컴프레서 카드: 사용 권장 여부/bypass, Ratio, Attack, Release, Knee, 외부 믹서에서 확인할 GR 참고 범위, Threshold/Makeup 조정 방법.
- 숫자는 18.3~18.4의 출발 범위로 표시하고, 악기 특성상 불필요하면 `기본: 사용 안 함`을 먼저 보여준다.
- Threshold는 입력 게인·장비 기준에 따라 달라지므로 공통 고정 숫자 대신 외부 믹서에서 맞추는 방법을 표시한다. GR 참고값은 외부 믹서 미터에서 사용자가 확인할 값이며 앱의 실측값이 아니다.
- 짧은 도움말: `추천값에서 시작해 믹서에서 직접 조정하고 들어보세요. 장비와 연주에 따라 적절한 값이 달라집니다.`

사용자는 악기와 연주 유형을 선택하고 추천값을 읽은 뒤 믹서에서 직접 설정한다. 약한 음·큰 음·긴 끝음을 들으며 조정한다. 앱은 설정값 입력이나 비교 측정을 요구하지 않는다. 게이트·컴프레서 전용 사용자 프리셋, 측정 기록, 교육용 시뮬레이터도 이번 범위에 추가하지 않는다. 기존 EQ 프리셋 기능은 유지한다.

### 18.6 정적 데이터 모델과 구현 범위

기존 악기 카탈로그에 다음 안내 데이터만 연결한다. 별도 오디오 처리·시간 통계·스냅샷 모델을 만들지 않는다.

| 모델 | 필드 |
|---|---|
| DynamicsGuidance | instrument/subtype, processorType(GATE/EXPANDER/COMPRESSOR), bypassDefault, usageCondition, cautions, catalogVersion, sourceIds |
| GateGuidance | attackMsRange?, holdMsRange?, releaseMsRange?, attenuationDbRange?, hysteresisDbRange?, thresholdProcedureKo |
| CompressorGuidance | ratioRange?, attackMsRange?, releaseMsRange?, kneeHint, grReferenceDbRange?, thresholdProcedureKo, makeupProcedureKo |

숫자 범위는 min/max와 단위를 명시한다. 추천값이 없는 항목은 null로 두고 `사용 안 함` 또는 설명을 표시한다. 0 ms나 임의 Threshold로 채우지 않는다. Range는 양수 감쇠량, ratio는 1 이상, 시간은 0 이상의 유한수로 검증한다. 참고 GR과 추천 시간 범위는 카탈로그 콘텐츠이며 실측 데이터가 아니다.

구현은 CatalogRepository와 정적 Compose 카드 범위로 제한한다. 캡처·DSP·스냅샷·DB migration은 이 안내 기능 때문에 변경하지 않는다. 탭 전환으로 기존 EQ 측정이 자동 시작되거나 새 AudioRecord가 열리지 않아야 한다.

### 18.7 추가 검증 기준

1. 6종 악기와 명시된 세부 유형/드럼 파트에 추천 설정값·bypass·주의사항이 표시된다.
2. 각 수치의 단위, 범위 순서, ratio·감쇠량 표기가 정확하고 숫자가 잘리지 않는다.
3. 패드와 전체 키트 gate 등 사용을 권하지 않는 경우 bypass가 명확하다.
4. Threshold는 외부 믹서에서 맞추는 방법으로 설명하고 앱의 dBFS/SPL을 대입하지 않는다.
5. GR은 추천 참고 범위로만 표시하며 실측값·효과 점수처럼 표현하지 않는다.
6. 마이크 권한 없음·내장 마이크·USB 연결 상태와 무관하게 같은 안내를 열람할 수 있다.
7. 게이트·컴프레서 탭에 RTA/시간 분석·측정·A/B·자동 설정 UI가 없고 관련 분석 worker도 추가되지 않는다.
8. 추천 설정값과 설명은 음향 담당자가 검토하며 Codex는 카탈로그·UI 일치와 범위 준수를 검증한다. 외부 장비의 압축 효과를 앱으로 검증하는 시험은 요구하지 않는다.

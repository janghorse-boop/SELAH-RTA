# 녹음·동기 재생 설계 (1차)

2026-09-21 · 구현자: Claude Code · **승인 전 설계서**
근거 명세: 「추가 명세: Recording & Synchronized Analysis」

## 0. 확정된 것

| 물음 | 정한 것 |
|---|---|
| 파일 형식 | **WAV 먼저.** AAC/M4A 는 다음 단계 |
| 재생 화면 | **최소** — 재생/일시정지·seek·SPL 그래프·커서·그 시점 수치 |
| 녹음 조건 | **측정 중에만** REC 를 누를 수 있다 |

## 1. 이 단계에서 만드는 것과 안 만드는 것

**만든다**

- 측정 중 REC → 마이크 PCM 을 WAV 로 저장
- 같은 시간축의 측정 타임라인 저장(0.5초 간격)
- 세션 메타데이터(마이크·샘플레이트·보정·기기 전환 이벤트)
- 최소 재생 화면: 재생/일시정지, ±10초, seek bar, 현재/전체 시각,
  SPL 시간 그래프 + 재생 위치 커서, 그 시점의 dBA/dBC/Leq/MAX/Peak

**안 만든다(다음 단계)**

- AAC/M4A 인코딩, 파형 개요 그리기, 31밴드 RTA 동기 표시,
  Peak·하울링·클리핑·구간 마커와 「들어보기」, 그래프 탭 seek,
  오프라인 재분석

명세가 요구한 것 가운데 **무엇을 아직 안 했는지**가 이 목록으로 남습니다.

## 2. 어디서 분기하는가 — 그리고 왜 거기인가

```
AudioRecord → runCaptureLoop → AudioBlock ─┬→ DSP (SPL·RTA·하울링)   [오디오 스레드]
                                           └→ RecordingSink          [오디오 스레드에서 건네기만]
                                                  │ 유한 큐
                                                  ↓
                                           녹음 스레드: WAV + 타임라인 쓰기
```

**분기점은 `CaptureController.onBlock`** 입니다. 거기가 이미 한 세션의
DSP 를 전부 지나는 자리이고, 그 앞(`CaptureLoop`)은 안드로이드에 기대지
않게 유지해야 합니다.

**반드시 지킬 두 가지**

1. **오디오 스레드에서 파일을 쓰지 않는다.** 파일 IO 는 수십 ms 씩 멎을
   수 있고, 그동안 `read()` 가 밀리면 **측정이 끊깁니다.** 건네주기만
   합니다.
2. **`AudioBlock.samples` 는 빌려주는 배열이다.** `runCaptureLoop` 이
   버퍼 하나를 재사용하므로(초당 50번 쓰레기를 만들지 않으려고 그렇게
   돼 있습니다), 큐에 넣을 때는 **반드시 복사**합니다. 복사본은 풀에서
   돌려 씁니다 — 안 그러면 GC 가 캡처를 멈추는 원래 문제로 돌아갑니다.

## 3. 큐가 밀리면 — 숨기지 않는다

느린 저장장치에서 녹음 스레드가 못 따라올 수 있습니다. 세 가지 중
하나를 골라야 합니다.

| 방법 | 결과 |
|---|---|
| 오디오 스레드를 막는다 | **측정이 끊긴다.** 절대 안 된다 |
| 조용히 버린다 | 녹음에 **말 없는 구멍**이 생긴다. 나중에 들으면 방이 그런 줄 안다 |
| **버리되 반드시 남긴다** | 버린 프레임 수를 세고 타임라인에 **끊김 사건**으로 적는다 |

**세 번째로 합니다.** 그리고 버린 양이 문턱을 넘으면 **녹음을 멈추고
알립니다** — 구멍투성이 녹음은 없는 것보다 나쁩니다. 화면에는 「이 녹음에
N초가 빠졌습니다」를 남깁니다.

이 프로젝트의 규칙과 같습니다: **말하지 않은 실패는 없다.**

## 4. 시간 동기화

명세가 못박은 요구입니다 — 벽시계로 맞추지 않습니다.

- 세션에 **`recordingStartMonotonicNs`** 를 적습니다.
- 모든 측정 행과 사건은 그 값 기준 **경과 ms** 로 적습니다.
- 오디오 파일의 표본 위치도 같은 기준입니다: 첫 프레임이 0.
- `AudioBlock.monotonicNs` 가 이미 그 시계입니다(캡처 루프가 덩어리를
  손에 쥔 시각). **새로 만들 것이 없습니다.**
- 재생 위치(ms) → 타임라인 행 번호는 **나눗셈 한 번**입니다(간격 고정).

**끊김(discontinuity)** — 큐가 밀려 버린 구간, 마이크 전환, 일시정지는
모두 타임라인에 사건으로 남기고, 그 뒤의 오프셋을 명시적으로 관리합니다.
「소리와 그래프가 여기서부터 N ms 어긋난다」를 추측하지 않게 합니다.

**드리프트** — 장시간 녹음에서 표본 수 기준 시간과 단조 시계가 벌어질 수
있습니다. 두 값을 주기적으로 함께 적고, **허용 오차를 정해 시험**합니다
(첫 목표: 2시간에 ±100ms). 재기 전에는 숫자를 적지 않습니다.

## 5. 저장 구조

```
files/recordings/<sessionId>/
    audio.wav        오디오 원본(16-bit PCM, 모노, 열린 샘플레이트 그대로)
    timeline.bin     0.5초 간격 측정 스냅샷(고정 길이 레코드, append-only)
    session.json     메타데이터와 사건 목록
```

### 5.1 WAV

- **16-bit PCM.** 24-bit 는 1.5배(시간당 518MB)이고, SPL·RTA 판정에는
  16-bit 의 여유가 충분합니다. **다만 이것이 재분석 정밀도의 상한**이라는
  것을 세션에 적어 둡니다.
- 헤더의 크기 필드는 32비트라 **4GB 가 한계**입니다. 48kHz 16-bit 모노면
  약 12.4시간이지만, **여유를 두고 상한에서 멈추고 알립니다.**
- 시작 전 **남은 저장 공간을 보고**, 예상 길이를 못 담으면 시작하지
  않습니다.

### 5.2 타임라인 — Room 을 쓰지 않는 쪽을 권합니다

명세 표는 「분석 데이터 | Room DB」라고 적었습니다. **다르게 하자고
제안**하며, 근거를 적습니다.

| | Room | 고정 길이 이진 파일 |
|---|---|---|
| 새 의존성 | Room 3종 + KSP 플러그인 | **없음** |
| seek | 쿼리 | **나눗셈 한 번** (행 번호 = ms / 500) |
| 2시간 크기 | 비슷 | 14,400행 × 약 100B = **1.4MB** |
| 스키마 변경 | 마이그레이션 필요 | 버전 바이트 + 새 파일 |
| 시험 | 기기/Robolectric | **순수 JVM 에서 결정적으로** |

마지막 줄이 이 프로젝트에서 가장 무겁습니다 — 지금까지 잡은 결함은 거의
전부 **JVM 에서 순서를 고정해** 잡았습니다.

**Room 이 나은 경우**는 세션을 가로지르는 질의(「하울링이 N회 넘은 예배
찾기」)인데, 1차 범위에 없습니다. 필요해지면 그때 타임라인을 읽어 넣으면
됩니다 — 원본이 파일이라 되돌릴 수 있습니다.

**결정해 주시면 ADR 로 남기겠습니다.**

한 행(고정 길이):

```
elapsedMs(u32) segment(u8) flags(u8) dBA dBC dBZ leq10s leq1m max peak (f16 ×7)
bands[31](f16)  → 약 100 바이트
```

`flags` 에 클리핑·끊김·미보정을 담습니다. **미보정 플래그가 중요합니다**
— 나중에 그 숫자를 음압이라 부르지 않게 합니다.

### 5.3 세션 메타데이터

마이크(종류·이름·`stableKey`), 샘플레이트·인코딩, **보정 프로파일과
`isReferenceOnly`**, 녹음 포맷, `recordingStartMonotonicNs`, 시작 벽시계
(표시용), 기기 전환·끊김 사건 목록, 버린 프레임 수, 분석 버전.

## 6. 세션 수명주기 — 지금 구조에 어떻게 얹는가

- REC 는 **측정 중에만** 눌립니다. 측정이 끝나면 녹음도 끝납니다.
- 측정 세션(`CaptureSession`)이 바뀌면(마이크 전환·오류 복구) **녹음도
  거기서 끊고** 사건으로 남깁니다. 다른 마이크의 소리를 한 파일에
  이어 붙이지 않습니다 — 측정값을 이어 붙이지 않는 것과 같은 이유입니다.
- 녹음 자원의 수명주기는 **`SignalPlayer` 에서 배운 규칙을 그대로**
  씁니다: 세션이 소유하고, 떼어 내기와 종료 추적을 한 전환으로 하고,
  닫기 실패를 성공처럼 세지 않습니다.

## 7. 실패를 어떻게 말하는가

| 무엇 | 어떻게 |
|---|---|
| 저장 공간 부족(시작 전) | 시작하지 않고 필요한 용량을 알린다 |
| 저장 공간 부족(도중) | 녹음만 멈추고 **측정은 계속**. 파일은 그때까지 유효하게 닫는다 |
| 큐 밀림 | 끊김 사건 + 화면 표시. 문턱 넘으면 녹음 종료 |
| 마이크 전환 | 녹음 끊고 사건 기록 |
| 앱 종료·비정상 종료 | WAV 헤더를 주기적으로 갱신해 **거기까지는 재생 가능**하게 |

## 8. 시험 계획 — JVM 에서 결정적으로 볼 것

| 무엇 | 어떻게 |
|---|---|
| **녹음이 측정을 바꾸지 않는다** | 같은 PCM 을 녹음 켜고/끄고 넣어 측정 결과가 **비트 단위로 같은지** |
| 오디오 스레드가 막히지 않는다 | 가짜 저장소를 느리게 만들고 `onBlock` 의 소요 시간을 잰다 |
| 버린 프레임이 기록된다 | 큐를 일부러 채우고 끊김 사건과 수를 본다 |
| 시간 정렬 | 알려진 시각에 임펄스를 넣고 WAV 표본 위치와 타임라인 행이 맞는지 |
| 드리프트 | 긴 합성 입력에서 표본 기준 시간과 단조 시계의 차이 |
| 끊긴 파일 복구 | 헤더 갱신 전에 끊고 열어 본다 |
| 마이크 전환 | 세션이 바뀌면 파일이 닫히고 사건이 남는지 |

실기기에서만 볼 것(따로 적습니다): 실제 저장 속도, 장시간 열·메모리,
재생 싱크의 청감 확인.

## 9. 명세와 다른 점·미결

1. **타임라인을 Room 대신 파일로** — 5.2 의 근거. 승인 필요.
2. **16-bit PCM** — 재분석 정밀도의 상한을 명시.
3. **AAC/M4A 는 다음 단계** — 인코더 지연·priming 보정을 따로 검증해야
   하므로 1차에서 분리.
4. 드리프트 허용 오차는 **재 본 뒤** 정합니다. 지금은 목표만 적었습니다.

3. 타임라인 writer/reader (JVM 시험)
4. `CaptureController` 에 붙이기 — **측정 결과 불변**을 먼저 시험
5. 세션 메타데이터·사건
6. 최소 재생 화면

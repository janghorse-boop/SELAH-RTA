# 응답곡선 첫 실측 시도 — 통과 못 함

날짜: 2026-09-24 새벽 (조용한 사무실)
경로: EMM-6 → UMC404HD(Input 1) 기준 / S23 Ultra 내장(하단) 대상
소리: PC 스피커, 핑크 노이즈 연속

**결론부터: 곡선은 만들어졌지만 앱의 관문을 통과하지 못했다. 적용하지
않았다.** 문턱을 낮춰 통과시키지 않았다.

## 통과한 것

| 단계 | 결과 |
|---|---|
| 1 장비·CAL | EMM-6_17860.txt, 점 256개, 20Hz~20kHz, 「마이크 응답」으로 읽음 |
| 2 DSP 점검 | 장 60개 · 본 대역 29개 · **이득 변화 0.0dB** · 모양 변화 3.8dB · 잡음 바닥 −63.7dBFS |
| 3 물리 마이크 | **LogicalOnly** — 「back」을 고르면 [22,24]가 함께 활성 |
| 4 세 번 측정 | 기준(처음)·대상·기준(마지막) 각 120장 |

## 막힌 곳

```
반복 측정이 4.6dB 벌어졌습니다(허용 2.0dB).
레벨은 11개 대역(40점)에서 맞췄습니다 — 오프셋 +42.0dB.
```

앞뒤 기준이 4.6dB 벌어졌다. 그사이 **입력 기기를 두 번 갈아 끼우느라
5분**이 걸렸다(기준=USB, 대상=내장). 앱은 기기 변경을 다음 측정 시작에
반영하므로 단계마다 「측정 종료 → 기기 선택 → 측정 시작」을 거쳐야 한다.

그 5분 동안 무엇이 변했는지는 **가르지 못했다.** 후보:

- USB 경로를 다시 열 때마다 이득이 달라진다
- 스피커·방이 그사이 변했다
- 마이크가 미세하게 움직였다

**다음에 할 일은 이것부터 가르는 것이다.** 아무것도 바꾸지 않고 USB 를
두세 번 다시 열어 dBFS 를 견주면 첫 후보가 바로 갈린다. 이득이 튄다면
기기 전환을 끼우는 이 순서로는 이 폰에서 교정이 되지 않는다는 뜻이고,
그때는 「기준 두 번을 붙여 재고 대상을 나중에」 같은 다른 순서를 봐야 한다.

## 핑크 노이즈 파일 길이가 판정을 흔들었다

DSP 점검의 모양 변화가 3.3 → 4.9 → 4.3dB 로 튀어 두 번 「NS 있을 수
있음」에 걸렸다(허용 4.0). 걸린 대역도 40Hz, 160Hz 로 매번 달랐다.

원인은 앱이 아니라 **내가 튼 소리**였다. 20초짜리 파일을 반복 재생했는데
측정 창이 7초쯤이라, **이음매가 창에 들어가면** 그 순간의 불연속이 대역
모양 변화로 잡혔다. 300초짜리로 바꾸니 3.8dB 로 바로 통과했다.

**문턱은 건드리지 않았다.** 재는 쪽이 틀렸지 관문이 틀린 것이 아니었다.
같은 이유로 4.0 이라는 값은 여전히 실측 두 번(2.2·3.2dB)에 기대고 있다 —
이음매 없는 소리로 여러 번 더 재서 다시 볼 값이다.

## 측정하면서 잡은 앱 결함 둘

1. 5단계가 **예시 곡선만** 받고 있어, 세 번을 다 재고 넘어가도 「아직 잰
   것이 없습니다」였다. 저장 전에 눈으로 보라고 둔 단계가 통째로 비어
   있었다.
2. 3단계 탐색 버튼이 재는 동안 「탐색 중…」이라고 적혀 있었다. 넘어오던
   값은 「측정 중인가」였다. 탐색은 시작도 안 했는데 기다리게 만든다.

둘 다 **실제로 끝까지 돌려 보지 않았으면** 보이지 않았을 것들이다.

## 남은 것

- 위의 「USB 를 다시 열면 이득이 달라지는가」 실험
- 그다음 세 번 측정을 다시, 기준 사이 시간을 최대한 줄여서
- 1kHz 음압 교정기가 오면 절대 기준을 다시 잡는다(그때 94 또는 114dB
  버튼을 쓴다). 곡선은 1kHz 에 못이 박혀 있으므로 순서는 상관없다
  ([결정](../decisions/2026-09-24-curve-anchored-at-1khz.md))

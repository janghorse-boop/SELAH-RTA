# UMC404HD + EMM-6 를 처음 꽂은 결과

측정: 2026-09-23 · 갤럭시 S23 Ultra(SM-S918N) · Android 16
장비: Behringer UMC404HD + Dayton Audio EMM-6(시리얼 17860) · Input 1 · +48V ON · 게인 3시
대상: [첫 연결 계획](2026-09-23-umc404hd-first-plug-plan.md)

계획서가 물은 것에 차례로 답한다. **막혀 있던 보정 부호가 풀렸다.**

---

## 1. 안드로이드가 UMC404HD 를 어떻게 보는가 — **4채널 다 내준다**

```
id=2120 type=11 name='USB-Audio - UMC404HD 192k' addr='card=1;device=0'
        ch=1,2,3,4   fs=48000,96000,176400,192000,44100,88200
```

- `type=11` = `TYPE_USB_DEVICE`. `classifyInput` 이 `Usb` 로 받는다.
- **`ch=1,2,3,4`** — 계획서가 걱정한 「2채널로 제한」이 아니었다.
  **설계를 바꿀 일이 없다.**
- 48kHz 지원. 실제로 48000 으로 열렸다.

USB 전용 권한은 **필요 없었다.** `UsbManager` 대화상자 없이 `AudioManager`
경로로 바로 보인다 — [대조 문서](2026-09-22-usb-audio-gap-analysis.md) 2.2
의 판단이 맞았다.

## 2. 실제로 몇 채널로 열리는가 — **고른 번호에 맞춰 열린다**

| 고른 채널 | 열린 형식 | 버퍼 |
|---|---|---|
| Input 1 | `channelCount=1, channelIndex=0` (모노) | 30,720 B |
| Input 2 | `channelCount=2, channelIndex=1` | — |
| Input 3 | `channelCount=3, channelIndex=2` | 92,160 B |

`planChannels` 가 「고른 번호가 들어가는 가장 작은 수」로 여는 것이
그대로 동작했다. 버퍼도 채널 수에 비례한다.

**색인 마스크(`setChannelIndexMask`) 경로가 처음 돌았다.** 어제까지
「코드만 있고 돌려 본 적 없다」고 적어 둔 자리다. Input 3 에서
`(1 shl 3) - 1 = 0b111` 로 3채널이 열렸다.

## 3. 고른 채널이 정말 그 채널인가 — **맞다**

EMM-6 는 Input 1 에만 꽂혀 있었다(2·3·4는 비어 있음).

| 고른 채널 | Peak |
|---|---|
| Input 1 (EMM-6 · 팬텀 ON) | **−22 ~ −25 dBFS** |
| Input 2 (빈 입력) | **−80.8 dBFS** |
| Input 3 (빈 입력) | **— (디지털 0)** |

**56dB 이상 벌어진다.** 다운믹스였다면 셋 다 같은 값이 나왔을 것이다.
지시서 17장 DoD 「선택 채널이 FFT 에 정확히 매핑됨」을 **증명했다.**

셋이 서로 다른 것도 뜻이 있다 — Input 2 는 인터페이스 잡음 바닥,
Input 3 은 완전한 0. 같은 「빈 입력」이라도 경로가 다르다.

## 4. 보정 부호 — **응답이다. 지금 코드가 맞다**

어제까지 막혀 있던 자리다(지시서 9.4: *「불명확하면 임의 부호로
측정값을 변경하지 않는다」*).

실제 EMM-6 파일(시리얼 17860):

```
*1000Hz	-41.1        ← 1kHz 감도. 주석이라 곡선에 안 들어간다
	                   ← 탭 하나뿐인 줄
20.00	-2.0
…                     256점, 20Hz~20kHz, 탭 구분, CRLF
```

우리 파서가 **256점을 하나도 빠뜨리지 않고** 읽었다(건너뛴 줄 0).

| 주파수 | 값 |
|---|---|
| 20Hz | **−2.0 dB** |
| 100Hz | +0.7 |
| 1kHz | **+0.06** (0 으로 정규화) |
| 8kHz | +2.4 |
| 20kHz | **+4.1 dB** |

**저역이 처지고 고역이 오르는 모양이다.** 이것은 EMM-6 의 알려진
**응답**이다 — 소구경 일렉트릿 측정 마이크는 다이어프램 공진으로 고역이
들린다. 이 파일이 `correction`(더할 값)이라면 「이 마이크는 20kHz 에서
4dB **덜** 잡는다」는 뜻이 되는데, 그건 이 마이크의 성질과 반대다.

그리고 1kHz 감도를 첫 줄에 따로 적고 곡선은 그 1kHz 에서 0 으로 정규화돼
있다 — 응답 곡선의 전형적 형식이고, 이 계열 cal 파일을 쓰는 도구
(REW·ARTA)가 **응답을 빼는** 관례와 같다.

**결론: `CalibrationCurve` 의 지금 규약(빼기)이 맞다. 고칠 것이 없다.**

**다만 파일이 스스로 밝힌 것은 아니다.** 열 이름이 없어 `sign=Unknown`
이고(그래서 거짓 경고도 안 뜬다), 판단의 근거는 ① 곡선 모양 ② 관례
둘이다. **다른 마이크의 파일에는 그대로 적용되지 않는다** — 그 파일은
그 파일대로 봐야 한다.

실제 파일은 저장소에 올리지 않는다(`inbox/` 규칙). 형식을 본뜬
`dsp/src/test/resources/SYNTH-emm6-format-sample.txt` 가 시험을 붙든다.

## 5. 화면 — 이번에 처음 눈으로 본 것들

- **채널 선택**: Input 1~4 가 뜬다. 기기가 알린 값 그대로이고 4를
  박아 넣지 않았다.
- **신호없음 안내**: Input 2(−84 dBFS)에서 3초 뒤 떴다. 문구에 기기
  이름이 **실제 값으로** 들어간다 — 「USB-Audio - UMC404HD 192k
  (card=1;device=0) 의 +48V 팬텀전원 및 GAIN 을 확인해주세요」.
- **외부 측정 준비 카드**: 팬텀전원이 **실제로 켜져 있는데도 `?`** 로
  나온다. 설계대로다 — 앱이 확인할 수 없는 것에 체크를 붙이지 않는다.
- **보정 카드**: `EMM-6_17860.txt · 점 256개 · 20Hz ~ 20kHz`.

## 6. 입력 소스와 DSP — **UNPROCESSED 를 못 쓴다**

```
audioSource=VoiceRecognition, unprocessedSupported=false
AGC: 기기에 없음 / NS: 원래 꺼짐 / AEC: 원래 꺼짐
```

S23 은 `UNPROCESSED` 를 지원하지 않아 `VOICE_RECOGNITION` 으로 열렸다.
AGC 는 세션에 붙지 않고 NS·AEC 는 원래 꺼져 있었다. **설정값으로 확인한
것까지이고**, 하드웨어·HAL 안쪽은 알 수 없다(S23 지시서 2장이 요구한
신호 기반 잔여 DSP 검사는 아직 안 했다).

## 7. 교정 측정은 **하지 못했다** — SNR 부족

사무실에서 PC 스피커로 핑크 노이즈를 냈다(볼륨은 낮춰서).

| | 가장 큰 대역(125Hz) |
|---|---|
| 핑크 노이즈 ON | 82.8 dB |
| OFF (에어컨·선풍기) | 73.8 dB |

**가장 센 대역에서도 SNR 이 9dB 뿐이다.** 배경 스펙트럼은 20~80Hz 가
특히 높다 — 에어컨·선풍기의 저역 럼블이다. 이 조건에서 잰 보정 곡선은
저역이 통째로 배경 소음의 모양이 된다.

지시서 3.3 이 *「SNR 이 낮거나 불안정한 구간을 배제한다」*, 4장이
*「허용 기준을 통과하지 못하면 저장·자동 적용을 막고 재측정을
안내한다」* 고 한 그 경우다. **사람이 없을 때 다시 잰다.**

## 8. 내장 마이크 분리 — USB 를 꽂아도 그대로

`LogicalOnly`. 후면을 골라도 하단이 함께 활성이다
([어제 결과](2026-09-22-s23-mic-separation-finding.md)와 같다).
USB 인터페이스가 붙은 조건에서도 바뀌지 않았다.

## 9. 케이스 — 사용자가 짚은 것

> 후면 마이크는 케이스 때문에 막혀서 하단과 소리 변화가 클 것.

맞는 지적이고, 지시서 6장의 「케이스 등 음향 조건 변경」이 그것이다.
후면을 고르면 **케이스를 벗기라는 안내**를 띄우도록 했다
(`builtInMicNoticeKo`). 위치는 기기가 알린 주소(`back`)로 판단하고,
모르는 주소면 아무 말도 하지 않는다.

3. 지시서 6장 **프로파일 저장**.
4. 신호 기반 **잔여 DSP 검사**(일정 레벨 신호의 시간별 이득 변화).

## 확인하지 않은 것

- **교정 측정 자체를 못 했다**(7절).
- 3m 케이블의 드롭 — 길게 재 보지 않았다. 이번 짧은 측정에서는 읽기
  오류 0.
- Input 4 는 건너뛰었다(2·3 으로 매핑이 증명돼 더 낮출 여지가 없다).
- 입력 소스를 바꿔 가며(`MIC` 등) 재지 않았다.
- 케이스 안내는 **화면에서 눈으로 보지 못했다** — 기기를 뺀 뒤에 붙였다.

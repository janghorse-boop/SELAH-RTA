# UMC404HD + EMM-6 를 처음 꽂을 때 — 무엇부터 볼 것인가

작성: 2026-09-22 (장비 연결 전날) · 기준 커밋 `d2e126e`

장비: Behringer UMC404HD(입력 4개) + Dayton Audio EMM-6 + XLR +
전용 전원 어댑터 + USB-B↔C 3m 케이블 + 갤럭시 S23.

**이 문서는 답이 아니라 질문의 순서다.** 지금까지 만든 것은 전부
「안드로이드가 무엇을 내주는지 모른다」는 전제 위에 있고, 그 전제가
풀리는 순간 설계가 갈리는 자리가 넷이다.

---

## 0. 꽂기 전에 한 번

```
adb logcat -c
```

앱을 **켜기 전에** 지운다. 기기 목록 로그는 앱이 뜰 때 찍힌다.

---

## 1. 안드로이드가 UMC404HD 를 어떻게 보는가 — **가장 먼저**

케이블을 꽂고 앱을 연 뒤:

```
adb logcat -d -s InputDeviceScanner:I | tail -1
```

이 한 줄에 답이 셋 들어 있다.

| 볼 것 | 왜 |
|---|---|
| `type=` | 11(USB_DEVICE)·22(USB_HEADSET)·12(USB_ACCESSORY) 중 무엇이든 `Usb` 로 받는다. 목록에는 뜬다 |
| **`ch=`** | **여기서 설계가 갈린다.** 아래 참고 |
| `fs=` | 48000 이 있는지. 없으면 열린 값을 그대로 쓴다(이미 그렇게 한다) |

### `ch=` 가 무엇이냐에 따라

- **`ch=1,2,4`** — 안드로이드가 4채널을 내준다. 설정에 「Input 1~4」가
  뜨고, `planChannels` 가 고른 번호에 맞춰 연다. **설계 그대로다.**
- **`ch=1,2`** — 안드로이드가 **2채널까지만** 내준다. 그러면 Input 3·4 는
  앱에서 고를 수 없다. **설계를 바꾸지 말고 먼저 적는다** — 인터페이스
  쪽에서 1·2번 입력을 쓰는 것으로 운용이 갈린다.
- **목록에 안 뜬다** — `AudioManager` 경로로는 못 쓴다는 뜻이고, 그때서야
  `UsbManager`(raw USB) 이야기가 시작된다. 지금까지의 판단
  (`docs/spec/2026-09-22-usb-audio-gap-analysis.md` 2.2)이 틀린 경우다.

**짐작해서 미리 만들지 않았다.** 이 줄을 보고 정한다.

---

## 2. 실제로 몇 채널로 열리는가

설정에서 UMC404HD 를 고르고 측정을 시작한 뒤:

```
adb logcat -d -s MicSource:I | grep "열림"
```

`channelCount=` 를 본다. **1번의 `ch=` 와 다를 수 있다** — 알리는 것과
열리는 것은 다르고, 이 프로젝트가 요청과 결과를 갈라 두는 까닭이 그것이다.

진단 화면의 「채널」 줄에도 같은 값이 뜬다(`4 중 2번` 형식).

2채널 넘게 열릴 때만 `setChannelIndexMask` 경로를 타는데, **그 경로는
한 번도 돌려 본 적이 없다.** 실패하면 조용히 다음 후보로 내려가 결국
모노로 열린다 — 그것도 `channelCount=1` 로 보인다.

---

## 3. 고른 채널이 정말 그 채널인가 — **DoD 의 핵심**

지시서 17장: *「선택 채널이 FFT 에 정확히 매핑됨」*.

EMM-6 를 **Input 1 에만** 꽂은 상태에서:

1. 설정에서 채널을 **Input 1** 로 두고 측정 → 소리에 반응해야 한다.
2. 채널을 **Input 2** 로 바꾸고 다시 측정 → **조용해야 한다**(아무것도
   안 꽂혀 있으므로).
3. EMM-6 를 Input 2 로 옮기고 → 이번에는 Input 2 에서 반응.

**2번이 조용하지 않으면 채널 매핑이 틀린 것이다.** 다운믹스되고 있거나
인터리브가 밀렸다는 뜻이고, 그때는 `readOneChannel` 과
`deinterleave` 를 실제 값으로 다시 본다.

입력 레벨 막대(Peak·RMS)가 이 시험의 눈이다.

---

## 4. 보정 부호 — **막혀 있던 것**

EMM-6 의 시리얼별 보정 파일을 가져온 뒤:

```
adb logcat -d -s CurveImport:I
```

```
CurveImport: EMM-6_xxxxxx.txt header=[...] sign=... points=...
```

`header=` 에 열 이름이 찍힌다. 그리고 **파일 앞 20줄을 눈으로 본다**:

```
adb shell cat /sdcard/Download/EMM-6_xxxxxx.txt | head -20
```

### 판단

- 둘째 열이 **마이크의 응답**(SPL·Response·Measured)이면 → 지금 코드가
  맞다. 아무것도 안 고친다.
- 둘째 열이 **보정값**(Correction·Compensation)이면 → **부호가 반대다.**
  `CalibrationCurve` 가 빼는 대신 더해야 한다. 그때는 저장된 곡선의
  해석도 함께 바뀌므로, 파일마다 규약을 적어 두는 자리가 필요하다.
- 열 이름이 없으면 → 제조사 문서를 본다. **여전히 추측하지 않는다.**

`sign=LooksLikeCorrection` 이 찍히면 화면에도 경고가 함께 뜬다.

---

## 5. 그 밖에 이번에 처음 눈으로 볼 것

지금까지 코드만 있고 화면을 못 본 것들이다.

- **외부 측정 준비 카드** — 외부 입력일 때만 나온다. 팬텀전원과 GAIN 이
  `?` 로 뜨는지(`✓` 가 되면 안 된다).
- **보정 ON/OFF 토글** — 파일이 있어야 뜬다. 끄면 배지가 「꺼 둠」이
  되고 RTA 에서 보정이 빠지는지.
- **입력 레벨 Peak·RMS** — 짙은 쪽(RMS)이 옅은 쪽(Peak) 안에 있는지.
- **신호 없음 안내** — **팬텀전원을 꺼 보면** 3초 뒤에 떠야 한다. 그리고
  **조용한 방에서는 뜨지 않아야 한다**(이쪽이 더 중요하다).
- **클리핑 안내** — GAIN 을 올려 일부러 잘리게 한 뒤, 「UMC404HD 의
  GAIN 을 낮춰주세요」가 뜨는지. **기기 이름이 그대로 나오는지.**

---

## 6. 3m 케이블

지시서 15장이 따로 적어 둔 항목이다. 길이 때문에 드롭이 나는지는
진단 화면의 **「오디오 지연」**과 **「읽기 오류」**로 본다. 길게 재
봐야 하므로 마지막에 둔다.

---

## 7. 하지 않을 것

- **`ch=` 를 보기 전에 채널 UI 를 고치지 않는다.**
- **파일을 보기 전에 보정 부호를 건드리지 않는다.**
- 안 되는 것이 있으면 **먼저 로그로 적고**, 고치는 것은 그다음이다.
  이 저장소에서 거듭 데인 자리가 「화면만 보고 원인을 짚는 것」이었다.

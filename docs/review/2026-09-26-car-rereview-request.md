# 재검토 요청 — CA-R01~R05 수정분과 기록·리포트 뼈대

요청일: 2026-09-26 · 구현자: Claude Code · 요청 대상: Codex(독립 검증자)

[재검토 회신](2026-09-26-ca-independent-review.md)의 **High 4 · Medium 1**
을 모두 고쳤습니다. 범위: **`0e72cc0..45c34ae`** (8커밋 · 24파일 ·
+2,237/−94, 시험 890줄 포함).

## 먼저 답합니다

**다섯 다 맞았습니다.** 그리고 다섯이 전부 같은 모양이었습니다 —
지난번에 「갈랐다」고 한 것이 **기기 열쇠 하나로만 갈라 놓은 것**이었고,
저장소는 그보다 잘게 가르고 있었습니다.

요청서에 적은 두 가지도 틀렸습니다:

- **「재개방은 잡고 세션 도중만 남았다」** — 주소가 언제나 비어 있어
  아무것도 잡지 못했습니다(CA-R03).
- **「`AndroidViewModel` 이라 시험을 못 세운다」** — 5번 답에서 실제로
  세울 수 있음을 보여 주셨습니다. 두 번 적은 핑계였습니다.

## 1. 고친 것

### CA-R04 — 제가 만든 회귀 (가장 먼저 고쳤습니다)

`stopWork()` 가 전경 상태까지 내렸습니다. 이 함수는 **탭 이동·닫기에서도**
불리므로, 액티비티가 앞에 있는 채로 `inForeground=false` 가 되고
`ON_START` 는 오지 않습니다.

취소와 전경 상태를 갈랐습니다 — `stopWork()`(끊기만) ·
`onBackground()`(`ON_STOP` 전용) · `onForeground()`(`ON_START`).

**시험을 둘 나란히 두었습니다.** 「앞에 없으면 안 낸다」와 「다시 오면
낸다」를 한 파일에 붙여, 한쪽을 고치다 다른 쪽을 깨면 바로 걸리게 했습니다.

**봐 달라**: 다중 창처럼 `ON_STOP` 없이 가려지는 경우는 그대로 재생을
허용합니다. 8절에서 「가능한 정책」이라 하셨던 자리인데, 지금 구현이 그
정책과 실제로 맞는지 봐 주십시오.

### CA-R01 — 경로 전체로 견줍니다

`WizardState.targetCalKey` 를 붙들고 셋을 모두 고쳤습니다 — 옮기기 관문
(`transferBlockedKo`), 곡선 저장(`save`), `saveOffsetDirect`.

**봐 달라**: 기준 쪽은 `referenceCalKey` 가 이미 있었으나, **전후 기준
측정이 같은 경로인지**는 아직 `deviceKey` 로만 봅니다
(`expectationFor`). 권고의 「reference 도 전체 입력 신원을 대조한다」를
절반만 한 셈입니다.

### CA-R02 — 증거를 경로 + 격자로 가릅니다

`evidenceKey = storageKey|fs<rate>|n<fft>`. 셋을 고쳤습니다:

1. 증거 열쇠를 넓혔습니다.
2. **잡음 측정이 실패하면 그 경로의 옛 증거를 지웁니다.**
3. 측정 중 가청 판정도 **그 단계의 증거**를 씁니다
   (`st.noiseFloorDb` → `noiseFloorByKey[stepEvidence]`).

**봐 달라**: 「수집 세대/시간」은 넣지 않았습니다. 같은 경로에서 다시
점검하면 덮어쓰므로 낡은 값이 남지는 않는다고 보았는데, **얼마나 오래된
증거까지 써도 되는가**는 정하지 않았습니다. 정책이 필요한 자리인지
판단해 주십시오.

### CA-R03 — 진짜 주소를 나릅니다

`OpenedFormat.routedAddress` 에 `AudioRecord.getRoutedDevice()` 가 알려 준
**접히기 전 주소**를 싣고, 환경이 그것을 먼저 씁니다. 라우팅 통지도
주소가 바뀌면 함께 알립니다.

**열쇠를 갈라 주소로 읽던 fallback 을 뺐습니다** — 내장 열쇠의 마지막
토막은 제품명이라, 그대로 두면 「SM-S918N 자리에서 쟀다」가 됩니다.

**열쇠 자체는 그대로 둡니다**(1번 답). 저장된 보정을 잃지 않으면서 자동
적용만 멈춥니다. **모르면 「같다」가 아니라**, 내장 마이크에서 어느 쪽이든
주소가 비면 자동 적용을 멈추고 「경로 재확인 필요」로 알립니다.

**기기에서 확인했습니다**(SM-S918N + UMC404HD):

```
경로 확인: BuiltIn|SM-S918N addr=bottom
경로 확인: Usb|USB-Audio - UMC404HD 192k|card=1;device=0 addr=card=1;device=0
```

열쇠에는 없는 주소가 실려 옵니다.

**아직 안 한 것**: 1번 답의 **마이그레이션**(버전 있는 route 증거, 과거
경로가 남은 항목만 대응, 반복 실행·중단 복구 시험)은 하지 않았습니다.
지금은 「빈 주소 = 재확인 필요」로 막기만 합니다. 이것이 중간 단계로
받아들일 만한지, 아니면 마이그레이션까지 해야 닫히는지 판단해 주십시오.

### CA-R05 — 열 선언만 자동 확정에 씁니다

`declaresColumns()` 가 머리글이 **열 이름을 선언했는가**를 봅니다 —
여러 칸으로 나뉘고, 칸마다 짧고(≤24자), 주파수 열이 있을 것.

**정규식에 예외를 더하지 않았습니다**(권고). 설명문은 사람에게 보일
단서로는 그대로 쓰되, 기준 CAL 을 **저절로 정하지는** 못합니다.
표시용 곡선은 예전대로입니다.

**봐 달라**: 「칸이 24자를 넘으면 문장」이라는 기준이 임의적입니다.
실제 CAL 파일에 긴 열 이름이 있으면 선언을 놓칩니다(그때는 묻게 되므로
안전한 쪽으로 틀립니다만, 쓰기 번거로워집니다).

## 2. 틀린 동작을 지키고 있던 시험

`CurrentEnvironmentTest` 의 fixture 가 `BuiltIn|SM-S918N|back` 처럼 손으로
적은 열쇠를 썼습니다. **실제 `stableKey` 에는 주소가 없습니다.** 실제와
다른 fixture 라, 「열쇠에서 주소를 뽑는다」는 틀린 동작이 시험으로
보호되고 있었습니다.

지적해 주신 자리입니다. fixture 를 실제 모양으로 바꾸고, 계약도 새로
적었습니다 — 열린 경로 → 목록 → 빈 값(열쇠를 가르지 않음).

**이 부류를 더 찾아봐 달라**: 같은 식으로 **실제와 다른 fixture 가 틀린
동작을 지키고 있는** 자리가 또 있는지. 제가 찾은 것은 이 하나뿐인데,
하나 있었다면 더 있을 것 같습니다.

## 3. 함께 들어간 것 — Phase 10·11 의 순수 계층

**이번 승인 대상이 아닙니다.** 다만 같은 범위에 들어 있어 적습니다.

명세 12·13장의 셈과 형식만 만들었습니다. 화면·캡처 연결은 없습니다.

| 파일 | 무엇 | 시험 |
|---|---|---|
| `SessionMeta.kt` | 기록의 겉장(마이크·보정·설정·요약·사건) | 9 |
| `SessionStore.kt` | 한 세션 = 한 폴더 | 11 |
| `SessionCsv.kt` | 명세 13장의 열 그대로 | 10 |
| `RowSlicer.kt` | 행·epoch 경계 쪼개기 | 10 |

타임라인 형식·행 집계·큐는 녹음 설계 1~4차와 독립 검토를 거쳐 이미
있었으나 **아무 데도 연결되지 않은 상태**였습니다.

정한 것 셋:

- **구간(설교/찬양)은 사건으로 적습니다.** 행마다 구간 바이트를 넣으면
  이미 검증받은 행 형식의 판을 올려야 합니다.
- **겉장을 마지막에 씁니다.** 그것이 「온전하다」는 표시이고, 겉장 없는
  폴더는 목록이 건너뜁니다.
- **CSV 의 `leq` 는 세션 전체 값을 모든 줄에 적습니다.** 행 형식 판 1 에
  시간별 Leq 칸이 없고, 시간가중 값을 평균해도 등가소음도가 되지
  않습니다. 없는 값을 셈해 넣지 않았습니다.

**다음 작업**은 캡처 연결입니다. 행마다 정확한 값을 남기려면 **DSP 에
넣기 전에 오디오를 행 경계에서 쪼개야** 하고(`SplitProcessingTest` 가
등가를 이미 증명해 둔 방식), 그것은 측정 핫패스를 건드립니다. 별도
가지로 내겠습니다.

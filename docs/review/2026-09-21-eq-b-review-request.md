## 2. 무엇을 만들었는가

**프로필 27개** — 신디 5 · 어쿠스틱 기타 2 · 일렉기타 3 · 베이스 3 ·
전자드럼 6 · 리얼드럼 8. 명세 §4 의 세부유형·드럼 파트를 그대로 옮겼습니다.

**값의 유효성을 자료형의 생성자에서 막습니다.** 카탈로그가 커서 눈으로는
놓칩니다.

- `HzRange` — `low < high`, 유한한 양수
- `RatioRange` — 1 이상(1:1 이 무압축)
- `DbRange` — **양수**. 게이트 Range 는 「감쇠량」이고 믹서의 음수 표기와 섞지 않습니다(§18.2)
- `MsRange` — 0 이상, 앞이 뒤보다 작거나 같음
- `FrequencyRegion`/`FilterGuidance`/`DynamicsGuidance` — 설명·조건·부작용이 **비면 만들어지지 않습니다**

**숫자가 없으면 null 입니다.** `0 ms` 나 임의 Threshold 로 채우지
않았습니다(§18.6). 화면은 그 자리에 「사용 안 함」이나 까닭을 적습니다.

**게이트·컴프레서에 threshold 값 자리가 아예 없습니다.** 자료형에
`thresholdProcedureKo`(방법) 뿐입니다. 숫자를 담을 곳이 없으니 실수로
채울 수도 없습니다.

## 3. 기기에서 확인한 것

**Galaxy S23 · 내장 마이크 · `RECORD_AUDIO` 를 회수한 상태.**

- 「분석 → 악기 EQ」 칩으로 들어가 **권한 없이 그대로 열립니다.** 캡처도
  DSP 도 부르지 않습니다(EQ-B 의 종료 조건 「마이크 없이 사용 가능」).
- 게이트 탭이 §18.3 의 어쿠스틱 기타 행과 같은 값을 보여줍니다 —
  `Attack 1~5 ms / Hold 80~150 ms / Release 200~400 ms / Range 6~12 dB /
  Hysteresis 2~6 dB`, 그리고 Threshold 는 **숫자가 아니라 맞추는 방법**.
- 게이트·컴프레서 탭에 측정·RTA·A/B 요소가 없습니다.
- 확인 뒤 **권한은 원래대로 돌려놓았습니다.**

보고 나서 하나 고쳤습니다 — 탭 줄에 이름표가 없어 바로 위의 「세부 유형」과
한 덩어리로 읽혔습니다. 「무엇을 볼까요」를 붙였습니다.

## 4. 시험 15건 — 수치는 **명세 표를 따로 옮겨 적어** 대조합니다

명세 §12.1 이 「기대값을 구현 함수로 다시 만들지 말라」고 해서, §18.3·
§18.4 의 표를 시험 안에 **손으로 다시 옮겨 적고** 카탈로그와 견줍니다.
옮기다 틀리면 거기서 잡힙니다.

| 시험 | 무엇을 단언하는가 |
|---|---|
| 6종 악기가 모두 있다 | §2 의 6종 |
| 세부유형과 드럼 파트가 명세대로 있다 | 27개, 순서까지 |
| stableId 가 겹치지 않는다 | 저장·비교 열쇠 |
| 모든 영역이 값과 문구를 갖는다 | 20Hz~20kHz 안, 빈 문구 없음, 출처가 실재 |
| 모든 필터 안내에 조건과 부작용이 있다 | §15 |
| 6종 전부에 게이트와 컴프레서 안내가 있다 | DYN-01 |
| 쓰지 않는 곳은 bypass 가 분명하다 | §18.7 3 — 패드·전체 키트·심벌 등 8곳 |
| Threshold 는 외부 믹서에서 맞추는 방법으로만 적는다 | §18.7 4 |
| GR 은 실측값이 아니라고 적는다 | §18.7 5 |
| 게이트를 발진 방지 장치로 설명하지 않는다 | §18.3 |
| **게이트 수치가 명세 표와 같다** | §18.3 24행 |
| **컴프레서 수치가 명세 표와 같다** | §18.4 25행 |
| **필터 시작점이 명세와 같다** | §4.1~§4.6 |
| 범위 문자열에 단위가 붙는다 | §18.7 2 (`0.5~2 ms`, `3:1~4:1`, `1k~2.5k Hz`) |
| 카탈로그 판이 붙어 있다 | 스냅샷·프리셋과 견줄 열쇠 |

### 시험 하나를 고쳤습니다

처음에 「`dBFS 를 threshold` 라는 말이 **없어야** 한다」로 적었는데,
그러면 **「앱의 dBFS 를 threshold 로 옮겨 적지 않습니다」라는 경고 문구
자체**가 걸립니다. 금지문과 지시문을 문자열로 가를 수 없어, 단언을
「금지 문장이 **있어야** 한다」와 「GR 미터를 보라는 말이 있어야 한다」로
바꿨습니다. 처음 것은 시험 이름과 단언이 어긋난 경우였습니다.

## 5. 명세와 다르게 한 곳

**카탈로그를 JSON 이 아니라 Kotlin 소스로 두었습니다.** 명세 §11 은
「내장 JSON 카탈로그」입니다. 그렇게 하지 않은 까닭:

- 값의 앞뒤·단위·부호를 **컴파일과 생성자에서** 막을 수 있습니다.
- **파싱 실패라는 상태가 아예 생기지 않습니다.** 내장 자원이 깨질 길이
  없는데 그 오류 경로를 만들고 시험할 까닭이 없습니다.
- 명세 §13 이 「실제 코드 구조와 충돌하면 최소 호환 설계를 ADR 에
  남기라」고 한 자리라고 보았습니다.

나중에 **사용자** 카탈로그를 파일로 받게 되면 같은 자료형으로 읽어
들이면 됩니다. 이 판단이 맞는지 봐 주십시오.

## 6. 스스로 짚은 빈 곳

**1. 크런치에 수치가 없습니다.** 명세 §4.3 은 LPF 를 「하이게인 6~10 kHz,
클린 10~14 kHz」만 주고, §18.3·§18.4 도 클린과 하이게인만 줍니다.
크런치는 **null 로 두고 그 사실을 화면에 적었습니다.** 임의로 중간값을
채우지 않았습니다. 이것이 맞는 처리인지, 아니면 크런치를 세부유형에서
빼는 편이 나은지 판정을 구합니다.

**2. 신디 「기타/복합」의 영역이 하나뿐입니다.** 명세가 「패치에 따라
전대역, 범용 정상 곡선 없음」이라고만 해서 20Hz~20kHz 한 칸으로 두고
역할을 기록하라고 적었습니다. 화면에서 빈약해 보입니다.

**3. 영역의 성격·증상 태그를 제가 나눴습니다.** 명세는 표에서 「주요
영역·성격」과 「문제」를 나란히 적었고, 저는 그것을 겹치는 별도 영역으로
옮겼습니다(예: 피아노 60~200 바디 / 150~500 먹먹함). **명세가 의도한
구조와 다를 수 있습니다.**

**4. `detectorRuleId` 가 전부 null 입니다.** 자동 후보 규칙은 EQ-E 라
아직 잇지 않았습니다.

**5. 음향 검토를 받지 않았습니다.** 명세 §17·§18.8 이 요구하는 음향
담당자 검토는 제 영역이 아닙니다. 저는 **옮겨 적기의 정확성**만
확인했습니다.

**6. 접근성·좁은 화면을 재지 않았습니다.** 큰 글씨 200%, TalkBack,
색각 대체 라벨은 §12.3 항목인데 **실행하지 않았습니다.** 칩에
`contentDescription` 을 붙이고 색 말고 텍스트로도 구분되게 했지만
**실기기에서 확인한 것은 아닙니다.**

**7. 화면 시험이 없습니다.** UI 는 기기에서 눈으로 본 것이 전부이고
Compose 시험은 쓰지 않았습니다.

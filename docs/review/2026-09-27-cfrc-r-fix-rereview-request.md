## 먼저 답합니다 — 두 지적 모두 맞습니다

**CFRC-R01.** 「부호만 어긋남」을 **증명 없이** 넓게 썼습니다. 그 이름은
「나머지는 다 읽을 수 있는 꼴임을 확인했다」는 뜻이어야 하는데, 코드는
「맨 처음 걸린 문제가 부호였다」로 적혀 있었습니다. **괄호나 줄 차례만
바꾸면 판정이 뒤집힌다**는 것이 그 증거이고, 같은 형식 오류가 순서에
따라 다르게 판정되는 것은 그 자체로 규칙이 틀렸다는 뜻입니다.

지난 요청서에서 제가 「`ConflictingSign` 은 사람이 고르면 풀린다」고
적으면서 **그 전제를 검사하지 않았습니다.**

**CFRC-R02.** 더 뼈아픕니다. 시험 이름을 「앱을 다시 켜도 확인이
남는다」로 붙여 놓고, 실제로는 `CurveStore` wrapper 만 새로 만들었습니다.
`by preferencesDataStore` 가 한 JVM 안에서 같은 인스턴스를 돌려준다는
것을 확인하지 않았습니다 — **메모리에 남은 것을 보고 「디스크에서
읽었다」고 적은 셈**입니다.

이 저장소가 「말하지 않은 것을 말한 것처럼 적지 않는다」를 규칙으로
두고 있는데(CLAUDE.md §7), 그것을 **시험 이름으로** 어겼습니다.

## 1. CFRC-R01 — 고친 것

제안하신 세 자리를 그대로 들였습니다.

### ① 여러 선언 — 못 푸는 사유가 이긴다

```kotlin
val bad = found.filterIsInstance<ColumnDeclaration.Unsupported>()
    .firstOrNull { !it.reason.fixableBySign }
```

없으면 `Ambiguous` 로 거절합니다. 지난 요청서에서 「Ambiguous 는 거절
쪽에 두었습니다」라고 적어 놓고 실제로는 부호 충돌이 앞에 오면 우회되던
자리입니다.

### ② 괄호 — 모두 본 뒤에만 부호 충돌을 돌려준다

발견하자마자 돌려주면 **그 뒤의 괄호를 아예 안 봅니다.** 이제 쌓아
두고 단위 검사를 모두 지난 뒤에만 `ConflictingSign` 입니다.

### ③ 낱말 — 정확히 맞아야 한다

`contains` 를 `in` 으로 바꿨습니다. 모르는 말은 아래 단위 검사로
흘려보내 거절되게 둡니다 — **반쯤 알아듣고 넘기는 것보다 모른다고 하는
편이 낫습니다.**

### 막기만 하지 않았습니다

`Response (dB) (correction)` · `Corr (dB) (response)` 는 그대로 고를 수
있습니다. Hz·dB 파일이 맞고 방향만 모르는 것이라, 이것까지 막으면
멀쩡한 파일을 영영 못 씁니다.

## 2. CFRC-R02 — 고친 것

`CurveStore` 가 `DataStore<Preferences>` 를 받습니다(기본값은 앱이 쓰는
그 하나라 제품 호출은 그대로입니다). 시험은 쓰던 scope 를 끊은 뒤
**같은 파일을 새 DataStore 로** 엽니다.

**프로세스를 다시 띄운 것은 아니라고 적었습니다.** 이름도
「디스크에서 다시 읽어도 확인이 남는다」로 좁혔습니다.

### 처음 고친 시험도 주입을 못 박지 못했습니다

`CurveStore` 가 주입을 **무시하고** 공용 delegate 를 쓰도록 되돌려
보았더니 **그대로 통과했습니다** — 같은 JVM 안이라 값이 보이기
때문입니다. 「폴더가 다르면 저장소도 다르다」 쪽도 마찬가지였습니다
(곡선 **파일**은 `filesDir` 로 이미 갈려 있어, 설정이 섞여 있어도
통과합니다).

그래서 **넣어 준 DataStore 를 직접 읽어** 거기에 썼는지를 보게
고쳤습니다.

```kotlin
val raw = written.data.first().asMap().keys.map { it.name }
assertTrue(raw.any { it.startsWith(key.storageKey()) })
```

이제 주입 무시 변이에서 2건이 실패합니다.

## 4. 봐 주셨으면 하는 것

1. **`fixableBySign` 이 이제 정말 그 뜻입니까?** `ConflictingSign` 이
   나오는 길이 한 곳(`declarationIn` 의 마지막)뿐인지, 제가 못 본
   샛길이 있는지 봐 주십시오.
2. **`readingOfWord` 를 정확 일치로 바꾼 파급**을 봐 주십시오. 예전에
   포함으로 통과하던 정상 파일이 이제 거절되는 경우가 있는지 — 기존
   697건은 통과했지만 제조사 표본이 없습니다.
3. **DataStore 주입 경계.** 기본 인자로 열어 두었는데, 제품 코드가 실수로
   두 인스턴스를 만들 길이 생겼는지 봐 주십시오.
4. **다음 작업(저장·리포트)과의 경계.** 담당자 지시로 측정 기록·리포트를
   시작합니다. 리포트에 **잰 조건**(입력 경로·Audio Source·UNPROCESSED
   지원 여부·활성 마이크 조합·마이크 자리·보정 상태·곡선 규약)을 측정값과
   **함께** 적을 계획입니다. 지금 교정 쪽에서 굳힌 것 중 그 기록에 꼭
   들어가야 한다고 보시는 것이 더 있으면 알려 주십시오.

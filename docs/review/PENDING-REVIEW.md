## 0. 이번에 **헛그물로 드러난 셋**

## 1. R3-01·R3-02 — 원본은 겉장까지, 게시는 한 번에

| | |
|---|---|
| PR | #112 |

**설계를 바꿨습니다.** 두 지적이 같은 뿌리라 함께 고쳤습니다.

**R3-01.** 원본은 `timeline-v1.bin` 한 파일이었습니다. 그런데 행에 든
것은 **보정 전 raw 값과 epoch 번호**라, 그 번호를 풀 표가 덮이면
**바이트가 남아도 원래 SPL 을 복원할 수 없습니다.** 지적이 정확했고,
제가 화면과 PR 에 적은 **「처음 잰 값도 그대로 남아 있습니다」가
거짓이었습니다.** 이제 `original/` 에 **겉장과 타임라인을 함께** 남깁니다.

**R3-02.** 이제 **옆(`staging/`)에 다 만들어 검사한 뒤**, 표시 파일
(`staged.ready`) 하나를 만드는 것으로 게시합니다 — **이름 바꾸기 한
번**이라 쪼개지지 않습니다. 읽는 자리마다 먼저 `recover()` 를 부르고,
게시 뒤에 죽었으면 거기서 마저 옮깁니다.

**봐 달라**:
- **표시 파일 한 장으로 충분한가.** 제안하신 「활성 revision 포인터」
  대신 **저널**에 가깝게 갔습니다 — 활성 파일 자리를 그대로 두어
  읽는 쪽(화면·CSV·PDF)을 하나도 안 고쳤습니다. 그 맞바꿈이 맞는지.
- **반쪽만 놓였을 때 치우는 것**이 맞는지(남겨 두면 열 때마다 되풀이).
- **옮기다 실패했을 때는 남겨 둡니다** — 온전한 판이라 다음에 마저
  옮길 여지가 있다고 보았습니다(저장공간이 찼다 비워지는 경우).

**안 한 것**: 동시 reader·삭제·내보내기와의 경쟁 정책은 **정하지
않았습니다.** 지금은 한 번에 하나만 도는 화면이라 미뤘습니다.

## 2. R3-03 — 다른 마이크의 보정을 걸지 않는다

| | |
|---|---|
| PR | #112 |

기록의 입력과 **지금 열린 입력**이 같은지 보고, 다르거나 **모르면
막습니다**(열린 것이 없다 · 경로 미확인 · 옛 기록이라 신원 없음).
판단은 화면 밖 순수 함수(`ReanalysisIdentity`)로 뺐습니다.

**봐 달라**: **막는 것이 맞는지, 「참고용으로 제한」이 나은지.**
지금은 막고 **무엇을 하라고** 적습니다(「측정을 시작해 이 기록을
담았던 마이크를 연 뒤에」). 권고에는 둘 다 있었습니다.

**약한 곳**: 보정의 **소유자 열쇠를 직접 견주지 않습니다.** 「지금 걸린
보정 = 지금 열린 입력의 것」이라는 성질에 기대어, **기록과 지금 열린
입력**을 견줍니다. 저장된 프로파일의 키를 직접 조회하는 쪽이 더 곧지만
그러려면 `CaptureSource` 를 겉장에서 복원해야 합니다.

## 3. R3-04 — 겉장이 셈을 말하게 했다 · **그리고 기대값 하나를 바꿨습니다**

| | |
|---|---|
| PR | #112 |

미보정으로 다시 셈했는데 옛 「전대역 보정」이 남아 **미보정 경고가
통째로 사라졌고**, 분석 가중은 겉장에 옛 값을 남기면서 **엔진은 기본값
Z 로** 돌았습니다. 셋 다 셈을 따라가게 했습니다.

### 그 실 끝을 따라가다 **라이브에서도 같은 거짓**을 찾았습니다

기록의 peak 는 `SplFrame.blockPeakDbfs` 이고, **그 값은 A·C·Z 가 모두
같습니다.** 재서 확인했습니다:

```
100Hz 순음 (A 와 C 가 19dB 갈리는 자리)
  blockPeak   A=-10.4576  C=-10.4576  Z=-10.4576   ← 같다
```

`SplEngine` 도 「Peak 는 가중 전에 잰다」고 적어 두었습니다. 그런데
겉장에는 **화면 설정값(기본 C)**을 적고 있었습니다 — 재분석뿐 아니라
**라이브 기록도** 그랬습니다.

### 그래서 검토자 단언을 바꿨습니다 — **여기를 봐 주십시오**

`peakWeightMetadataMustFollowReanalysis` 의 원래 단언은
`assertEquals(Weighting.C, peakWeighting)` 였습니다. **지적은 맞습니다**
(옛 A 가 그대로 남아 있었다). 다만 위 측정대로 **따라갈 대상이 C 가
아닙니다.** 「라벨이 셈을 따라가야 한다」는 뜻은 그대로 지키고 **Z**
(안 걸림)로 바꿨고, 까닭을 시험 KDoc 에 적었습니다.

**제 판단이 틀렸다면 여기서 짚어 주십시오.** 대안은 **기록기가 peak
가중을 실제로 걸게** 하는 것인데, 그러면 저장되는 숫자가 바뀌고
화면(`weightedPeakDbfs`)과 기록이 비로소 같아집니다. 그쪽이 맞는
방향인지 판단을 구합니다.

## 4. 남겨 둔 원본을 **꺼낼 수 있게** 했습니다 (새 기능)

| | |
|---|---|
| PR | #113 |

R3-01 을 고치고 보니 **원본을 남겨 두고도 꺼낼 길이 없었습니다.**
화면은 「처음 잰 값은 그대로 남습니다」라고 말하는데 **확인할 수단이
없으면** 그 약속은 지켜졌는지 알 수 없는 말입니다.

「처음 잰 값으로 되돌리기」를 넣었습니다. **게시하는 길은 다시 분석과
같은 함수**라, R3-02 의 성질이 그대로 따라옵니다.

**봐 달라**: 되돌리기에 **보정 소유권 검사를 걸지 않았습니다**(R3-03).
새 잣대를 거는 일이 아니라 **그때 잰 것을 그대로 꺼내는 일**이라고
보았는데, 그 구분이 맞는지.

| | |

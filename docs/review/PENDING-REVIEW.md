> **왜 이 문서가 있는가**
>
> 검토를 **한 번에 몰아서** 보낸다(크레딧 절약, 담당자 지시). 그러면 보내는

> 쌓인다. 이 저장소가 CHANGELOG 로 이미 한 번 데인 자리와 같다. 그래서
> **끝날 때마다 여기에 한 항목씩** 쌓는다.
>
> 검토를 받으면 **지우지 말고** 맨 아래로 옮기고 회차와 판정을 적는다.

## 1. R4-01·R4-02 — 복구 실패를 드러내고, 한 판으로 읽는다 (**다 닫지는 못했습니다**)

| | |
|---|---|
| PR | #115 |

**R4-01.** `recover()` 가 실패를 삼키고 있었습니다. 이제 **던집니다.**
표시 파일은 **남겨 두되**(온전한 판이라 저장공간이 비워지면 마저 옮길
여지가 있습니다) **그때까지 읽지 못하게** 막습니다.

**R4-02.** 목록도 먼저 복구하고(실패한 기록만 「못 읽음」으로 셈),
**겉장과 행을 한 번에** 읽는 `readSnapshot` 을 두었습니다. 기록을 열
때와 CSV 를 낼 때 **목록이 준 겉장을 그대로 쓰지 않습니다.**

### **권고와 다르게 갔습니다 — 여기를 봐 주십시오**

권고는 **「불변 revision + 원자적 활성 포인터」** 또는 **「저널을 유지하면
완료까지 모든 reader/writer 를 같은 세션 잠금으로 통제」** 였습니다.

저는 **저널을 유지하되 잠금은 안 걸었습니다.**

**얻은 것**: 활성 파일 자리를 그대로 두어 **읽는 쪽(화면·CSV·PDF)을
하나도 안 고쳤습니다.** 고치는 곳이 많을수록 하나를 빠뜨려 「어떤
화면만 옛 숫자」가 됩니다.

**못 닫은 것**: **읽는 도중에 다른 곳에서 게시가 일어나면 여전히
갈립니다.** 지금 막은 것은 **재시작 뒤의 어긋남**뿐입니다. 코드 주석에도
그렇게 적었습니다.

**봐 달라**: 이 맞바꿈이 받아들일 만한지. 아니라면 **잠금을 어디에
걸어야 하는지**(세션 단위 `withSnapshot` 인지, 저장소 전체인지)
짚어 주시면 그대로 하겠습니다.

**안 한 것**: 재분석 중 **삭제·메모·내보내기를 막지 않습니다.**
전원 손실과 프로세스 종료의 **내구성 계약 구분·fsync 설계**도 안 했습니다.

## 2. R4-03 — 입력 경로까지 본다

보정의 주인이 **기기 + 입력 경로 + 채널**인데 검사는 **기기와 채널만**
봤습니다. 이제 경로도 보고, **어느 한쪽이라도 안 적혀 있으면 막습니다.**

**약한 곳은 그대로입니다**: 저장된 프로파일의 **실제 키를 직접 조회하지
않습니다.** 「지금 걸린 보정 = 지금 열린 입력의 것」이라는 성질에
기대어 **기록과 지금 열린 입력**을 견줍니다. 권고하신 「저장 키와 현재
적용 키를 직접 비교」까지는 안 갔습니다 — `CaptureSource` 는 겉장에
있지만 **경로 주소·활성 마이크 조합**은 복원할 길을 아직 못 찾았습니다.

## 3. R4-04 — 곡선의 이름과 확인 근거가 따라간다

이름·읽는 법·확인 여부·보정 출처를 **새 설정에서 가져옵니다.**
**곡선을 끄면 흔적도 함께 지웁니다.** 미보정이면 출처를 안 적습니다
(라이브와 같은 규칙).

## 4. R4-05 — **또 확인하지 않고 적었습니다**

지난 회차에 단정을 낮추면서 대신 「앱의 테스트 신호로 하면 커플링도
배경 소음도 없다」고 적었는데 **틀렸습니다.** 그 기능은 `AudioTrack` 으로
**스피커에 내보냅니다.**

**디지털로 만든 소리라는 것과 디지털로 되돌아온다는 것은 다른 말**인데,
코드를 안 보고 적었습니다. **두 회차 연속으로 문서에서 틀렸습니다.**

그 문장을 걷어내고, 앱·DSP 만 가리는 일은 **소리를 내지 않고** 한다고
적었습니다 — 이미 있는 JVM 시험이 그 자리이고 **현장에서 할 일이
아닙니다.**

## 5. 검토 밖에서 찾은 것 — 「흐리게 그립니다」가 거짓이었다

| | |
|---|---|
| PR | #116 |

분석 화면은 **「○○Hz 아래 밴드는 흐리게 그립니다」**라고 적고
`BandMeter` 머리말도 그렇게 적혀 있었는데, **실제로는 안 흐렸습니다.**
주석이 참조하던 `UNRESOLVED_ALPHA` 는 **아예 없는 상수**였습니다.

기기에서 **픽셀로** 확인했습니다:

```
밴드 6  (못 가름)    = (0.310, 0.765, 0.969)
밴드 12·20·30 (가름) = (0.310, 0.765, 0.969)   ← 같은 색
```

**44.1kHz 에서는 맨 위 20kHz 대역도 여기 듭니다** — 위 경계 22,387Hz 가
나이퀴스트 22,050Hz 를 넘습니다. **내장 마이크도 USB 인터페이스도 44.1 을
지원한다고 알려 옵니다.**

**시험이 두 번 엉뚱한 이유로 통과했습니다.** `폭/31` 로 자리를 어림해
**빈틈을 집었고**, 다음에는 바탕색 기준이 틀려 **31개가 하나로** 잡혔습니다.
기하에 기대지 말고 **색의 가짓수**를 묻도록 바꿨습니다.

**봐 달라**: 흐림 값(0.35)이 적당한지. 그리고 **색을 안 바꾸고 흐림만**
얹은 선택(하울링 후보 색과 안 섞이게)이 맞는지.

## 6. USB 인터페이스를 꽂고 찾은 셋 (검토 밖)

| | |
|---|---|
| PR | #118 · #119 · #120 |

담당자가 **Behringer UMC404HD** 를 폰에 꽂아 주어 **처음으로 실기기에서
USB 경로를 확인**했습니다. 보이는 것은 좋았는데 **셋이 걸렸습니다.**

### 6-1. 가공 없는 경로를 **안 써 보고 포기**하고 있었다 (#118)

`PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED` **하나로** 갈랐습니다. 그
값은 **이 폰의 내장 경로**에 대한 답인데, 소리가 **USB 인터페이스에서
오는** 경우까지 그것으로 막아 **시도조차 안 했습니다.**

```
기기 속성 SUPPORT_AUDIO_SOURCE_UNPROCESSED=false
source=9(UNPROCESSED) 상태=3 읽음=81920 실제기기=USB-Audio - UMC404HD 192k
```

**열립니다.** 그래서 USB 면 폰 속성과 무관하게 시도하게 했고, 고친 뒤
`열린 경로=Unprocessed` 를 확인했습니다.

**봐 달라**: 「열린다」를 「가공이 없다」로 읽지 않도록 적어 두었는데
(그 판단은 마법사 2단계가 합니다), 그 선 긋기가 맞는지.

### 6-2. **무음을 「깨끗하다」로** 읽고 있었다 (#119) ← **여기를 가장 봐 주십시오**

DSP 점검이 **완전한 디지털 무음**을 받고 **「변하는 처리를 찾지
못했다」로 통과**했습니다.

```
입력 RMS=-240.0dBFS PEAK=-240.0dBFS 표본=266240
판정=NoTimeVaryingFound 전대역 흔들림=0.0 모양 흔들림=0.0
```

**무음은 앞창도 뒤창도 바닥값이라 흔들림이 정확히 0** 입니다 — **가장
깨끗한 측정처럼 보입니다.** 아무것도 안 들어온 것을 「깨끗하다」로 읽으면
그 위에서 만든 교정 프로파일이 **아무 근거 없이 「검증됨」**이 됩니다.
**R2-01(저장은 성공인데 자료가 없다)과 같은 성질**입니다.

`Silent` 로 가르고 마법사가 막습니다. 「짧다」(`NotEnoughData`)와 따로
둔 까닭은 **사람이 할 일이 다르기** 때문입니다.

**봐 달라**: 문턱(`-120dBFS`)과, **「짧다」와 가른 것**이 맞는지.

### 6-3. 소리를 틀면 **자기 입력을 죽이고** 있었다 (#120)

```
앱 그대로     → 실제 출력=UMC404HD, 입력 RMS=-240.0dBFS  (죽음)
폰 스피커로   → 실제 출력=SM-S918N,  입력 RMS= -67.8dBFS  (삶)
```

안드로이드가 인터페이스를 꽂으면 **출력도 그쪽으로** 보내는데, **같은
USB 카드로 동시에 넣고 빼면** 입력이 무음이 됩니다. **재는 쪽이 USB 일
때만** 출력을 폰 스피커로 돌리게 했습니다.

**봐 달라**: **기기 하나로 본 것**이라 「USB 면 무조건 폰 스피커」가 맞는
기본값인지 모릅니다. 그리고 **PA 로 신호를 넣으며 USB 마이크로 재려던**
쓰임은 이제 뜻이 달라집니다 — 그 맞바꿈이 맞는지.

**모르는 것**: **왜 그런지** 모릅니다. 안드로이드 쪽인지 기기 쪽인지
가리지 않았습니다.

### 이 셋을 찾은 방식

**0.0 이 너무 깨끗해서** 의심한 것이 시작이었습니다. 되풀이 장인 줄 알고
장 번호로 걸렀고(279→127), **그래도 0.0 이라** 입력 레벨을 쟀더니 무음

## 11. R6-01 — 두 창을 같은 표본 번호에서 끝나게 뜬다 (6회차 뒤)

6회차 회신(`inbox/2026-10-02-round6-independent-review.md`)의 High 둘 중
**R6-01 만** 닫았습니다. R6-02~05 는 아직입니다.

| 회신이 요구한 것 | 어떻게 |
|---|---|
| 창과 함께 **sample index·epoch** 를 한 잠금에서 | 두 스트림을 각자 0 부터 센 번호로 놓고, **덜 들어온 쪽의 개수**(`windowEnd`)에서 **둘 다** 끝나게 뜹니다. `windowEnd`·`epoch` 를 `TransferMeasurement` 에 싣습니다. `reset()` 마다 epoch 가 바뀝니다 |
| 배열 안 lag 와 **보고할 지연을 분리** | 분리하지 않고 **창 자체를 같은 번호로 맞췄습니다** — 그러면 배열 안 lag 가 곧 번호 좌표의 지연입니다. `rawLag − (Nref − Nmeas)` 식은 쓰지 않았습니다 |
| 두 count 를 별도 getter 로 나중에 읽지 않기 | 번호는 `measure()` 의 잠금 안에서 고리 복사와 함께 정합니다 |
| 교차 콜백 순서 · 다른 chunk 크기 | 시험: 기준 먼저 / 측정 먼저 / 크기가 다른 조각을 번갈아 넣으며 **매 조각마다** 잼(양쪽이 앞선 순간을 다 지났는지도 단언) |
| 음수 상대 lag | 시험: 지연을 **지어내지 않고** 못 찾음. 고친 뒤 처음부터 통과했습니다 — 기존 동작을 못박은 것이지 RED 를 본 것은 아닙니다 |
| 정지/재시작 | `epoch` 로 가릅니다. 진행 중 측정과 `reset()` 이 겹치면 **고리를 reset 보다 먼저 뜬 측정은 옛 epoch, 아직 안 뜬 측정은 새 epoch** 로 나옵니다. reset 은 진행 중 계산을 취소하지 않습니다 — 버리는 것은 받는 쪽 몫입니다. *(7회차 R7-02 로 고침 — 처음에는 「그 측정은 옛 epoch 로 나온다」고 넓게 적었습니다. 두 순서 모두 시험으로 편입했습니다)* |
| 프레임 누락 | **이 클래스는 알아챌 수 없습니다.** 번호는 「들어온 개수」라 누락이 있으면 그 뒤가 통째로 어긋납니다. 들여보내는 쪽이 세어야 한다고 KDoc 에 적었습니다 |
| 비동시 시작 | **닫지 않았습니다.** 지연은 이제 **표본 번호 좌표의 지연**이라 두 스트림의 시작 시각 차이가 섞여 있습니다 — 음향 지연이 아닙니다. 같은 epoch 안에서는 상수라 **변화**는 볼 수 있습니다 |

**한쪽이 고리 여유보다 앞서면 재지 않습니다**(`null`) — 그 번호의 창은 이미
덮어써졌습니다. 여유는 **방향마다 다릅니다** — 기본값에서 기준이 앞설 때 37,440표본(0.78초), 측정이 앞설 때 61,440표본(1.28초). *(7회차 R7-01 로 고침 — 처음에는 양쪽 다 0.78초인 것처럼 적었습니다. 양방향 경계와 회복을 시험으로 편입했습니다)*

**대가**: 측정도 `span + maxLagSamples` 만큼 쌓여야 첫 측정이 나옵니다.

**검증**: 변이 둘(되돌리기 제거 → 2건 실패, 여유 검사 제거 → 1건 실패),
전체 `--rerun-tasks` app 1,146 + dsp 715 통과, 검토자 독립 시험의
`R6_CHUNK` 통과(`between=300`). `R6_DRIFT`·`R6_DC` 는 그대로 실패합니다.

### 봐 주셨으면 하는 것

1. **보고할 지연을 따로 두지 않고 창을 맞춘 것**이 권고의 뜻에 맞는지.
2. 「표본 번호 좌표의 지연」이라는 계약으로 **저녁 음향 드리프트 기록**에
   쓸 수 있는지 — `windowEnd` 를 시간축으로, `epoch` 가 바뀌면 구간을 끊습니다.
3. 여유를 넘을 때 `null` 이라 「자료 부족」과 **구별이 안 됩니다.** 따로
   알려야 하는지.

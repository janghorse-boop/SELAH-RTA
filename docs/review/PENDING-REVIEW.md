## 1. PND-03 — 10초 평균을 실제로 10초로 (단계 A·B)

| | |
|---|---|
| 설계 | [`../superpowers/specs/2026-09-30-rta-coverage-tap-design.md`](../superpowers/specs/2026-09-30-rta-coverage-tap-design.md) |
| PR | #95(설계) · #96(단계 A) · #97(단계 B) |

**무엇이 잘못됐었나**: 저장되던 「10초 평균」은 10초치 소리의 평균이
아니었습니다. ① 화면용으로 **평활된 값**을 다시 평균했고, ② 화면은 66ms 에
한 번만 받으므로 **분석한 장의 3분의 1 이상이 안 들어왔습니다**(실기기에서
초당 23.5장 중 15장 남짓).

**한 일**: 평활 **바로 앞**에 sink 를 달고, **겹친 창을 이중으로 세지 않는**
누적기를 붙였습니다(창들이 덮은 입력 구간의 **합집합**). 단계 A 는 적기만,
단계 B 에서 평균을 그 값으로 바꾸고 `averageVersion` 을 올렸습니다.

**봐 달라**:
- **창 경계 규칙** — 측정 시작·끝에 걸친 창을 넣을지 뺄지. 지금은 **켠 뒤
  첫 창을 0 으로** 삼고 10초를 넘는 꼬리는 자릅니다.
- **「못 받으면 저장 안 함」이 맞는 선택인지.** 옛 길로 돌아가면 같은 이름을
  단 두 값이 섞입니다. 대신 **분석이 안 도는 상황에서는 아무것도 안
  남습니다.**
- `averageVersion` 으로 옛·새 기록을 가르는 방향.

**제가 틀렸던 것**: 「옛 길은 짧고 큰 소리를 **작게** 적는다」고 적었는데
**반대로 나왔습니다**(옛 길이 0.28dB 더 큼). 실제 성질은 **「같은 소리에
같은 답을 못 준다」** 입니다 — 자리만 옮겨도 값이 달라집니다.

**확인 못 한 것**: **문턱값**(단계 D). 기기 여럿에서 정상 측정의 coverage
분포를 먼저 재야 합니다. 지금은 **적기만 하고 판정에 안 씁니다.**

## 2. PND-01·02 — 완료 경계와 「무슨 소리로 쟀나」 (High 둘)

| | |
|---|---|
| PR | #93 |

- **PND-01**: 틱이 먼저 「끝났다」로 바꾸면 `cancel()` 이 **아무 일도 하지
  않아**, 완료 경계에서 바뀐 조건이 **알아채고도 저장**됐습니다. 이제
  **저장 직전에 다시 보고 저장 함수를 아예 부르지 않습니다.**
- **PND-02**: 순음 주파수가 조건에 없어 **1kHz 와 2kHz 가 한 곡선에**
  섞였습니다(retune 이라 재생 세대가 그대로). `signalSpec` 을 넣고, **대역
  폭은 숫자 대신 규칙의 이름**으로 적습니다.

**봐 달라**: 저장 직전 검사의 자리가 맞는지(출력 확인은 기다리는 일이라 그
뒤에 다시 봅니다). 견주는 쪽에 **자극 종류**를 더한 것.

**제 시험이 처음 헛그물이었습니다** — 「조건 바꾸고 마지막 장」으로는 경계가
안 만들어졌습니다(틱이 먼저 정상 취소). **고침을 꺼도 통과**해서 알았습니다.

## 6. 곁다리로 고친 것 둘

- **보던 화면을 잃는 문제.** `SelahApp` 의 구역·칩이 `remember` 라 화면이
  다시 만들어지면 **측정 탭으로 돌아갔습니다**(PR #86). 「활동 유지 안 함」
  으로 둘 다 확인했습니다. **까닭을 처음에 잘못 짚었고**(권한 대화상자
  때문인 줄), 실은 **제 시험 좌표가 낡았던 것**입니다.
- **검토자 시험 하나의 전제가 바뀌었습니다.**
  `RtaStoreVmIndependentTest.stableCaptureControlPersistsViaFreshStore` 는
  합성 장을 밀어 넣어 **저장까지 가는 것**을 대조군으로 삼았는데, 단계 B
  뒤로는 **분석이 안 돌면 저장할 값이 없어** 그 전제가 깨집니다. 고쳐 적고
  까닭을 KDoc 에 남겼습니다. **실제로 재서 저장되는 대조군은
  `RtaCoverageRecordedTest`** 가 맡습니다.

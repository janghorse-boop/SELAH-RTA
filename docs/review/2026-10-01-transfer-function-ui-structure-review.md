# Transfer Function UI 구조 검토 — 보고

지시서: [`SELAH_RTA_기능_복잡도_및_TF_UI_구조_검토지시서`](#) (2026-10-01 접수)
고정본: `main` 의 `607ddba` · **구현은 하지 않았습니다**(지시서 §20)

**결론 먼저: 네비게이션을 바꾸지 않고, 분석 탭 안에 「문 하나」를 더 다는
쪽을 추천합니다(안 2).** 그 패턴은 이 앱에 **이미 있고 검증돼 있습니다** —
교정 마법사가 그렇게 동작합니다.

## 1. 현재 앱 구조 (코드로 확인한 것)

```
측정   SPL                                   ← 칩 1개라 칩 줄이 아예 안 보임 · 세로 고정
분석   RTA · Spectrum · Spectrogram · FR     ← 칩 줄을 안 쓴다(아래) · 가로 고정
도구   테스트 신호 · 악기 EQ                   ← 칩 2개 · 세로 고정
기록   기록                                   ← 세로 고정
설정   설정                                   ← 세로 고정
```

출처: `ui/nav/Navigation.kt` 의 `NavSection`(174줄) · `ViewMode`(11줄).

**지시서가 모르고 있는 사실 셋**(모두 담당자 본인의 지시로 정해진 것):

| | 사실 | 언제 |
|---|---|---|
| **아래 탭은 아이콘만** 쓴다. 글자가 없다 | 「메인메뉴는 측정·분석·도구·설정 텍스트를 삭제해 달라」 | 2026-09-26 |
| **분석은 가로 고정**이다 | 「31밴드는 가로로 늘어선 그림이라 세로에서는 막대가 실오라기처럼 보인다」 | 2026-09-25 |
| **기록은 칩이 아니라 아래 탭**이다 | 칩으로 올렸다가 **되돌린** 것이다 — 기록이 실제로 쌓이고, SPL 칩이 늘 켜진 채 자리만 차지했다 | 2026-09-26 |

**분석 탭은 위 칩 줄을 쓰지 않습니다.** `hasOwnModeSwitch` 가 분석에만
`true` 이고(225줄), 모드 고르개는 **차트 안**에 그립니다 — 「RTA 창안에
RTA, FR 버튼은 없애주고 박스안에 작게」(2026-09-25 지시).

그 고르개(`AnalyzeScreens.kt` 의 `AnalyzeModes`, 1001줄)는 **평범한 `Row`**
입니다. 줄바꿈도 가로 스크롤도 없고 `softWrap = false` 입니다. **넘치면
그냥 잘립니다.**

**복잡한 흐름을 문 뒤에 두는 패턴이 이미 있습니다**: 교정 마법사와 프로파일
관리가 `SelahApp.kt` 에서 `rememberSaveable` 플래그 + `BackHandler` + `닫기`
로 열리고 닫힙니다(635·753줄). **새로 발명할 것이 없습니다.**

## 2. 복잡도가 증가할 가능성이 높은 부분

| 자리 | 무엇이 문제인가 |
|---|---|
| **분석의 차트 안 고르개** | 지금 넷입니다. 「Transfer Function」은 **「Spectrogram」보다 훨씬 긴 이름**이라 다섯째로 넣으면 좁은 화면에서 잘립니다. **오늘 이 고르개가 실제로 깨진 일이 있었습니다**(Spectrum·Spectrogram 이 사라졌던 것) |
| **아래 탭** | 다섯 개가 **아이콘만**으로 구별됩니다. 여섯째를 더하면 아이콘만으로 가르기가 급격히 어려워집니다 |
| **설정 화면** | 지금도 1,325줄입니다. 그런데 이 화면은 **계속 덜어내 온 역사**가 있습니다 — 내장 마이크 탐색 카드, 「외부 기기 자동 사용」, 「기기가 빠졌을 때」가 모두 **지시로 빠졌습니다**. 여기에 FFT·Averaging·Window·Phase View·Drift 를 더하면 그 흐름을 거스릅니다 |
| **측정 화면** | 1,534줄로 이미 가장 큽니다. TF 를 여기 붙이면 안 됩니다(지시서 §4 와 같은 판단) |

## 3. 유지해야 할 현재 UX

- **아래 탭 다섯, 아이콘만.** 건드리지 않습니다.
- **분석 = 가로 / 나머지 = 세로.** TF 는 분석에 들어가므로 **가로**입니다.
  지시서 §5·§6 의 화면 예시는 세로형 목록인데, **실제로는 가로로 그려야
  합니다.** 아래 5~7장은 가로를 전제로 다시 그렸습니다.
- **모드 고르개는 차트 안에.** 분석의 성격입니다.
- **설정은 「값을 바꿔 두는 곳」, 도구는 「하는 곳」**이라는 구분
  (`ToolsScreen.kt` 머리말). TF 는 **보는 곳**이라 분석이 맞습니다.

## 4. Transfer Function 권장 위치 — 세 안을 견줌

### 안 1 — 분석의 **다섯째 모드**로 넣는다

`AnalyzeModes` 에 `TransferFunction` 을 더합니다.

- ✅ 코드 변경이 가장 적다
- ❌ **고르개가 잘린다**(2장). FlowRow 나 스크롤로 바꿔야 하는데, 그러면
  차트 머리가 두 줄이 되어 가로 화면에서 차트가 줄어든다
- ❌ **성격이 섞인다.** 나머지 넷은 「지금 들어오는 소리를 어떻게 그릴까」
  이고, TF 는 **「기준과 견주어 시스템을 잰다」**다. 연결·채널·지연을 먼저
  정해야 시작되는 **측정 모드**지 그리기 방식이 아니다
- ❌ 지시서 §5(진입 화면에서 간편/정밀을 먼저 고른다)를 둘 곳이 없다

### 안 2 — 분석 안에 **문 하나**를 단다 ← **추천**

분석 화면에 「Transfer Function」 한 줄을 차트 **밖**에 둡니다. 누르면
교정 마법사와 **똑같은 방식으로** TF 화면이 덮습니다.

```
분석 (가로)
├─ 차트: RTA · Spectrum · Spectrogram · FR     ← 그대로, 손대지 않음
└─ [ Transfer Function ▸ ]                      ← 한 줄 추가

        ↓ 누르면

Transfer Function (가로, 덮는 화면)
├─ 진입: [간편 측정] [정밀 측정] [여러 위치 비교]
├─ 간편 → Magnitude · 지연 · 측정 신뢰도 → [상세 분석]
├─ 정밀 → 상태 줄 + 그래프 하나 크게
└─ 뒤로가기 / 닫기 → 분석으로 복귀
```

- ✅ **아래 탭을 건드리지 않는다**(아이콘 추가 0, 재배치 0)
- ✅ **차트 고르개를 건드리지 않는다**
- ✅ **패턴이 이미 검증돼 있다** — 교정 마법사·프로파일 관리와 같은 구조
- ✅ 지시서 §4·§5·§12 를 모두 만족한다
- ✅ 되돌리기 쉽다 — 한 줄과 한 화면이다
- ❌ 분석 화면에 요소가 하나 는다(한 줄)

### 안 3 — 지시서 §3 대로 **네 탭으로 재편**

- ✅ 「기본 vs 고급」 경계가 **탭 수준에서** 드러난다
- ❌ **위 1장의 결정 셋을 모두 뒤집는다** — RTA 가 세로로 가고, 기록이
  칩으로 돌아가고, 「가이드」 아이콘을 새로 만들어야 한다
- ❌ **테스트 신호와 FR 의 자리가 제안에 없다.** 테스트 신호는 TF 를 쓰려면
  **반드시 있어야 하는 기능**이다
- ❌ 큰 변경이고 되돌리기 어렵다

### 추천과 까닭

**안 2 입니다.**

지시서의 진짜 목적은 **「기본 화면을 단순하게 유지하는 것」**(§1·§24)이지
**「탭을 재배치하는 것」**이 아닙니다. 안 2 는 그 목적을 **네비게이션 변경
0** 으로 달성합니다. 안 3 이 주는 추가 이득(탭 수준의 경계)은 **나중에도
할 수 있고**, 안 2 가 그 길을 막지 않습니다.

> **고려했다가 뺀 것**: TF 를 **도구**에 두는 안. TF 간편 모드는 소리를
> 내보내므로 「하는 곳」에 맞는 면이 있습니다. 그러나 사람이 몇 분씩
> 들여다보는 것은 **그래프**이고, 정밀 모드는 소리를 아예 안 냅니다.
> 분석이 맞습니다.

## 5. 간편 모드 기본 화면 제안 — **가로**입니다

지시서 §6 의 예시는 세로 목록인데, 분석이 가로 고정이라 이렇게 됩니다.

```
┌───────────────────────────────────────────────────────────┐
│ ‹ Transfer Function · 간편                    [고급] [저장] │
│ 내장 마이크(하단)  ▸  USB-C · ADAM D3V                     │
├────────────────┬──────────────────────────────────────────┤
│  지연           │                                          │
│  23.4 ms        │                                          │
│                 │            Magnitude                     │
│  측정 신뢰도     │                                          │
│  ● 좋음         │                                          │
│                 │                                          │
│  [상세 분석 ▸]   │   평균: 표준 ⌄        20Hz ─── 20kHz     │
└────────────────┴──────────────────────────────────────────┘
```

**가로가 오히려 유리합니다** — 숫자(지연·신뢰도)를 왼쪽에 세로로 쌓고
그래프를 오른쪽에 넓게 줄 수 있습니다. 세로였다면 그래프가 납작해집니다.

### 「측정 신뢰도」에 **제3의 상태**가 필요합니다

지시서 §6 의 `Coherence → 측정 신뢰도` 변환은 좋은 방향입니다. 다만
**명세 검토에서 지적한 것과 이어집니다** —
[`2026-10-01-transfer-function-spec-rereview-request.md`](2026-10-01-transfer-function-spec-rereview-request.md)
1장: **평균이 8회 미만이면 coherence 는 수식상 항상 1.00** 입니다.

그 상태를 「좋음」으로 바꿔 보이면 **거짓말이 한 겹 더 두꺼워집니다.**

```
● 좋음        평균이 충분하고 coherence 가 높다
● 보통
● 낮음        반사·소음·간섭
○ 측정 중     ← 아직 평균이 안 찼다. 「좋음」이 아니다
```

## 6. 간편 모드 상세 화면 제안

`[상세 분석]` 을 누르면 같은 화면에서 **그래프만 바뀝니다**(화면을 또
덮지 않습니다 — 문을 두 겹 두면 돌아오는 길이 길어집니다).

```
[Magnitude] [Coherence] [Phase]        ← 한 번에 하나를 크게
왼쪽 숫자 칸: 지연 · 신뢰도 · 클럭 드리프트 · 떨어진 블록
```

**Phase 에는 「뺀 지연」을 함께 적습니다** — 명세 검토 보완 3. 지연 추정이
0.1 ms 달라지면 10 kHz 위상이 한 바퀴 돕니다. 그 값이 안 보이면 사람은
시스템이 변한 것인지 추정이 변한 것인지 가릴 수 없습니다.

## 7. 정밀 모드 화면 제안

```
┌───────────────────────────────────────────────────────────┐
│ ‹ Transfer Function · 정밀                    [고급] [저장] │
│ UMC404HD │ 기준 CH1 │ 측정 CH2 · EMM-6 │ 클럭 공유 │ 12.8ms│
├───────────────────────────────────────────────────────────┤
│                                                            │
│                      Magnitude                             │
│                                                            │
│  [Magnitude] [Coherence] [Phase]      평균: 표준 ⌄          │
└───────────────────────────────────────────────────────────┘
```

**상태를 한 줄로 눌러 담고 그래프에 자리를 다 줍니다**(지시서 §8 과 같은
판단). 간편과 **같은 뼈대**를 씁니다 — 머리 두 줄, 그래프 하나, 아래 전환.
그래야 두 모드를 오갈 때 다시 배우지 않습니다.

## 8. Multi-Point 위치 제안

**TF 진입 화면에서 갈립니다**(지시서 §13 과 같음).

```
[간편 측정]  [정밀 측정]  [여러 위치 비교]
```

「여러 위치 비교」는 **측정 방식이 아니라 쓰임**이라 세 번째 자리에 둡니다.
결과 화면은 **대표 곡선 하나**로 시작하고, 각 위치별 곡선·Median·Envelope
는 `[각 위치 보기]` 버튼 뒤에 둡니다.

**위상 공간 평균은 넣지 않습니다** — 위치마다 지연이 달라 평균하면 뜻이
사라집니다(명세 검토 보완 6).

## 9. 설정 화면 영향 — **설정 탭에 넣지 않기를 권합니다**

지시서 §10 은 설정 탭 아래에 「Transfer Function 고급 설정」 하위 메뉴를
두자고 합니다. **한 걸음 더 가서, 설정 탭을 아예 건드리지 않기를 권합니다.**

까닭은 둘입니다.

1. **이 앱의 설정은 계속 덜어내 온 화면입니다.** 탐색 카드·자동 사용·빠졌을
   때 설정이 모두 지시로 빠졌습니다. 거스를 이유가 없습니다.
2. **TF 설정은 TF 를 쓰는 동안에만 뜻이 있습니다.** 설정 탭에 두면 TF 를
   한 번도 안 쓰는 사람도 그 항목을 보게 됩니다 — 지시서 §23 이 막으려는
   바로 그것입니다.

TF 화면 머리의 `[고급]` 에서 들어가게 합니다.

### 다만 **Averaging 은 고급에 두면 안 됩니다**

참고한 Smaart RTA 가 이 자리를 분명히 보여줍니다 — **메인 화면에
`Averaging: Fast ⌄` 와 `Banding: 1/12 Oct ⌄` 를 그대로 올려 두었습니다.**
재면서 계속 바꾸는 값이기 때문입니다. 전체 목록은 설정에 또 있습니다.

```
화면 안        평균(Averaging)          ← 재면서 계속 바꾼다
[고급] 뒤      FFT 크기 · Window · Phase 보기 · 드리프트 진단
```

지시서 §10 의 목록은 이 둘을 한 덩어리로 묶었는데, **갈라야 합니다.**

## 10. Beginner / Intermediate / Advanced

| | 쓰는 것 | TF 가 보이는 정도 |
|---|---|---|
| **Beginner** | 측정(SPL) · 분석(RTA) · 도구(악기 EQ) | 분석 화면 아래 **한 줄**. 안 누르면 없는 것과 같다 |
| **Intermediate** | + TF 간편 | 들어가면 **숫자 둘과 그래프 하나**. 전문용어 없음 |
| **Advanced** | + 상세 · 정밀 · Multi-Point | `[상세 분석]`·`[고급]` 뒤 |

**안 2 의 가장 큰 미덕이 여기 있습니다** — Beginner 가 치르는 비용이
**분석 화면의 한 줄**뿐입니다.

## 11. 구현 우선순위

지시서 §19 의 차례에 **동의합니다.** 다만 한 가지를 덧붙입니다.

```
1차  분석 → TF → 간편 → Magnitude · 지연 · 측정 신뢰도
2차  간편 상세 — Coherence · Phase · 드리프트
3차  정밀
4차  Multi-Point
```

**1차를 시작하기 전에 정해야 할 것**: 간편 모드의 Magnitude 를
**절대 응답**으로 낼지 **상대 비교 전용**으로 낼지입니다.

전기 기준으로 재면 **마이크 응답이 상쇄되지 않습니다**(명세 검토 3장).
그런데 폰 마이크의 보정 곡선이 **아직 없습니다** — 절차 G 가 2단계에서
멈춰 있습니다. 다만 **같은 마이크로 두 상태를 견주는 쓰임**(정렬·전후 비교)
에서는 상쇄되므로, **상대 비교만으로도 1차는 쓸모가 있습니다.**

```

ui/SelahApp.kt                  문 열기/닫기 + BackHandler (교정 마법사와 같은 꼴)
```

**건드리지 않을 것**


## 참고한 것 — Smaart RTA (모바일)

담당자가 폰에 열어 둔 `com.rationalacoustics.smaartrta` 를 2026-10-01 에
봤습니다. **이 앱에는 Transfer Function 이 없습니다**(단채널 RTA 앱입니다.
TF 는 데스크톱 Suite 쪽입니다). 그래서 TF 화면 배치는 참고할 수 없었고,
**「전문 도구를 작은 화면에 어떻게 담았나」**만 봤습니다.

| 본 것 | 우리에게 주는 뜻 |
|---|---|
| **세로 한 칸에 SPL·Spectro·RTA 를 전부 쌓아 둔다** | 우리는 분석을 가로로 고정했습니다. **둘 다 성립합니다** — 다만 Smaart 의 RTA 막대는 1/12 옥타브에서 꽤 가늡니다. 지금 결정을 바꿀 근거는 못 됩니다 |

| **자주 바꾸는 값은 메인에**(Averaging · Banding), 나머지는 설정에 | **9장의 근거**입니다. 같은 값이 두 곳에 있어도 됩니다 |

| **차트 위에 사진기(저장)·폴더(불러오기) 아이콘** | 저장이 **한 번 누름**입니다. 우리는 「이 측정을 기록하기」 글자 단추입니다 |

## 먼저 봐 주셨으면 하는 곳 — 구현자가 가장 자신 없는 순서

의심스러운 자리를 숨기지 않고 먼저 적는다. 여기가 틀렸으면 그 위의
모든 숫자가 틀린다.

### 1. 쌍일차 변환의 고역 오차를 「괜찮다」고 판단한 근거

`dsp/Weighting.kt`, `WeightingTest.kt`

48kHz 에서 실측한 A 가중 오차:

| 주파수 | 오차 |
|---|---|
| 10Hz~5kHz | ≤ 0.27 dB |
| 8kHz | −0.59 |
| 10kHz | −1.21 |
| 12.5kHz | −2.62 |
| 16kHz | −6.54 |
| 20kHz | −15.89 |

이것이 실무에 문제가 되는지를 **계산으로** 가렸다. 밴드별 스펙트럼을
가정해 총 A 가중 레벨의 오차를 구했다:

| 신호 | 총 오차 |
|---|---|
| 백색잡음 | −0.85 dB |
| 분홍잡음 | −0.23 dB |
| 설교(말소리) | −0.011 dB |
| 찬양 | −0.077 dB |

**봐 주셨으면 하는 것**: 이 판단이 타당한가? 특히
- 시험에 쓴 설교·찬양 스펙트럼 모형(`WeightingTest.kt` 의 `speech`, `worship`)이
  실제 예배 소리를 대표하는가? 제가 지어낸 함수라 근거가 약하다.
- 프리엠퍼시스(pre-warping)나 오버샘플링으로 고쳐야 할 만큼인가?
- IEC 61672 Class 1/2 허용오차와 견주면 어디에 드는가? (저는 허용오차
  수치를 확신하지 못해 시험에 넣지 않았다.)

### 2. 주파수 보정을 광대역 음압에 걸지 않기로 한 결정

`app/calibration/CurveStore.kt` 의 `FREQUENCY_SCOPE_NOTE`, `ui/CaptureViewModel.kt`

주파수 보정을 **RTA 밴드에만** 걸고 큰 음압 숫자(dBA 등)에는 걸지 않았다.
제대로 걸려면 시간 영역 역응답 FIR 이 필요한데, 손쉬운 대안(밴드마다
고쳐 다시 합치기)은 Fast/Slow 시간가중을 깨뜨린다고 판단했다.

근거로 든 것: 측정용 마이크는 응답이 ±2dB 안팎이라 광대역 영향이 0.5dB
아래이고, 전대역 보정이 이미 흡수한다.

**봐 주셨으면 하는 것**:
- 이 판단이 맞는가? 0.5dB 이라는 어림의 근거가 충분한가?
- 화면 문구(「RTA 막대에만 적용됩니다」)로 충분한 고지인가?
- FIR 없이 할 수 있는 더 나은 방법이 있는가?

### 3. 저역 비중(C−A) 경계값

`dsp/MultiWeightEngine.kt` 의 `LowEnergyHint`

4 / 10 / 16 dB 로 네 단계를 갈랐다. **규격이 아니라 어림이다.**
그래서 판정색을 쓰지 않고 「설명」으로 뒀다.

**봐 주셨으면 하는 것**: 경계값이 실제 예배 신호에서 쓸모 있는가?
말소리 5dB · 찬양 15dB 이라는 제 전제가 맞는가?

### 4. 밴드 경계에 걸친 칸을 나누는 방식

`dsp/BandAnalyzer.kt`

칸이 밴드 경계에 걸치면 **겹치는 폭의 비율**로 전력을 나눠 넣는다.
에너지 보존은 시험으로 확인했다(`경계에 걸친 칸은 나눠 넣는다`).

**봐 주셨으면 하는 것**: 선형 비율 분배가 맞는가? 칸의 실제 응답은
사각형이 아니라 창 함수의 모양이므로, 엄밀히는 그 모양으로 가중해야
하지 않는가? 그 차이가 얼마나 되는가?

### 5. FFT 스케일링과 창 보정

`dsp/Fft.kt`

- 한쪽 스펙트럼으로 접을 때 0Hz 와 나이퀴스트를 뺀 칸만 2배
- Hann 창의 **에너지 보정**(제곱평균의 역수의 제곱근)을 쓴다
- 진폭 보정과 에너지 보정이 1.76dB 다른 것을 시험으로 못박았다

파스발 정리로 검증했다(칸 전력 합 = 원신호 평균 제곱, 오차 2% 이내).

**봐 주셨으면 하는 것**: 2% 허용오차가 느슨한가? 어디서 오는 오차인가?

## 구현 중 실기기가 잡아낸 것 (참고)

같은 실수가 또 있는지 보시는 데 도움이 될 것이다.

1. **진단 지표를 잘못 쟀다** — `read()` 대기 시간을 처리 시간에 넣어
   모든 기기가 「못 따라감」으로 보였다. 실제로는 손실 0.
2. **거짓 경고를 만들었다** — `routedInfo` 를 손으로 만들며 주소를 빠뜨려
   「고른 기기와 다른 곳으로 열렸다」가 잘못 떴다.
3. **보정 열쇠 충돌** — 갤럭시 내장 마이크가 둘(하단·후면)인데 이름이 같아,
   물리적으로 다른 마이크에 같은 보정값이 적용될 뻔했다.
4. **시험 기댓값을 틀리게 썼다** — 에너지 평균 −12.97dB 을 −13.01 로 적었다.
   시험이 잡았다.
5. **주파수 눈금이 잘렸다** — 630Hz 자리에 「63」이 찍혀 적극적으로
   오해를 부르는 상태였다.
6. **lint 가 크래시를 막았다** — `getAddress()` 는 API 28+, minSdk 는 26.

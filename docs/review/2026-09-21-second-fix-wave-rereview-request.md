# 2차 수정분 독립 재검증 요청

요청일: 2026-09-21 · 구현자: Claude Code · 요청 대상: Codex(독립 검증자)
대응 문서: [SELAH-RTA-fix-wave-rereview.md](SELAH-RTA-fix-wave-rereview.md)

## 검증 범위

**커밋 `a236363..f4305c1`** (2개 커밋).

- `0df28d0` — F01~F07 과 추가 지적
- `f4305c1` — 가짜 캡처 이음매와 순서 시험

지적 7건과 「추가 한계」의 코드 항목을 모두 손댔다. 그중 **하나는 제품
결정이 필요해 사용자에게 물었고**(F07), 하나는 검증자가 받아들일 수 있다고
한 쪽으로 갔다(F05).

## 먼저 볼 것

검증자의 `FixWaveProbe.kt` 측정 논리를 그대로 옮겨
`dsp/src/test/kotlin/kr/joa/selahrta/dsp/FixWaveRegressionTest.kt` 에 두었다.
찍기만 하던 값을 **재는 방법은 손대지 않고** 단언으로 바꿨다.

**F06 은 고치기 전에 실패하는 것을 먼저 확인했다.** `setCurve` 에서
`latest = null` 을 빼면 「곡선을 바꾸면 옛 프레임을 내놓지 않는다」가
실패한다.

새로 만든 순서 시험도 같은 방법으로 확인했다 — `runCaptureLoop` 에서
「읽고 나서 running 을 다시 본다」를 빼면 「읽는 동안 멈추면 그 덩어리를
내보내지 않는다」가 실패한다.

## 지적에 대한 수정

### F01 · 측정 중 reroute (High)

`onRoutingLost()` 가 안내문만 쓰던 것을 **분리와 같은 정책 처리**로 바꿨다.
`MicSource` 가 무엇으로 바뀌었는지(`InputDeviceInfo`) 함께 넘기고,
`onRoutingChanged(session, to)` 가 세대 검사를 거쳐 `applyDisconnectPolicy` 를
부른다. Pause 면 멈추고 실패로, FallBack 이면 **새 세션**으로 다시 연다.

### F02 · 종료 timeout 뒤 옛 worker (High)

엔진·명령 큐·통계를 전부 `CaptureSession` 에 묶었다. 캡처 콜백은 맨 앞에서
`if (active !== session) return` 을 보므로, 늦게 깨어난 옛 스레드는
**자기 세션의 객체조차 건드리지 않고** 돌아간다. 읽기 루프도 `read()` 뒤에
`running` 을 다시 본다.

두 겹인 까닭: `close()` 가 `running=false` 후 500ms 만 기다리므로, 이미
`running` 검사를 지나 콜백 안에 들어가 있는 스레드가 있을 수 있다. 루프의
검사는 그 앞을 막고, 세션 검사는 그 뒤를 막는다.

### F03 · 오류와 목록 변경의 순서 (Medium)

둘을 `applyDisconnectPolicy` 하나로 모았다. **두 번 돌지 않는 것은 세대가
보장한다** — 먼저 온 쪽이 `stop()` 을 부르면 세대가 닫히므로 늦게 온 쪽은
`accepts()` 에서 걸린다.

### F04 · stop 이 세션을 무효화하지 않음 (Medium)

`stop()` 이 `generation.end()` 로 세대를 닫고 화면 쪽 `session` 도
`CaptureGeneration.NONE` 으로 만든다. 늦게 온 경로 확인이 보정을 되살리거나,
늦게 온 오류가 정상 종료를 실패로 뒤집는 일이 없다.

### F05 · 표본을 최대인 것처럼 표시 (Medium)

**검증자의 수학적 판단을 받아들인다.** 「경계 손실은 소리가 두 밴드에 걸쳐
있어서」라고 적었던 것은 틀렸다 — 순음은 한 밴드에 속하고, 갈라지는 것은
창 누설과 칸 분배로 인한 분석 오차다. 주석과 ADR 에서 그 설명을 지웠다.

다만 **경계까지 넣어 판정하지는 않는다.** 검증자의 첨부 로그가 그 까닭을
보여 준다 — 1kHz 밴드의 `sampledWorst=2.3643 at=0.01` 이다. 가장자리 손실은
저역만의 현상이 아니라 유한 창의 구조적 한계라 **모든 밴드에** 있으므로,
1dB 기준에 넣으면 31개 밴드가 전부 미분해가 되어 화면이 아무것도 구별해
주지 못한다.

그래서 검증자가 「가능하다」고 한 쪽으로 갔다: 시험 영역을 명시하고 표본
이라고 표현한다. 화면 문구는 이제

> 「…밴드 가운데에 순음을 놓고 재면 6.6dB 까지 낮게 나왔습니다 — 밴드 경계
> 가까이에서는 더 샙니다.」

이고, ADR 에 가운데 구간과 경계 근처(t=0.99) 값을 나란히 적었다.

### F06 · 곡선 표시가 실제 적용보다 앞섬 (Medium)

`setCurve()` 가 `latest` 를 비우고, `RtaFrame` 이 **계산에 쓰인 곡선 세대**를
싣는다. 화면은 자기 세대와 같을 때만 「보정 적용됨」을 적는다.

### F07 · 자동 전환 요구 (Medium)

**사용자에게 물었고, 「새 세션으로 자동 전환」으로 결정됐다.** 요청서의 제
설명을 승인으로 간주하지 않겠다는 판단이 옳았다.

구현: 「외부 기기 자동 사용」이 켜져 있고 사용자가 기기를 직접 고르지
않았으며, 새 목록으로 `chooseInput` 을 돌렸을 때 그 새 기기가 뽑히면 —
지금 측정을 끝내고 그 마이크로 새 측정을 연다. 고른 기기가 있으면 바꾸지
않는다. ADR 에 결정과 까닭을 적었다.

설정 화면의 「재는 도중에 꽂아도 바꾸지 않고 알리기만 합니다」도 함께
고쳤다 — 구현을 바꾸고 문구를 두면 그 문구가 거짓이 된다.

### 추가 한계에 대한 수정

- **보정 저장이 routeConfirmed 를 안 봤다** — 검증자가 답변 3번에서 짚은
  것이다. `confirmedFormat()` 을 거치게 했고, 미확인 상태면 그 사실을 적어
  거절한다. R01 이 막으려던 오귀속이 저장 쪽으로 새어 나간 것이었다.
- **stop 뒤 `opened` 가 남아 「사용 중」이 붙었다** — `opened` 를 지우고
  `lastInput` 을 따로 뒀다. 설정 화면은 「마지막으로 쓴 기기 … 지금은 열려
  있지 않습니다」로 적는다.
- **CurveStore**: 임시 파일 이름에 나노초를 붙여 동시 저장이 같은 `.tmp` 를
  쓰지 않게 했고, rename 실패 시 **직접 덮어쓰지 않고 오류를 낸다**.
  이전 판 이름의 파일이 있으면 알린다 — **옮기지는 않는다.** 옛 이름은
  서로 다른 기기가 같은 파일을 가리킬 수 있어, 옮기는 순간 귀속을 우리가
  정하는 셈이 된다.
- **bandGainsDb**: 측정 경로에서 빠져 있고 뜻을 주석에 적었지만 이름은
  그대로다. 검증자의 제안대로 `bandCenterResponseDb` 로 바꾸거나 deprecated
  처리할지 판단을 구한다.

## 새로 만든 시험 이음매

검증자가 요구한 「fake AudioRecord/read barrier」다.

`MicSource` 의 읽기 루프를 `CaptureLoop.kt` 로 떼어 냈다. `AudioRecord` 에
붙어 있는 부분(16비트 변환·실제 읽기·`routedDevice`)만 `RecordAdapter` 에
남고, **지켜야 할 순서는 `runCaptureLoop` 이 갖는다.** 그래서 기기 없이
순서를 강제할 수 있다.

`FakeRecorder` 에 문(`CountDownLatch`)을 걸면 `read()` 가 거기서 멈춘다.
시험은 읽기가 문 앞에 닿은 것을 확인한 뒤 `running` 을 내리고 문을 연다 —
**「읽는 도중에 멈췄고, 읽기가 늦게 돌아오는」** 상황이 정확히 만들어진다.

| 시험 | 무엇을 못박는가 |
|---|---|
| 읽는 동안 멈추면 그 덩어리를 내보내지 않는다 | F02 |
| 읽기 오류는 한 번 알리고 끝난다 | L01 |
| 오류 코드마다 다른 까닭으로 옮긴다 | DEAD_OBJECT→DeviceLost 등 |
| 경로 미확인이면 첫 덩어리 뒤에 한 번만 더 묻는다 | R01 |
| 경로를 못 잡아도 계속 돈다 | 경로 미확인 기기 |

세대 규칙은 `CaptureGeneration` 으로 따로 빼고 7건으로 못박았다 — 멈춘 뒤
버리기(F04), 다시 시작하면 이전 세대 버리기(F02), 번호 재사용 없음.

## 판단이 갈릴 수 있는 곳

1. **이음매가 ViewModel 까지 닿지 못했다.** `runCaptureLoop` 과
   `CaptureGeneration` 은 순수하게 시험되지만, **`CaptureViewModel` 자체는
   여전히 시험 밖**이다. 「stop→start→old callback」을 ViewModel 수준에서
   재현하려면 DataStore·scanner·MicSource 생성까지 주입 가능하게 해야 하고,
   그건 지금 규모의 리팩터링을 한 번 더 하는 일이다. 두 조각으로 충분한지,
   아니면 ViewModel 까지 갈라야 하는지 판단을 구한다.

2. **F05 를 「표본으로 표시」로 끝낸 것.** 검증자가 가능하다고 한 쪽이지만,
   1dB 이라는 선과 「가운데 절반」이라는 영역은 여전히 내가 정한 값이다.

3. **F01 에서 reroute 를 분리와 같은 정책으로 묶은 것.** Pause 면 멈추고
   FallBack 이면 새 세션으로 다시 연다. reroute 가 자주 흔들리는 기기가
   있으면 재시작이 되풀이될 수 있는데, 그런 기기를 본 적이 없어 가정에
   기대고 있다.

4. **F07 의 자동 전환 조건.** 「자동 설정이 켜짐 + 고른 기기 없음 + 새
   목록으로 `chooseInput` 했을 때 그 기기가 뽑힘」 셋을 모두 만족해야
   바꾼다. 마지막 조건은 USB 가 둘 꽂힌 경우를 위한 것인데, 그때 어느 쪽을
   골라야 하는지는 명세에 없다.

## 이번에도 하지 못한 것

- **ViewModel 수준의 순서 시험** — 위 1번.

  곡선 격리를 실물로 확인하지 못했다. 자동 전환은 **코드 경로만** 맞춰 놓은
  상태다.
- **`ERROR_DEAD_OBJECT` 실기기 주입** — 가짜 레코더로는 시험했지만 실제
  기기에서 내는 방법을 찾지 못했다.

## 결론

**종료 승인 보류. Critical 없음, High 1건 잔존.** 이전 두 반례는 수정됐지만, 새 최종 승인 함수가 계산 후 유효 대역의 내부 결손을 보지 않는다. RCP-F01의 입력 단계 교집합·CAL 범위 통합은 해결됐고, 결과 단계 승인 검사가 불완전하다.

코드와 요청 문서를 확인하고 대상 시험 150개 및 독립 probe를 실행했다. Production 수정은 없으며 작업 트리는 검토 전후 깨끗하다. 구현자의 문서상 완료 주장은 검증 대상으로 취급했다.

## F01-R — High: 상한 처리로 대부분의 보정이 무효화돼도 양끝만 남으면 최종 Pass

**파일/위치:** `dsp/src/main/kotlin/kr/joa/selahrta/dsp/CalibrationQuality.kt:398–430`, 특히 `:405–416`.

`judgeCalibration()`은 correction.valid의 개수가 0인지 검사하고, 0이 아니면 첫 유효점과 마지막 유효점의 주파수만 본다. 중간에서 얼마나 많은 대역이 무효화됐는지는 검사하지 않는다. 기존 approvedRatio는 보간·평활·상한 처리 **이전** 보고의 값이다. 따라서 입력 보고가 충분하고 두 끝점이 넓게 떨어져 있으면, 그 사이 대부분의 보정을 신뢰할 수 없어도 최종 Pass가 된다.

### 재현 — outcome을 조작하지 않고 실제 계산 경로를 통과

기본 CalibrationSettings(보정 상한 12dB)를 사용한다.

- 31개 대역, 각 단계 동일한 프레임 8개.
- 대상은 모든 대역 70dB.
- 기준 전후는 동일: index 0, 1, 29, 30은 70dB, index 2–28은 짝수 100dB / 홀수 40dB.
- 두 경로 배경 0dB, CAL 범위 20–20000Hz.
- `referenceCalApplied=true`, `dspVerifiedBySignal=true`.
- `qualityFromSession → calibrateFromSession → judgeCalibration` 순서로 호출.

독립 출력:

```text
POST_LIMIT approved=30/31 pre=Pass final=Pass auto=true
valid=49/120 centers=3/31
span=25.19842099789747..19330.54592372118 norm=40
```

입력 단계의 공통 유효 대역은 30/31이다(가장 낮은 정확 중심 주파수는 20Hz 미만이므로 CAL 하한에서 제외). 계산 후에는 축 120점 중 **49점(40.8%)**만 유효하다. 원래 31개 중심 주파수 각각에 가장 가까운 축 점을 검사하면 **3개만 유효**하다. 그런데 약 25Hz와 19.3kHz에 유효점이 있어 최종 Pass·mayAutoApply=true가 된다.

`centers`는 최근접 축 점을 샘플링한 관측치이며, 새로운 공식 대역 커버리지 정의라는 뜻은 아니다. 마찬가지로 49/120을 원래 대역 수 정책에 그대로 대입하자는 뜻도 아니다. 핵심은 최종 함수가 **어떠한 내부 커버리지 검사도 하지 않아**, 극심한 상한 초과로 대부분의 중심 주파수 보정을 제외한 결과를 무제한 Pass로 승인한다는 것이다.

### 사용자 영향

제조사 CAL과 측정 응답의 큰 불일치, 좁은 피크·딥 등으로 결과의 많은 부분이 무효가 돼도 검증 완료·자동 적용 가능으로 분류될 수 있다. valid 마스크 자체가 사라지거나 무효 보정값이 적용된다는 주장은 아니다. 신뢰할 수 없는 결과에 대한 승인·안내가 문제다. 현재 저장 경로 연결 전이므로 실제 파일 저장이나 기기 자동 적용을 관찰한 것은 아니다.

### 권장 수정

최종 correction.valid에서 유효 커버리지를 계산하고 승인에 반영한다. 원래 1/3옥타브 대역별 지원 여부 또는 로그 주파수 폭 등, 선택한 기준의 정의와 기존 최소 비율 정책과의 관계를 명시한다. 보간 점 개수를 원래 대역 수와 무조건 동일하게 취급하지 않는다. 양끝 범위는 별도 안내로 유지하되 내부 결손과 상한 초과 제외를 숨기지 않는다.

진단 곡선을 반환하는 것은 허용 가능하다. 다만 최종 유효 지원이 정책에 못 미치면 Pass/자동 적용을 금지한다. 지지구간 충분성의 상세 정책이 아직 미정이라면, 검증된 것으로 승인하기보다 그 불확실성을 최종 판정에 반영한다.

### 필요한 회귀 테스트

1. 위 세션을 그대로 사용하고 입력 approvedRatio 통과·정규화 점 양수·양끝 주파수 통과를 전제로 단언한 후 최종 Pass 금지를 검사한다.
2. 모든 점 유효한 정상 평탄 입력은 Pass.
3. 최종 유효점 0개, 좁은 단일 구간, 양끝만 남고 중간이 비는 경우를 각각 검사한다.
4. 유효 커버리지 정책 경계 및 축 해상도 변경 시 같은 지원 구간에 대한 판정 일관성을 확인한다.
5. 마법사/저장 경로 구현 시 이 최종 판정 결과가 실제 저장·자동 적용에 사용되는지 통합 시험한다.

현재 `judgeCalibration` 호출 검색 결과는 `ApprovalProbeTest`의 출력용 probe뿐이다. 함수에 대한 직접 회귀 단언이 없으므로 기존 150개 시험 통과가 위 반례를 검출한다는 뜻은 아니다.

## 이전 반례와 설계 변경 확인

| 항목 | 이번 독립 결과 |
|---|---|
| 대상 20/31, 기준 19/31, 교집합 8/31 | Fail, auto=false |
| CAL 1000–1300Hz 제한 | Fail, auto=false |
| 계산 전 교집합 통계 | approvedCount/Ratio/Range에 대상 SNR·기준 SNR·CAL 범위 반영 확인 |
| CAL 범위 전달 | calibrateFromSession의 별도 인자 제거, quality의 범위 사용 확인 |
| 앞선 정규화·프레임 반례 | 동일 입력 correction=0.0, 정규화 0점 거절, 유지 2개 Fail 유지 |

CAL 범위를 한 곳에서 받도록 한 변경은 적절하다. 이번 잔여 결함은 그 수정의 부정이 아니라, **계산 후 더 줄어든 지원 범위를 검사한다는 새 함수의 계약이 아직 완성되지 않은 것**이다.

## 요청서 질문 및 통합 경계

- 정규화 점/대역 수와 오프셋을 표시하는 것은 진단에 도움이 되지만 충분성 검증을 대체하지 않는다. 임의 숫자를 새로 만드는 대신 실측으로 정책을 정한다는 방향은 유지해도 된다. 다만 결과가 불확실함을 표시하는 것과 Pass 승인은 구분해야 한다.
- `judgeCalibration`이 아직 production 저장 경로에서 호출되지 않는다는 요청서의 제한은 코드 검색과 일치한다. 마법사가 없는 현 단계에서 미연결 자체를 별도의 새 High로 세지는 않았다. 향후 저장/자동 적용의 필수 통합 게이트다.
- `referenceCalApplied` Boolean의 실제 bin 보정 증명 부족, 8프레임/2dB 정책의 실측 근거 부족, 저장 형식 계약 미확정은 이전과 같이 남는다. 이번에 종료한 것으로 해석하지 않는다.
- 새로운 교집합 검사로 기준 SNR 미측정은 이제 approvedRatio=0이 되어 Fail로 내려간다. 이전 Degraded보다 보수적인 동작이며, 기존 기준 미측정 승인 차단을 약화시키지는 않는다.

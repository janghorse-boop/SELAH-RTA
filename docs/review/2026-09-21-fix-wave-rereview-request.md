## 각 지적에 대한 수정

### R01 · 라우팅 확인 전에 보정 기기를 확정 (High)

- `tryOpen()` 에서 `routedDevice` 를 **읽지 않는다.** 그 자리의
  `OpenedFormat` 은 `routeConfirmed=false` 이고 열쇠는 요청한 것이다.
- `start()` 가 `startRecording()` 직후 `confirmRoute()` 로 신원을 확정하고
  `onRouteConfirmed` 으로 알린다. 그때 못 잡으면 **첫 정상 읽기 뒤에 한 번
  더** 시도하고, routing-changed 콜백에서도 다시 시도한다.
- 비교는 표시명이 아니라 **열쇠**(`종류|이름|주소`)로 한다.
- ViewModel 은 **경로가 확인된 뒤에야** `watchCalibration()` 을 건다.
  확인 전에는 `ActiveCalibration.assumed`(미보정)로 둔다 — 「보정된 측정값
  발행 보류」를 이렇게 구현했다.
- `openingKey`(분리 감시 기준)도 확인된 열쇠로 바꾼다.
- 화면 상단 배지에 「입력 확인 중」 상태를 따로 뒀다.

**실기기 확인**(Galaxy S23, SM-S918N):

```
09:51:03.208 열림(경로 미확인): … deviceKey=BuiltIn|SM-S918N|back, routeConfirmed=false
09:51:03.271 경로 확인: BuiltIn|SM-S918N|back        ← startRecording 후 63ms
```

### R02 · 캡처 스레드가 최신 설정·보정을 덮어씀 (High)

- 캡처 스레드는 이제 `MeasurementSnapshot`(세션 번호·진단·A/C/Z 프레임·RTA
  프레임·클리핑 여부)만 `_measurement` 에 쓴다. **`_state` 를 읽지도 쓰지도
  않는다.**
- 화면 상태는 `combine(_state, _measurement).stateIn(...)` 으로 **주
  스레드에서** 합친다. 가중치 선택도 합치는 자리에서 한다(그래서 A/C/Z 를
  모두 실어 보낸다).
- DSP 객체를 만지는 일(엔진 교체·`resetPeaks`·`setCurve`)은 모두
  `ConcurrentLinkedQueue` 명령으로 넘겨 **오디오 스레드가 덩어리 사이에서**
  실행한다. `engine`/`rta` 참조는 `@Volatile`.
- `stop()` 에서 큐를 비운다 — 다음 세션 엔진에 지난 명령이 걸리지 않게.

**덧붙여 고친 것**: 마이크 열기에 실패하면 `_state.value = CaptureUiState(...)`
로 상태를 통째로 갈아 끼워 설정·기기 목록이 기본값으로 돌아갔다. DataStore 가
같은 값을 다시 내보내지 않으므로 그 상태가 그대로 남는다. `copy()` 로 고쳤다.
지적에는 없지만 같은 갈래다.

### R03 · 기기를 바꿔도 이전 보정이 남음 (High)

- `stop()` 과 `start()` 가 `calibration`/`curve` 를 즉시 비운다.
- `CaptureUiState.session` 세대 토큰을 두고, 번호가 다른 스냅샷은 버린다.
- `stop()` 은 **지금 보정으로 계산한 값을 굳혀서** 남긴다. 그러지 않고 보정만
  지우면 멈춘 순간 화면의 숫자가 까닭 없이 튀어 오른다.

**실기기 확인** — 후면 마이크에 보정을 저장한 뒤:

| 단계 | 배지 | 로그 |
|---|---|---|
| 후면 측정 중 | 보정됨 | `경로 확인: …\|back` |
| 멈춤 | **미보정** | — |
| 하단으로 시작 | **미보정** (이전 보정 안 붙음) | `경로 확인: …\|bottom` |
| 후면으로 다시 시작 | 보정됨 (제 것은 돌아옴) | `경로 확인: …\|back` |

### L01 · read 오류 후 Running 과 마지막 숫자가 유지됨 (High)

- `read() < 0` 이면 `running.set(false)` 하고 `CaptureEnd` 로 알린 뒤
  루프를 **return** 한다.
- `CaptureEnd.of(code)` 가 `ERROR_INVALID_OPERATION`→Preempted,
  `ERROR_DEAD_OBJECT`→DeviceLost, 그 밖→ReadError 로 옮긴다.
- ViewModel 은 `stop()` 후 `MeasureState.Failed` 로 바꾸고 까닭을 적는다.

**실기기에서는 재현하지 못했다** — `ERROR_DEAD_OBJECT` 를 낼 방법을 찾지
못했다. 코드 경로만 확인했다.

### R05 · 밴드 보정이 세 지점 평균을 뺌 (Medium)

- `CalibrationCurve.binCorrectionLinear(fftSize, sampleRate)` 가 FFT 칸마다
  `10^(−g(f_k)/10)` 을 만든다.
- `BandAnalyzer.toBandPower(power, out, binCorrection)` 가 **밴드로 묶기
  전에** 칸마다 곱한다. `RtaEngine.setCurve()` 가 경로를 쥔다.
- `bandGainsDb()` 는 남겼지만 **밴드 중심의 응답**(표시용)으로 바꿨고,
  측정 경로에서 뺀다. `RtaFrame.toView()` 는 이제 보정을 걸지 않는다.
- 회귀 시험 `CurveCorrectionTest` 7건 — 기준답을 구현에서 끌어오지 않고,
  **알려진 전달함수로 마이크 신호를 만든 뒤 원음 에너지(A²/2)를 되찾는지**
  본다. 밴드 중심·밴드 안 좌우·같은 밴드 두 순음·평탄·notch.

### R06 · MAX 가 덩어리 마지막 값만 봄 (Medium)

`pushBlock` 이 `BlockWeighting(last, max)` 를 돌려주고 `SplEngine` 이
`max` 로 MAX 를 갱신한다.

### R07 · 시간가중이 첫 샘플 제곱을 상태로 주입 (Medium)

초기 에너지를 0 으로 두고, `settled`(넣은 샘플 ≥ 3τ)를 `SplFrame`→
`MeterReading` 으로 내보낸다. 자리를 잡기 전에는 측정 화면이
「레벨이 자리를 잡는 중입니다」를 띄운다.

### R08 · 63/80Hz 를 분해됐다고 표시 (Medium)

기준을 **재서** 정한다. 엔진을 만들 때 밴드마다 순음을 넣어 실제로 얼마나
빠지는지 재고(`bandLossDb`), 1dB(`LEAKAGE_TOLERANCE_DB`)을 넘으면 분해되지
않았다고 본다. 화면도 참·거짓 대신 실제 수치를 적는다:
「125Hz 아래 밴드는 … 실제보다 최대 6.6dB 낮게 나옵니다」.

4096점·48kHz 실측: 20Hz 6.64 / 31.5Hz 5.05 / 50Hz 3.32 / 63Hz 2.49 /
80Hz 1.78 / 100Hz 1.02 / 125Hz 0.92 / 1kHz 0.00 dB.

### R09 · 곡선 파일명 충돌 (Medium)

파일명을 열쇠의 **SHA-256** 으로 바꾸고, 원래 열쇠는 파일 첫 줄에
`# selah-key: …` 주석으로 남긴다(해석기가 건너뛰는 줄이다). 저장은 임시
파일 → rename.

### R10 · 무가중 PEAK 를 dBA/dBC 로 표시 (Medium)

PEAK 타일 단위를 「dB 가중없음」/「잘림 · 가중없음」으로 고정했다. 구간
참고범위의 「순간 피크 … dBA」도 실제로 견줄 수 있는 「짧은 최대(MAX)」로
이름을 바꿨다(그 범위는 dBA 기준이고 MAX 가 dBA 다).

**실기기 확인**: PEAK 타일에 `dB 가중없음` 표시.

### R11 · 입력 선택 UI 가 실제 정책과 다름 (Medium)

제품 정책을 **「재는 도중에는 입력을 바꾸지 않는다」로 고정**하고 화면이
그렇게 말하게 했다(아래 「판단이 갈릴 수 있는 곳」 참고).

- 「사용 중」은 **확인된 경로**에만 붙는다. 고르기만 한 것은 「다음 시작에
  사용」이다.
- 「외부 기기 자동 사용」 설명에 시작 시점의 규칙임을 적었고, 재는 도중에
  꽂히면 그 설정을 읽어 안내문을 다르게 쓴다.
- **「내장 마이크로 전환」 정책이 이름대로 동작한다.** `chooseInput(...,
  disconnectFallBack = true)` 가 고른 기기·자동 규칙을 무시하고 내장을
  고른다. 시험 2건 추가.

**실기기 확인** — 후면으로 재는 중에 하단을 고르면:
하단 「다음 시작에 사용」 · 후면 「사용 중」 · 「지금 열려 있는 기기: 후면」.

### R12 · USB 에서도 PHONE MIC 고정 (Medium)

`capture.opened.micKind` 로 그리고, 세 상태를 구분한다: 안 열림(흐린
PHONE MIC) / 경로 미확인(「입력 확인 중」, 경고색) / 확인됨(그 기기 배지).

**USB 마이크가 없어 USB MIC 표시는 확인하지 못했다.**

### R04 · 광대역에서 주파수 보정을 뺀 근거 (Medium)

범위는 그대로 두되 **근거를 바꿨다.** 「±2dB 마이크면 0.5dB 아래이고
전대역 보정이 흡수한다」는 틀린 문장이라 지웠다. 대신 남는 오차를 적는다
— 보정 기준 대역 −2dB, 측정 대역 +2dB 이면 4dB. 화면 문구
(`FREQUENCY_SCOPE_NOTE`)도 같이 고쳤다.

결정 근거: `docs/decisions/2026-09-21-measurement-accuracy-limits.md`

## 판단이 갈릴 수 있는 곳 (여기를 봐 주십시오)

1. **R08 의 판정 기준을 내가 정했다.** 1dB 은 규격에서 온 값이 아니다.
   재는 자리도 밴드 안 로그 눈금 0.25/0.5/0.75 로 정했는데, **경계에 바싹
   붙은 자리를 뺀 것이 옳은지** 봐 주십시오. 0.1/0.9 로 재면 더 나쁜 값이
   나오고(63Hz 2.93dB) 분해 기준선이 398Hz 까지 올라간다. 경계 근처에서
   새는 것의 상당 부분은 창 때문이 아니라 「그 소리가 두 밴드에 걸쳐
   있어서」라고 판단해 뺐는데, 그 판단이 틀렸다면 기준선이 크게 달라진다.

2. **R11 을 「정책을 UI 에 맞추는」 대신 「UI 를 정책에 맞추는」 쪽으로
   골랐다.** 재는 도중 입력 전환을 구현하지 않았다. 예배 중에 입력이 바뀌면
   그 앞뒤 값이 다른 마이크의 값이 되는데, 그것을 한 세션으로 묶어 리포트에
   싣는 것이 더 위험하다고 봤다. 명세의 자동 전환 요구와 어긋난다면
   지적해 주십시오.

3. **R01 에서 경로가 끝내 확인되지 않으면 보정을 영영 못 건다.** 그런
   기기가 있으면 그 기기에서는 보정 기능 자체가 막힌다. 확인 시도는 세 번
   한다(startRecording 직후 / 첫 정상 읽기 뒤 / routing-changed). 그래도
   실패하는 기기가 현실에 있다면 다른 처리가 필요하다.

4. **R05 에서 `bandGainsDb()` 를 지우지 않고 의미를 바꿨다.** 이름이 같은
   채로 뜻이 바뀐 함수는 다시 오용되기 쉽다. 지워야 한다고 보시면 그렇게
   하겠다(검증자의 `ReviewProbe.kt` 가 이 함수를 부르고 있어 남겼다).

5. **R02 의 명령 큐가 실제로 경합을 없앴는지.** 큐는 오디오 스레드가
   덩어리 사이에서 비우는데, `stop()` 이 `close()`(스레드 join) 뒤에
   큐를 비운다. 그 사이에 주 스레드가 명령을 넣으면 — `postToCapture` 가
   `source != null` 을 보므로 막힌다고 봤지만, 그 판단이 맞는지 봐 주십시오.

## 이번에도 하지 못한 것

- **USB 마이크 검증** — 기기가 없다. R12 의 USB MIC 표시, 서로 다른 열쇠의
  곡선 격리(R09)를 실물로 확인하지 못했다.

- **60분 부하·열·메모리** — 돌리지 않았다.
- **조용한 환경 측정** — 사무실이라 주변 소음이 있다. 사용자가 밤에 다시
  잰다고 했다.

## 판정

**검토 범위에서 Critical/High 없음. Medium 1건, Low 1건. EQ-B의 명세 일치 완료 판정은 보류한다.**
정적 화면만 추가하는 범위는 지켜졌다. 아래 EQB01을 고치고 회귀 시험을 추가한 뒤 EQ-C 오버레이에 카탈로그를 연결하는 것을 권고한다. 기존 전체 앱이나 음향 수치의 현장 타당성을 승인하는 판정은 아니다.

## EQB01 — Medium: 서로 다른 성격·증상 대역을 합쳐 증상 주파수 경계가 바뀜

위치:
- app/src/main/java/kr/joa/selahrta/data/instrument/InstrumentCatalog.kt:134
- app/src/main/java/kr/joa/selahrta/data/instrument/DrumsCatalog.kt:88,122,139,242,281,294
- 표시 경로: app/src/main/java/kr/joa/selahrta/ui/instrument/InstrumentGuideScreen.kt:134,167
- 근거 명세: docs/spec/SELAH_RTA_Instrument_EQ_Guide_v1.0.md:99,163,165,166,178,181,182

FrequencyRegion 하나에 range와 characterTags/symptomTags가 함께 있다. 이 구조에서 두 태그의 원래 대역이 다른데도 성격 대역을 공통 range로 사용했다. `증상만`은 symptomTags가 있는 영역을 그대로 거르므로 잘못된 경계가 실제 안내 숫자로 나온다.

| 프로필 / 증상 | 명세의 증상 대역 | 현재 증상 카드 대역 |
|---|---|---|
| synth.lead_brass / 날카로움 | 2–6 kHz | 2–5 kHz |
| edrums.snare / 날카로움 | 3–6 kHz | 2–5 kHz |
| drums.snare / 자극 | 3–6 kHz | 2–5 kHz |
| edrums.hihat / 거침 | 3–7 kHz | 3–8 kHz |
| drums.hihat / 날카로움 | 3–7 kHz | 3–8 kHz |
| edrums.cymbal / 자극 | 3–7 kHz | 3–8 kHz |
| drums.overhead / 자극 | 3–7 kHz | 3–8 kHz |

재현: 독립 JVM probe로 위 7개 region의 symptomTags가 비어 있지 않음을 확인하고 실제 range를 명세의 별도 기대값과 대조했다. 7/7 불일치. 원래 카탈로그 시험 15건은 모두 통과했다. 스네어의 경우 카드 숫자는 2–5 kHz인데 같은 카드 주의 문장은 3–6 kHz여서 현재 화면 자체도 모순된다.

사용자 영향: 증상 청취 범위를 잘못 안내한다. EQ-C에서 이 자료를 그대로 음영으로 그리면 누락·과잉 범위가 오버레이로 이어진다. 아직 자동 후보 탐지나 필터를 실행하지 않으므로 측정값 손상이나 실제 오디오 처리 결함은 아니다.

권장 수정: 경계가 다르면 성격과 증상을 각각의 FrequencyRegion으로 분리하고 고유 id를 부여한다. 예: 스네어 attack 2–5 kHz, harshness 3–6 kHz. 성격 영역 자체를 3–6으로 바꾸면 다른 명세 값을 잃으므로 피한다. 동일 범위를 공유하는 태그까지 무조건 분리할 필요는 없다.

필요 회귀 시험: 명세 §4의 `(profile, 의미/태그, lowHz, highHz)` 기대값을 독립 표로 대조한다. 위 7개 사례에서 성격과 증상 경계를 각각 확인한다. `증상만`에서도 증상용 범위가 선택되는지 검증한다. EQ-C의 최대 3개 표시는 별도의 선택·표시 정책으로 처리하고 원본 영역을 합치거나 삭제하지 않는다.

## EQB02 — Low: 수치 일치 시험이 검증하는 범위보다 보고가 넓음

위치:
- app/src/test/java/kr/joa/selahrta/instrument/InstrumentCatalogTest.kt:187–243 (게이트 표 대조)
- 같은 파일:301–352 (필터 시작점 대조)
- docs/review/2026-09-21-eq-b-review-request.md §4

게이트 표 대조는 attack/hold/release/감쇠량을 확인하지만 Hysteresis는 확인하지 않는다. 필터 대조도 모든 프로필의 모든 HPF/LPF/대체 범위/bypass가 아니라 일부 값만 확인한다. 영역 시험은 범위 유효성과 문구 존재를 검사할 뿐 §4의 경계 일치를 검사하지 않는다. 따라서 「필터 시작점이 명세와 같다」를 전체 전사 정확성 보증으로 읽으면 안 된다.

독립 재현: 원본을 건드리지 않고 검증 폴더의 카탈로그 복사본에서 패드 HPF를 100–200 → 110–210 Hz로, 공통 Hysteresis를 2–6 → 20–60 dB로 동시에 변이시켰다. 기존 시험은 여전히 **15/15 통과**했다. 이 변이값이 현재 제품에 들어 있다는 뜻은 아니다.

사용자 영향: 현재 정확한 값도 이후 전사·편집 오류가 생기면 놓칠 수 있다. EQB01은 실제로 현재 시험이 놓친 데이터 오류다.

권장 수정: Hysteresis와 전체 필터 표를 독립 기대값으로 확인하거나, 시험 이름·요청서에 부분 표본 점검임을 명시한다. `Sources.titles[id] != null`은 내장 출처 키 연결 검사이며 URL의 접근 가능성이나 문헌의 수치 보증을 뜻하지 않는다.

필요 회귀 시험: 위 두 변이가 각각 실패하도록 검증한다. 전체 프로필 키 집합과 기대값 표의 키 집합도 대조해 새 프로필의 검사 누락을 막는다. 생성자 검증을 시험할 경우 잘못된 범위/NaN/무한대 입력의 거절을 직접 확인한다.

## 요청서의 다섯 질문

1. **Kotlin 카탈로그: 수용 가능.** 정적 내장 자료에 JSON이 필수인 기술적 이유는 발견하지 못했다. 다만 범위 숫자의 검증은 주로 생성 시점의 runtime require이지 컴파일 타임 검증은 아니다. 현재 ADR에는 JSON→Kotlin 결정을 기록하지 않았으므로 그 결정과 범위를 추가하고 §11과 일치시킬 것. 현재 소스 주석/요청서 설명은 확인했다.
2. **크런치 null + 설명: 적절.** 유형은 유지하고 명세에 없는 수치를 임의 생성하지 않는 방향이 맞다. 다만 사용자 화면의 「명세가 숫자를 주지 않았다」보다 「공통 시작값을 제시하지 않습니다. bypass부터 청취하며 조정하세요」가 이해하기 쉽다. 클린과 하이게인의 중간값을 정답처럼 암시하지 않도록 한다.
3. **겹치는 별도 영역: 적절.** 주파수 중첩 자체는 결함이 아니다. 이번 결함은 오히려 경계가 다른 것을 하나로 합친 곳이다. 최대 3개는 오버레이 표시 정책이지 카탈로그 영역 수 제한이 아니다. synth.other의 전대역 설명도 자동 정상 곡선이나 탐지 규칙으로 쓰지 않는 현재 범위에서는 허용한다.
4. **시험 이름/주장: EQB02 참조.** 15건은 실제 통과했고 주요 게이트·컴프레서 표를 별도 기대값으로 옮긴 점은 유효하다. UI 표시, 전 EQ 대역 정확성, 외부 출처 유효성까지 입증하지는 않는다.
5. **EQ-C 이전: EQB01과 그 회귀를 먼저 닫을 것.** detectorRuleId null은 EQ-E 이전 상태로 허용한다. EQ-C sink를 붙일 때 기존 시험 수가 유지되는 것만으로 EQ-08 비간섭을 보증하지 말고, 가이드 on/off 동일 입력의 기존 결과와 sink 유실·처리 경계를 비교해야 한다.

## 확인한 범위와 남은 위험

- 카탈로그 3개 production 소스와 InstrumentCatalogTest를 로컬 Kotlin 2.2.20/JDK/JUnit으로 직접 컴파일·실행: **고유 15건 통과**. 독립 경계 probe: **7개 불일치**. 별도 변이 실행: **15건 모두 통과**(검출 공백 확인).
- 화면·내비게이션 연결을 코드로 확인했다. 새 가이드 화면은 카탈로그만 읽고 AudioRecord/DSP/측정 worker를 시작하지 않는다. 게이트·컴프레서 탭에 A/B나 측정 처리를 추가하지 않았다.
- 이번 차례에서는 전체 354건, Gradle build/lint, 기기 권한 회수 및 화면 조작을 다시 실행하지 않았다. 이들은 구현자 보고와 독립 실행 결과를 구분해야 한다. 스피커·마이크도 조작하지 않았다.
- 200% 글꼴·TalkBack·좁은 화면은 여전히 미검증. `ChipRow`(InstrumentGuideScreen.kt:384–393)는 폭에 맞추는 흐름 배치가 아니라 `chunked(3)` 고정 행이다. 주석의 자동 줄바꿈 보장은 없다. 실제 화면에서 글자/숫자 잘림을 재현한 것으로 주장하지 않는다. 320dp/360dp와 fontScale 2.0에서 모든 칩·수치 접근을 검증하고 필요하면 FlowRow 등으로 바꾼다.
- 정적 증상 카드의 황색 `확인 후보`는 향후 실측 후보와 혼동되지 않도록 EQ-C/E에서 정적 참고임을 구분할 것. 현재 화면은 정적 가이드 문맥이 있으므로 이를 실제 탐지 오작동으로 판정하지 않는다.
- Sources에는 gate/compression 출처 키가 정의되지만 대부분 프로필 sourceIds는 EQ 문헌만 가리킨다. 향후 동작별 출처 표시를 보강하는 편이 낫다. 외부 문헌 내용·URL은 이번 코드/전사 검토 범위에 포함하지 않았다.
- 음향 담당자의 설정값·설명 검토는 여전히 필요하다. 이 검토는 해당 수치가 모든 악기·공간에 적합하다는 청감 검증이 아니다.
- 저장소 production/test 파일은 수정하지 않았고 종료 시 working tree는 clean이었다.

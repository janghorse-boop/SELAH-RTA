## R2-01 — High: 무음 평균을 저장 성공으로 알리고 다시 읽지 못한다

**위치:** `app/src/main/java/kr/joa/selahrta/data/rta/RtaCoverage.kt:146`; `RtaMeasurementStore.kt:47` 및 decode의 유한 수 검사.

새 tap은 `BandAnalyzer.toBandDbfs` 앞에 있다. 기존 경로가 적용하던 무음 바닥값을 지나지 않으므로 0 전력에 그대로 log10을 취한다. 입력을 검증할 때 0은 허용되지만 출력은 `-Infinity`다.

**실행 근거:** 실제 `RtaEngine(48000)`에 무음 PCM 8,192표본을 공급하고 tap의 평균을 실제 저장소로 저장·재개방했다.

```text
R2_SILENCE windows=3 finite=0 first=-Infinity
R2_REOPEN success=true count=0 listing=RtaListing(items=[], unreadable=1)
```

**영향:** 디지털 무음이나 0 전력 대역이 있는 입력에서 저장 성공과 파일 재개방 결과가 모순된다. 마이크가 항상 잡음을 낸다는 전제로 배제할 수 없다. 이 시험은 DSP→저장 경로이며 Android VM 전체 저장 흐름을 실행한 것은 아니다.

**수정:** 기존 `SILENCE_DBFS` 정책을 평균의 최종 dB 변환에 적용한다. 저장소에도 `bandsSpl.all { it.isFinite() }` 검사를 두어 다른 호출자까지 방어한다. 무한대를 임의의 SPL 0으로 바꾸지 않는다.

**회귀:** 전 대역 무음, 한 대역만 0, 매우 작은 양수, 저장 후 새 저장소 인스턴스로 재개방. 제공 패치는 평균 변환만 수정하며 저장소 방어는 별도 권고다.

## R2-02 — Medium: coverage에서 자른 구간 밖의 소리가 평균에는 들어간다

**위치:** `RtaCoverage.kt:100–104,112–116`; `CaptureViewModel.kt:1872,1895,1933`.

`windows++`와 power 합산을 먼저 수행하고 `addSpan`에서만 구간을 자른다. 구간과 전혀 겹치지 않는 창도 평균에는 포함된다. 종료 시 detach도 명령을 큐에 넣고 즉시 반환하므로 완료된 이후 다음 오디오 블록이 명령을 처리하기 전까지 누적기가 닫혔다고 보장할 수 없다.

**실행 근거:** 총 구간 100표본에 [0,100) 전력 1e-6, 완전히 밖인 [100,200) 전력 1을 전달했다.

```text
R2_OUTSIDE coverage=1.0 windows=2 mean=-3.010295613697165
expected mean=-60.0
```

이 수치는 작은 결정적 단위 반례이며 실기기 10초 측정 오차의 실측값이 아니다. 그러나 UI 종료 지연·현재 처리 중인 블록이 추가 창을 내는 경로에서 같은 결함이 발생할 수 있다.

또한 `arm()`은 UI 측정 전환을 본 뒤 호출되고, 그 뒤 **첫 FFT 창의 시작**이 원점이 된다. 첫 창은 arm 이전 표본도 포함할 수 있다. 이 방식은 고정한 UI의 10초와 같은 구간임을 보장하지 않으며, 시작 때 놓친 시간을 원점 이동으로 감출 수 있다.

**수정:** 분석 스레드에서 시작 프레임·끝 프레임을 확정하고, 같은 소유자가 누적을 닫아 불변 결과를 반환하게 한다. 전혀 겹치지 않는 창은 합·개수에도 넣지 않는다. 부분 중첩 창은 전체 창 채택/제외 또는 명시적 추정 가중 중 무엇인지 계약으로 정해야 한다. 창 power를 겹친 길이만큼 곱하는 것만으로 실제 부분구간 에너지를 정확히 복원할 수는 없다.

**회귀:** 완료 후 큰 입력, 마지막 창 부분 중첩, 한 블록에서 여러 FFT, UI 완료 지연, 분석 명령 처리 지연, 실제 시작 프레임과 첫 창의 관계. 제공 패치는 **완전히 구간 밖인 창 거부만** 다루며 전체 경계·detach 계약을 해결하지 않는다.

## R2-03 — Medium: 평균의 분모와 합이 서로 다른 시점의 값이다

**위치:** `RtaCoverage.kt:142–147`; `CaptureViewModel.kt:1895,2223–2226`.

`meanDb`가 `windows`를 잠금 밖에서 읽고 합만 잠금 안에서 읽는다. 그 사이 생산자가 한 장을 더하면 N+1장의 합을 N으로 나눈다. volatile은 개별 값의 가시성을 제공할 뿐 이 둘의 스냅샷을 묶지 않는다. 비동기 detach 때문에 최종 읽기에서도 동시 생산을 배제하지 못한다.

**실행 근거:** 생산자 monitor를 확보한 상태에서 평균 reader가 BLOCKED 된 것을 확인하고, 같은 lock 안에서 두 번째 장을 누적한 뒤 풀었다. reflection은 lock 참조를 얻는 데만 썼으며 sum·windows 값은 직접 바꾸지 않았다.

```text
R2_SNAPSHOT mean=3.010299956639812 windows=2
expected mean=0.0
```

**영향:** 평균과 기록한 개수·coverage가 서로 다른 시점의 값일 수 있다. 두 장 예시의 3.01dB를 정상 235장 측정 오차라고 주장하지 않는다. 같은 경합에서 한 장 차이면 약 `10*log10(236/235)=0.0184dB`이지만 시간 일관성 결함은 남는다.

**수정:** 우선 n과 sum을 같은 잠금 안에서 읽는다. 최종 해법은 분석 스레드에서 detach/close 후 `mean + windows + coveredFrames + origin/end + hop`을 한 결과로 반환하는 것이다. 현재 `averagedFrames`는 새 평균에 사용한 창 수가 아니라 옛 UI 장 수를 저장하므로 의미를 분리하거나 수정한다.

**회귀:** 제공된 결정적 monitor 시험, 종료와 마지막 FFT 경합, snapshot 이후 불변성, 평균의 개수와 메타데이터 일치. 부분 패치는 n/sum 경합만 닫는다.

## R2-04 — Medium: 합성 band-power 시험으로 PCM 위치 불변·참값을 주장한다

**위치:** `AverageDefinitionTest.kt:31,69–96`; `docs/superpowers/specs/2026-09-30-rta-coverage-tap-design.md:237–241`.

시험은 이미 계산된 전력 배열 하나를 다른 인덱스로 옮긴다. 같은 숫자들의 합이 같은 것은 확인하지만 PCM→Hann 창→FFT→밴드 계산을 거치지 않는다. 이 시험으로 “같은 크기의 소리를 자리만 옮겨도 늘 같은 참값”이라고 결론 낼 수 없다.

**실행 근거:** 길이 48,000의 PCM에 진폭 0.5 충격 표본 하나를 넣고, 경계에서 충분히 떨어진 16,384와 17,408 위치를 비교했다. 엔진·평균·PCM 에너지는 동일하고 위치만 다르다. 실제 `RtaEngine`과 새 tap을 통과한 17번 밴드 결과:

```text
R2_IMPULSE a=-71.4780453987058 b=-74.4916739677606
delta=-3.013628569054802 dB
```

**영향:** 비교 신뢰도와 허용 오차의 근거가 과장된다. 50% 겹침 Hann 창에서 제곱 창 가중의 합은 위치별 상수가 아니므로, 모든 FFT를 평균했다고 시간영역 에너지의 정확한 참값이 되는 것은 아니다. 이는 tap을 평활 앞으로 옮긴 개선 자체를 부정하지 않는다.

**수정:** 제품 정의를 “지정한 경계 규칙에 따른 비평활 FFT 밴드 전력 평균”으로 명시하고 참값·임의 위치 불변 주장을 철회한다. 같은 PCM/같은 FFT 창 격자에 대해 블록 크기·UI 발행률만 바꾸는 불변 시험을 추가한다. 별도 기준 계산도 같은 FFT 크기·hop·창·밴드 정의를 사용해야 한다. 물리적인 구간 에너지의 위치 불변을 요구한다면 별도 추정기 설계 문제이며 FFT 길이를 임의로 바꾸는 간단한 수정이 아니다.

**회귀:** 동일 PCM의 다른 청크 크기, 화면 소비 지연, impulse의 hop 내 위치 이동, 구간 앞뒤 burst, 독립 Welch 기준 계산. 제공 위치 이동 시험의 0.1dB 단언은 문서의 “늘 같은 값”을 반박하기 위한 값이며 새 제품 허용 오차 제안이 아니다.

## C·D 진행에 반영할 것

1. **먼저 구간·최종 스냅샷을 고정한다.** 현재 origin 이동과 늦은 누적을 포함한 분포로 거부 문턱을 정하면 구현 지연까지 정상 분포에 섞인다.
2. C에서는 coverage만 수집하지 말고 target/start/end frame, first/last window, windows, hop, sampleRate, 세션/정의 버전, UI·분석 시작/종료 지연을 함께 남긴다. 현재 coverage는 공급된 PCM의 창 구간 합집합이다. 실제 AudioRecord에서 잃은 표본의 물리적 시간까지 자동으로 알아내는 지표는 아니다.
3. D는 정상 분포뿐 아니라 알려진 누락·초반 누락·종료 지연·장시간 고른 지연의 거부 사례로 검증한다. 이번 검토에서 특정 coverage 문턱을 발명하지 않는다. C·D 진행 의사는 확인했으며, 이를 특정 수치의 검증 완료로 해석하지 않는다.

- PDF 반복 경고는 정상 A4에서 본문 공간을 먼저 차지하므로 페이지 나눔 방향이 맞다. 현재 경고 생성기의 경고는 제한돼 있다. 임의로 긴 경고를 자를 때 마지막에 “더 있습니다”만 남기는 정책은 향후 핵심 신뢰 경고를 누락할 수 있어, 핵심 요약은 항상 반복하고 전문을 부록에 남기는 편이 낫다. 이번에는 별도 재현 결함으로 세지 않았다.

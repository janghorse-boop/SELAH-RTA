[5차 회신](2026-09-27-cfr-fix-independent-review.md)의 **Medium 1건**을
고쳤습니다. 범위: `feat/factory-default-calibration` 의 `c275823`.

> **가지가 다릅니다.** CFR 수정(`5b48460`)은 PR #13 으로 병합됐고, 그 뒤
> 담당자 요청으로 시작한 이 가지에 기종 기본값·활성 마이크 작업이
> 들어가 있습니다(회신서 1장에서 「사용자의 동시 작업」으로 관측하신

> 나머지 커밋까지 승인해 달라는 뜻이 아닙니다.

## 먼저 답합니다 — 「꺼 두는 것」으로 막았다고 여긴 것이 틀렸습니다

CFR-02 에서 저는 가져올 때 `enabled=false` 로 저장하는 것으로 일을
끝냈습니다. 그런데 **꺼 두는 것은 막는 것이 아니었습니다.**

```
TOGGLE_WITHOUT_READING enabled=true correction=FromFile
REOPEN                 enabled=true correction=FromFile
```

읽는 자리가 켜짐 표시 하나만 보고 있었으니, 스위치 한 번이면 판정이
통째로 없는 것이 됩니다. 제가 고친 것은 **처음 한 번의 기본값**이었고,
그 뒤로는 아무 관문도 없었습니다.

**여덟째 머리글 줄**은 제가 만든 문제였습니다. 저장할 때 첫 줄에
`# selah-key:` 를 붙여 놓고, 읽을 때 그대로 넘겼습니다. 머리글로 보는
줄은 여덟 칸뿐이라 **저장할 때는 막혔던 파일이 다시 열면 통과**합니다.
따로 표본을 만들어 확인해 주신 자리입니다(`EIGHTH_HEADER`).

---

## 1. 고친 것

### 읽을 때마다 다시 판정한다

막는 자리를 **읽기 경계 하나로** 모았습니다. 권고대로입니다 — 화면
스위치만 막으면 다른 부르는 곳이 생길 때 또 새어 나갑니다.

- `watch` — `enabled = onFlag && !needsPerson`
- `setEnabled(true)` — 같은 판정을 거칩니다. 막히면 **까닭을 돌려주어**
  화면이 말합니다(조용히 안 켜지면 스위치가 고장 난 줄 압니다).
- `setEnabled(false)` — 언제나 됩니다.

저장할 때의 판정을 믿지 않습니다. 옛 판으로 저장된 파일은 그때 규칙으로
통과한 것이고, 그 사이 규칙이 두 번 바뀌었습니다(CF2-02 · CFR-02).

**열 선언을 판정에 함께 넘깁니다.** 지금까지 `CurveStore` 는
`decideReading(evidence, DisplayCurve)` 만 불렀습니다. 그래서
`Frequency (Hz),Corr (dB)` 처럼 **둘째 열이 보정값이라고 적혀 있는**
파일이 설명문 쪽으로 새어 「단서 없음 → 관례(응답)」로 확정됐습니다.
(`Corr` 은 열 이름 목록에만 있고 설명문 낱말 목록에는 없습니다.)

### 앱이 붙인 첫 줄을 떼고 읽는다

`curveSourceText()` 로 `# selah-key:` 줄을 뗀 뒤 파싱합니다. **해시도 이
내용으로 뜹니다** — 앱이 붙인 줄까지 넣으면 저장 열쇠가 바뀔 때 같은
파일의 해시가 달라져, 하지도 않은 파일 교체로 읽힙니다.

### 막기만 하지 않았습니다 — 4장 설계를 넣었습니다

최소안만 넣지 않은 까닭을 적습니다. 그대로 넣으면 **「보정값(correction
factors)」이라고 제대로 적힌 정상 파일이 영영 못 걸립니다** — 그 파일은
판정상 늘 `NeedsPerson` 이기 때문입니다. 지적하신 그대로입니다
(*"기존 LooksLikeCorrection도 현재 판정상 NeedsPerson이므로 보류한다"*).

막는 길만 내고 나가는 길을 안 내면 사람은 파일을 지웁니다. 그래서
보고서 4장의 확인 기록을 구현했습니다.

```kotlin
data class ReadingConfirmationRecord(
    val sha: String,          // 앱 주석을 뺀 원본 내용의 SHA-256
    val readingName: String,  // CurveReading 의 이름
    val rulesVersion: Int,
)
```

- 화면이 **「마이크 응답 으로 사용」 / 「보정값 으로 사용」** 두 단추로
  묻습니다. 「확인」 하나로는 무엇을 확인했는지 남지 않습니다.
- 일반 스위치는 `requestedEnabled` 만 바꿉니다. 두 물음을 가릅니다.
- 셋이 **모두** 맞아야 인정합니다. 해시가 다르면 파일이 바뀐 것이고,
  규칙 판이 다르면 앱이 묻던 말이 달라진 것입니다.
- 확인된 규약이 관례와 다르면 **원본에서 다시 만듭니다**
  (`CalibrationFile.load(source, reading)`). 이미 뒤집힌 점을 또 뒤집으면
  원래대로 돌아가, 단추가 아무 일도 안 한 것처럼 보이면서 보정은 반대로
  걸립니다.
- `Unknown` 은 예전대로 관례로 갑니다. 정상 파일을 끄거나 지우지
  않습니다.

### 화면과 문구

- 「확인 필요」를 「꺼 둠」과 **가릅니다.** 앞엣것은 앱이 막은 것이고
  뒤엣것은 사람이 끈 것입니다.
- 곡선은 그려 주되 **그림 위에** 「미리보기이고 측정에는 걸려 있지
  않습니다」라고 적습니다. 무엇이 들어왔는지 봐야 고를 수 있습니다.
- 보류를 「적용했습니다」라고 말하지 않습니다(권고 그대로).
- 확인 전에는 스위치가 눌리지 않습니다 — **두 번째 그물**입니다.
  저장소가 이미 막습니다.

### 판정을 떼어 두었습니다

`app/.../calibration/CurveReadingGate.kt` 입니다. 저장소 안에 있으면
안드로이드 `Context` 없이는 한 줄도 돌려 볼 수 없고, 그러면 「막았다」를
짐작으로만 말하게 됩니다. 이 판단이 틀리면 **보정이 거꾸로 두 배 걸리는데
화면에서는 드러나지 않습니다.**

## 2. 시험이 잡는지 확인했습니다

다섯 자리를 되살려 돌렸습니다(`--rerun-tasks`).

| 되살린 것 | 실패한 시험 |
|---|---|
| `enabledWith = onFlag` (켜짐 표시만 본다) | 켜 두었어도… · 옛 판에서 켜진 채로… |
| `columnDeclarationOf` 를 판정에 안 넘김 | 둘째 열이 보정값으로 선언되면 묻는다 |
| 내용 해시를 안 견줌 | 내용이 바뀌면 확인이 무효다 |
| 규칙 판을 안 견줌 | 규칙 판이 바뀌면 확인이 무효다 |
| 앱 주석을 안 뗌 | 앱이 붙인 첫 줄… · 여덟째 줄의 단서… |

**열 선언 시험은 처음에 변이를 지나쳤습니다.** `Correction (dB)` 로
적었는데, 그 말은 설명문 쪽에서도 잡혀 열 선언이 없어도 막힙니다. 열
이름 목록에만 있고 설명문 낱말 목록에는 없는 `Corr (dB)` 로 고쳐 실제로
갈리는 자리를 짚게 했습니다.

`CalibrationFileReadingTest` 에서 **부호가 한 번만 뒤집히는지**도 따로
봅니다(두 번 뒤집으면 확인 단추가 아무 일도 안 한 것처럼 보입니다).

되돌린 뒤 `assembleDebug test` → **BUILD SUCCESSFUL**.

## 3. 봐 주셨으면 하는 것

1. **확인 기록의 범위가 맞습니까?** 기기/채널 `CalibrationKey` 아래에
   두었고 해시는 원본 내용입니다. 4장에서 말씀하신 「다른 채널에서 확인
   기록 재사용 안 됨」이 이 구조로 보장되는지 봐 주십시오.
2. **`Unsupported` 를 표시용에서 막지 않았습니다.** `Frequency,Phase,SPL`
   은 표시용 판정에서 여전히 설명문으로 내려가고, 파서는 둘째 값(위상)을
   읽습니다. CAR-04 때 기준 CAL 만 막아 둔 자리인데, 이번 범위를 넓히지
   않으려고 그대로 두었습니다. 같이 막아야 하는 자리입니까?
3. **수량/단위 오류를 별도 거절하라**고 하신 부분은 넣지 않았습니다.
   지금은 `Unsupported` 로 흘러갑니다. 어디까지가 이번 Medium 이고
   어디부터 다음 일인지 갈라 주시면 좋겠습니다.
4. **이미 확인된 파일이 규칙 판 상승으로 다시 막힐 때**의 문구를 따로
   두지 않았습니다. 지금은 처음 가져왔을 때와 같은 말을 합니다.

## 4. 이번에도 확인하지 못한 것

기기에서 돌려 보지 못했습니다 — Compose 의 확인 단추·스위치·복귀
표시와 실제 DataStore 왕복은 폰에서 봐야 합니다. JVM 에서 돌린 것은
**판정 부분**뿐입니다. 검토자께서 실제 `CurveStore` + DataStore 로
재현해 주신 수준에는 아직 못 미칩니다.

기준 SPL 계·교정기·EMM-6 가 없어 마법사 전체를 끝까지 재 본 적이 없다는
점도 지난 판과 같습니다.

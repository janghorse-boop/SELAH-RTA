# 세로 화면을 거꾸로도 — 자동 / 정상 고정 / 거꾸로 고정

- 날짜: 2026-10-03
- 요구(담당자, 「코덱스 검토」 창): 「핸드폰 마이크로 측정할 때 아래쪽을 스피커로 향하면 세로 화면 자체가
  거꾸로 되어야 보기 편하다. 뒤집어도 방향이 바뀌지 않는다. 검토 의견을 주고 Claude Code 에도 반영되게
  해 달라.」
- 검토 의견: 「코덱스 검토」가 정리한 의견(`inbox/2026-10-03-phone-reverse-portrait-review.md`, inbox 라
  커밋하지 않는다)의 요지를 아래에 옮겼다.
- 결론: 분석 밖의 세로 화면에 **자동 / 정상 고정 / 거꾸로 고정**을 두고 선택을 저장한다. 기본은 자동.
  분석 구역은 그대로 가로 양방향.

## 원인

`ui/Orientation.kt` 의 기본 방향이 `SCREEN_ORIENTATION_PORTRAIT`(정상 세로만)였다. 폰을 뒤집어도 앱이
거꾸로 세로를 요청하지 않으니 화면이 따라오지 않았다.

## 왜 셋인가 — 자동 하나로 끝나지 않는다

- **자동**(`SENSOR_PORTRAIT`): 센서를 따라 정상·거꾸로 세로를 오간다. 그러나 Android 문서는 이 값도
  기기 설정에 따라 거꾸로 세로를 허용하지 않을 수 있다고 적는다. 그래서 **상수 한 줄로 해결됐다고 보지
  않는다.**
- **탁자·거치대에 눕혀 두면** 센서가 사람이 읽는 쪽을 정하지 못한다. 폰을 다시 들어 올리지 않고 고칠 길이
  있어야 한다 — 그래서 **거꾸로 고정**(`REVERSE_PORTRAIT`)과 **정상 고정**(`PORTRAIT`)을 함께 둔다.
- 앱 전체를 `fullSensor` 로 바꾸지 않는다. 「분석만 가로, 나머지는 세로」 규칙(2026-10-01 담당자 지시)이
  무너진다. 화면 그림만 돌리는 방식도 쓰지 않는다 — 대화상자·키보드·시스템 막대가 따로 논다.

## 규칙을 한 자리에

[`orientationFor(inAnalysis, portrait)`](../../app/src/main/java/kr/joa/selahrta/ui/Orientation.kt) 하나가
시작·설정 바꾸기·분석 드나들기의 방향을 모두 정한다.

예전 `LockLandscape` 는 분석에 들어갈 때 **돌아갈 값을 미리 붙잡아** 두었다. 세로 선택이 생기면 그 값이
낡을 수 있다(분석 중 설정이 바뀌어 도착하면 옛 값으로 돌아간다). 그래서 `ApplyOrientation` 이 두 값이
바뀔 때마다 **지금 값으로 다시 묻는다.**

## 화면 방향은 마이크 선택이 아니다

화면을 뒤집는 것은 어느 마이크로 재는지를 바꾸지 않는다. 「하단 마이크로 변경」처럼 적지 않는다. 실제로
쓰는 입력은 기존 경로 확인이 가린다(`getAddress()` 이름은 표기일 뿐 물리 위치가 아니다 — CLAUDE.md 7장).

## 확인한 것과 남은 것

- JVM: 방향 규칙(분석은 가로, 세로 셋의 매핑, 기본 자동, 분석을 나오면 지금 선택, 저장 이름 되살리기·모르면
  자동) — `OrientationPolicyTest`.
- **실기기 몫**(아직): 자동 전환이 실제로 일어나는지, 시스템 회전 잠금과의 관계, 탁자 위에서, 거꾸로 세로에서
  큰 숫자·차트·단추·대화상자·키보드·상태바/내비게이션 막대·컷아웃·터치 위치, 회전 중 캡처·재생이 끊기지
  않는지(매니페스트가 `orientation|screenSize` 를 스스로 처리하지만 실제로 보지 않았다).
- 저장된 선택은 비동기로 오므로 앱을 켤 때 잠깐 기본값(자동)으로 섰다가 맞춰질 수 있다.

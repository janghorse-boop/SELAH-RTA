# EMM-6 CAL 파일의 둘째 열을 어떻게 읽는가

날짜: 2026-09-23 · 계기: 독립 검토 R04

## 무엇이 문제였나

앱은 보정 파일의 둘째 열을 **마이크의 응답**으로 보고 측정값에서 뺀다.
어떤 제조사는 **이미 뒤집힌 보정값**을 준다. 뒤바꿔 읽으면 보정이 반대로
두 배 걸린다 — 적힌 값이 +2dB 면 실제 오차는 4dB 다.

그런데 **곡선은 멀쩡해 보인다.** 기존 경고는 ±30dB 를 넘을 때만 뜨는데,
측정 마이크 파일은 대개 ±5dB 안쪽이라 부호가 반대여도 조용히 통과한다.

## 실제 파일에서 관찰한 것

담당자가 건넨 EMM-6 개별 CAL 파일(`inbox/17860.txt`, **저장소에 올리지
않는다**)을 열어 보았다.

| 항목 | 값 |
|---|---|
| 머리글 | `*1000Hz  -41.1` 한 줄 (1kHz 감도, dBV/Pa 로 보인다) |
| 점 수 | 256 |
| 20 Hz | −2.0 dB |
| 1 kHz | 0.0 dB |
| 10 kHz | +3.0 dB |
| 20 kHz | +4.1 dB |

머리글에 `response`·`correction` 같은 말이 **없다.** 그래서 글자만 보는
판정([`signEvidenceOf`])은 「모름」이다.

## 값 자체가 주는 단서

모양이 **1kHz 에서 0 으로 맞춰지고 고역으로 갈수록 올라간다.** 작은
측정용 캡슐은 대체로 저역이 조금 모자라고 고역이 솟는다(다이어프램 앞의
압력 상승과 캡슐 공진). 그 마이크의 **응답**을 적은 파일이라면 이 모양이
그대로이고, 이미 뒤집은 **보정값**이라면 거울상(저역이 솟고 고역이
내려감)이어야 한다.

즉 **응답 쪽에 무게가 실린다.** 다만 이것은 단서이지 확인이 아니다 —
마이크마다 다르고, 정규화 자리도 다르다.

## 정한 것

1. 읽는 법을 **값으로 들고 다닌다**(`CurveReading`). 보정값이면 곡선을
   만들 때 한 번 뒤집고, 나머지 계산은 손대지 않는다.
2. **걸린 것의 크기로 가른다.**
   - RTA 막대에 거는 표시용 곡선: 단서가 없으면 관례(응답)대로 간다.
   - **교정의 기준이 되는 CAL**: 단서가 없으면 **사람에게 묻는다.** 그
     파일로 만든 프로파일이 전부 같은 방향으로 틀어지기 때문이다.
   - 머리글이 우리 가정과 **반대**를 가리키면 용도와 상관없이 묻는다.
3. 화면에 **단서를 곁에 둔다**(`CalReadingCard`): 머리글에서 찾은 것과
   곡선 모양(저·중·고 세 점). 숫자를 먼저, 뜻은 뒤에 — 순서를 바꾸면 앱이
   정해 준 것처럼 읽힌다.

## 아직 확인하지 않은 것

- **제조사 문서로 확인하지 않았다.** 위의 모양 추론은 물리적 개연성이지
  규약 확인이 아니다. Dayton/Cross-Spectrum 이 이 파일 형식을 무엇으로
  적는지 문서에서 확인해야 한다.
- 머리글의 `-41.1` 이 1kHz 감도라는 것도 **읽어서 그렇게 보이는** 것이고,
  앱은 그 값을 쓰지 않는다. 절대 음압 교정과 엮으려면 따로 확인해야 한다.

# ND-9 음압 교정기 — 114 dB 단 고장 · 94 dB 로 교정 완료

**판정: 교정기의 114 dB 단을 쓰지 않는다.** 약 **9 dB 모자라고**, 거기에 **±1.5 dB 로 흔들린다.**
94 dB 단은 재현되어(0.4 dB) 그쪽으로 교정했다.

잰 날: 2026-10-01 · 체인: EMM-6 → UMC404HD(Input 1, 팬텀 +48V) → USB-C → SM-S918N

---

## 1. 교정 결과 (지금 걸려 있는 값)

```
기기        USB-Audio - UMC404HD 192k (card=1;device=0) · Input 1
기준        교정기 94 dB (1kHz 순음)
읽은 값     -31.2 dBFS (최근 3초 평균, 흔들림 0.1dB)
오프셋      125.3 dB
확인        화면이 94.0 ~ 94.2 dB(A) 로 읽는다
```

**114 검증은 건너뛰었다.** 건너뛴 까닭이 이 문서 전체다.

> **GAIN 손잡이를 돌리면 이 교정은 무효다.** 교정이 저장한 것은 「지금 이 게인에서
> 94 dB 이 −31.2 dBFS 로 들어온다」이기 때문이다. **그런데 무효가 되어도 앱은
> 아무 말도 하지 않는다** — 화면은 계속 그럴듯한 숫자를 보여준다. 손잡이 위치를
> 테이프나 사진으로 남겨 둘 것.

## 2. 왜 114 를 믿지 않는가

교정기의 두 단은 **정확히 20 dB** 차이여야 한다. 오늘 잰 값은 한 번도 20 근처에 가지 않았다.

**마지막 측정** — 게인을 내려 CLIP 을 끄고, 풀스케일까지 23 dB 을 비우고, 밀봉된 통으로:

| | 1회 | 2회 | 재현성 |
|---|---|---|---|
| **94 dB** | −31.5 | −31.2 | **0.3 dB** ✓ |
| **114 dB** | −22.9 | −20.0 | **2.9 dB** ✗ |

**114 − 94 = 8.6 ~ 11.5 dB** (있어야 할 값 20)

같은 결합·같은 게인에서 **94 는 붙박이고 114 만 흔들린다.** 제대로 된 교정기는
±0.5 dB 안에 있어야 한다.

하루 동안 쌓인 모든 쌍이 같은 말을 한다. 20 근처는 한 번도 없었다.

| 조건 | 114 − 94 |
|---|---|
| EMM-6, 첫 쌍 | 11.0 dB |
| EMM-6, 다시 끼움 | 10.6 dB |
| EMM-6, **배터리 교체 뒤** | 9.2 dB |
| 폰 내장 마이크 (장비 하나도 안 거침) | 7.4 ~ 13.1 dB |
| EMM-6, PAD 누름 | 11.3 dB |
| EMM-6, PAD 풀림 | 10.4 dB |
| **EMM-6, 게인 내림 · CLIP 꺼짐** | **8.6 ~ 11.5 dB** |

## 3. 다른 의심을 어떻게 지웠나

**교정기를 탓하기 전에 우리 쪽을 먼저 의심했다.** 쉬운 결론은 남의 장비 탓이고,
그게 틀렸을 때 치르는 값이 가장 크다 — 멀쩡한 기구를 버리고 진짜 고장은 남는다.

| 의심 | 어떻게 지웠나 |
|---|---|
| **앱의 dB 계산** | `MeterLinearityTest` 4개 — 진폭 10배를 정확히 20.00 dB 으로 읽는다 |
| **측정기가 20 dB 을 못 본다** | PAD 로 **진짜 20 dB 한 칸**을 넣어 19.5 dB 로 읽어냈다 |
| **배터리 약함** | 새 9V 로 교체 → 차이 그대로(10.6 → 9.2) |
| **마이크·프리앰프** | 폰 내장 마이크(완전히 다른 캡슐·프리앰프·ADC)도 같은 말 |
| **프리앰프 과입력** | 게인 내려 CLIP 끄고 재측정 → 20 으로 돌아오지 않고 오히려 줄었다 |
| **결합이 움직였다** | 94 를 세 번 따로 끼워 −31.5 / −31.2 / −31.1 |

**「20 dB 이 10 dB 으로 보인다」는 처음에 계산 실수의 지문처럼 보였다** — 진폭에
`20·log10` 을 써야 할 자리에 `10·log10` 을 쓰면 모든 차이가 정확히 반으로 접힌다.
그래서 코드부터 봤고, 읽은 것으로 끝내지 않고 시험으로 돌려 **결백을 확인**했다.
그 시험은 남겼다(아래 5장).

**PAD 를 쓴 방법이 열쇠였다.** PAD 가 정확히 몇 dB 인지 몰라도 된다 — **같은 단추를
94 에서 한 번, 114 에서 한 번** 재서 두 값을 견주면 「체인이 큰 소리에서 눌리는가」가
바로 나온다. 결과는 19.5 / 18.6 으로, 압축은 **1 dB 미만**이었다. 1 로는 9 를
설명할 수 없다.

## 4. 아직 확인하지 못한 것

- **94 단이 맞다는 보증이 없다.** 견줄 두 번째 기준기가 없었다. 94 를 고른 근거는
  **재현성**(0.4 dB)과 **고장 양상**(큰 쪽만 못 내고 작은 쪽은 멀쩡한 것이 흔하다)
  이지, 잰 값이 아니다. 소음계나 다른 교정기가 생기면 **가장 먼저 이것을 맞대 볼 것.**
- **주파수 응답 곡선이 없다.** 1kHz 한 점의 크기만 맞았고 모양은 마이크 그대로다.
  앱도 화면에서 그렇게 적고 있다.
- **교정기는 점검 또는 교체가 필요하다.** 114 단이 저 상태면 수리 전까지 그 단은
  어떤 용도로도 쓰지 않는다.

## 5. 남긴 시험

`dsp/src/test/kotlin/kr/joa/selahrta/dsp/MeterLinearityTest.kt`

한 번 가르고 버릴 시험이 아니다. 「계기가 레벨에 선형이다」는 소음계의 바닥
가정이고, 여기가 어긋나면 **그 위의 모든 숫자가 조용히 틀린다** — 교정 오프셋도,
Leq 도, RTA 밴드도. 오늘은 이 자리를 의심하는 데 한나절이 들었다.

## 6. 다시 재는 법

```
1. EMM-6 를 교정기 통에 끝까지 끼운다 (자유공간으로 들고 재지 않는다 —
   손으로 잡으면 94/114 사이에 결합이 5.7dB 까지 움직였다)
2. UMC404HD Input 1 · 팬텀 +48V · LINE · PAD 와 GAIN 은 건드리지 않는다
3. 앱 설정 → 측정 기기가 UMC404HD 「사용 중」인지, 그리고 바로 아래
   「이 기기의 보정」이 **같은 기기**를 가리키는지 확인한다
4. 교정기 94 를 켜고, 「보정에 쓸 값」이 10초 동안 0.3dB 안에 머무는 것을 본 뒤
   [교정기 94 dB] 를 누른다
5. 화면이 94.0 dB(A) 로 읽히면 끝이다
```

> **누르기 전에 값부터 본다.** 오늘 한 번은 교정기가 꺼진 줄 모르고 누를 뻔했다
> (−93.9 dBFS). 그대로 눌렸으면 오프셋이 187.9 dB 로 저장되어 **모든 음압이
> 63 dB 씩 부풀고도 화면은 멀쩡해 보였을 것이다.**

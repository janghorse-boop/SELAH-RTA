# RTA 측정 저장과 겹쳐 보기 — 설계

담당자 지시(2026-09-29). 지시서 §7 에 해당한다.

> **저장 목적은 같은 위치에서 좌우와 양쪽 출력을 비교하고, 이후 조정 전후
> 결과까지 다시 확인하는 것**이다.

## 0. 이 문서가 정하는 것과 안 정하는 것

담당자가 **무엇을 어떤 단위로 저장하고 어디서 비교할지**를 정해 주었다.
**저장 기술과 구현 세부는 코드를 확인한 뒤 내가 고른다** — 그 결정과 까닭을
7장에 모았다. 틀렸으면 그 장만 보면 된다.

---

## 1. 저장 단위 — 「측정 결과 1개」

저장 버튼을 누르면 **평균 처리가 끝난 곡선**과 그때의 측정 조건을 함께
남긴다.

| 저장 항목 | 예 |
|---|---|
| 이름 | 본당 중앙 · L |
| 측정 곡선 | 주파수별 측정 레벨(31밴드) |
| 테스트 신호 | 핑크 노이즈 |
| 출력 채널·레벨 | L · −20 dBFS |
| 측정 조건 | 입력 장치, 보정, 평균 시간, 분석 설정 |
| 측정 시각·메모 | 측정 날짜, 마이크 위치 등 |

**그림이 아니라 곡선 값을 저장한다.** 그래야 나중에 겹쳐 보거나 좌우 차이를
셈할 수 있다. **앱을 껐다 켜도 남아야 한다.**

## 2. 묶는 단위 — 「비교 세트」

```
비교 세트: 본당 중앙 · 조정 전
  ├── L 측정
  ├── R 측정
  └── L+R 측정

비교 세트: 본당 중앙 · EQ 조정 후
  ├── L 측정
  ├── R 측정
  └── L+R 측정
```

- 첫 저장 때 세트를 만들고, 이어 저장하는 채널은 같은 세트에 넣는다.
- **세 채널을 다 재야만 저장되는 구조로 만들지 않는다.** 한 채널만 있어도
  그대로 쓸모가 있다.
- 같은 채널을 다시 재면 **덮어쓰지 않고 새 기록으로 쌓는다.** 비교 화면에서
  어느 것을 쓸지 고른다.

## 3. 보여 주는 자리 — RTA 화면 안

별도 기록 탭을 새로 만들지 않고 RTA 에 **「저장된 측정」** 단추를 둔다.

1. 테스트 신호를 틀고 RTA 로 간다.
2. L·R·L+R 을 각각 재고 저장한다.
3. 「저장된 측정」에서 비교 세트를 고른다.
4. 지금 RTA 그래프에 저장 곡선을 겹쳐 본다.

실시간 곡선과 저장 곡선을 **각각 켜고 끌 수 있게** 하고, 저장 곡선에는
채널과 측정 시각을 적는다.

## 4. 기존 FR 기록과의 관계

**사용자 화면에서는 RTA 측정 기록으로 구분한다.**

코드를 확인한 결과 **FR 은 아무것도 저장하지 않는다** — 한 번 재고 화면에
띄우고 끝난다. 그러므로 지금 당장 합칠 기록이 없다.

그래도 **측정 방식을 처음부터 적어 둔다**(`method: "rta" | "sweep" | …`).
일반 RTA 곡선과 Sweep 분석으로 얻은 응답은 **재는 방식이 다르므로 이름만
보고 같은 자료로 다루면 안 된다.** 나중에 FR·Sweep 을 같은 저장소에 넣게
되면, 그때 이 칸이 둘을 가른다.

## 5. 초기 구현 범위

- 개별 측정 저장, 앱을 다시 켠 뒤 불러오기
- 비교 세트 만들기·이름 바꾸기·지우기
- L·R·L+R 곡선 겹쳐 보기
- 곡선별 보이기·숨기기
- **측정 조건이 다를 때 안내**

## 6. 이번에 하지 않는 것

자동 차이 표시, 안내형 측정 순서, 내보내기. 뒤에 더한다.

## 7. 내가 고른 것과 까닭

### 7-1. 저장 기술 — `SessionStore` 와 같은 방식(파일 + 원자적 바꿔치기)

DataStore(Preferences)는 보정·곡선 설정이 쓰고 있지만 **31칸 실수 배열을
여러 벌 담기에 맞지 않는다.** Room 을 새로 들이는 것도 이 크기에 과하다.

기록 탭의 `SessionStore` 가 이미 쓰는 방식을 따른다: **기록마다 폴더 하나,
겉장을 `.tmp` 로 쓴 뒤 이름을 바꾼다.** 쓰다 죽으면 겉장이 아예 없는 상태로
남아 **반쯤 쓰인 겉장을 읽는 일이 없다.** 이 저장소가 이미 믿고 쓰는
성질이다.

`schemaVersion` 을 겉장 첫 줄에 적는다 — `SessionMeta` 와 같은 규칙이다.

### 7-2. 평균 — `MeasurementTap` 을 그대로 쓴다, 230장(약 10초)

**한 장만 저장하면 이 기능이 통째로 쓸모없어진다.** 핑크 노이즈는 장마다
밴드 값이 흔들려서, 같은 자리에서 두 번 재도 몇 dB 씩 다르게 나온다. 그
둘을 겹쳐 놓고 「좌우가 다르다」고 읽으면 **없는 차이를 보는 것**이다.

`MeasurementTap` 이 이미 **31밴드 값을 장마다 모으고** 있고 FR 이 그것으로
응답을 잰다. 새로 만들지 않고 그대로 쓴다.

장수는 FR 과 같은 **230장**(48kHz·FFT4096·50% 겹침에서 약 10초)으로 둔다.
방을 핑크 노이즈로 재는 데 이 저장소가 이미 고른 값이고, **같은 값을 쓰면
FR 로 잰 것과 RTA 로 잰 것을 나중에 견줄 여지가 남는다.**

> **담당자 확인이 필요한 자리**: 저장 한 번에 **약 10초**가 걸린다.
> L·R·L+R 을 재면 30초다. 더 짧아도 되면 줄인다 — 다만 짧을수록 저역이
> 덜 가라앉는다.

### 7-3. 「측정 조건이 다를 때 안내」의 기준

무엇이 다르면 알릴지 정해야 한다. **잰 값을 실제로 움직이는 것만** 본다:

| 다르면 알린다 | 왜 |
|---|---|
| 입력 장치 | 마이크가 다르면 곡선이 통째로 다르다 |
| 보정 상태·출처 | 보정 안 된 값과 된 값은 같은 축이 아니다 |
| 주파수 보정 곡선 | 걸린 것과 안 걸린 것은 다른 자료다 |
| FFT 길이·표본율 | 밴드 에너지 셈이 달라진다 |
| 평균 장수 | 흔들림의 크기가 다르다 |

**출력 채널과 레벨은 알리지 않는다** — 그것이 다른 것이 바로 비교하려는
까닭이다.

**막지 않고 알리기만 한다.** 현장에서는 조건이 조금 다른 것을 알면서도
견줘 봐야 할 때가 있다. 막으면 사람이 앱 밖에서 눈으로 견준다.

### 7-4. 기록 탭에 넣지 않는 까닭

기록 탭은 **두 시간짜리 측정 세션**(소리 파일·타임라인 포함)을 다루는
자리다. RTA 한 장은 성격이 다르고, 섞으면 목록에서 서로를 덮는다.
담당자 지시대로 RTA 화면 안에 둔다.

---

## 8. 확인하지 못하는 것

- 실제 예배당에서 10초 평균이 **충분히 가라앉는지**. 저역은 더 걸릴 수 있다.
- 저장 곡선이 실시간 곡선 위에 겹쳤을 때 **눈에 갈리는지**(색·굵기).
- 기록이 많아졌을 때 목록이 쓸 만한지.

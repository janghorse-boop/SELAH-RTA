# A/C/Z 가중치 — 화면별 설정과 표기 통일

**날짜**: 2026-09-27
**지시서**: `SELAH_RTA_Weighting_ACZ_Implementation_Guide.md` (2026-09-27 수령)
**담당자 결정**: 3줄 묶음 · L 기호 표기 · Session Leq 추가 · FR 은 Z 고정 · Window 는 Hann 고정

---

## 1. 왜 하는가

가중치 자체는 이미 제대로 구현되어 있다. IEC 61672-1 의 아날로그 전달함수를
biquad 로 옮겼고, 1kHz 에서 정확히 0dB 이며, 10Hz~5kHz 에서 규격과 A 는
0.3dB·C 는 0.2dB 안에 든다. 지시서 §12 가 경고한 「화면에 숫자를 더하는
방식」이 아니다.

고쳐야 할 것은 **그 사실이 화면에 제대로 드러나지 않는 것**이다.

1. **표기가 어긋난다.** `dBA` · `dBC` · `dB(Z)` — Z 만 괄호가 있다.
2. **분석 화면이 제 잣대를 말하지 않는다.** RTA·Spectrum·Spectrogram 은
   Z-weighting 으로 보는데(그게 맞다), 화면에 그 말이 RTA 타일 하나에만 있다.
3. **가중치가 앱 전체에 하나뿐이다.** 음압을 C 로 보려고 바꾸면 RTA 까지
   따라 바뀔 자리가 없고, 반대로 RTA 만 A 로 보고 싶어도 길이 없다.
4. **Session Leq 가 계산되는데 화면까지 오지 않는다.**
   `SplEngine` 이 `leqSessionDbfs` 를 내놓지만 받는 곳이 없다.

## 2. 용어 — **A-weighting · C-weighting · Z-weighting**

세 가중의 이름을 이 세 낱말로만 부른다. **「Z 가중」·「무가중」·「가중
없음」·「Flat」은 쓰지 않는다** — 같은 것을 네 가지로 부르고 있었고, 그
때문에 「고정된 Z 와 무가중이 다른 것인가」라는 물음이 실제로 나왔다.

| 가중 | 이름 | 단위 |
|---|---|---|
| A | `A-weighting` | `dB(A)` |
| C | `C-weighting` | `dB(C)` |
| Z | `Z-weighting` | `dB(Z)` |

**이름은 이름이고 설명은 설명이다.** Z 가 평탄하다는 사실은 이름이 아니라
설명 줄에서 말한다(§4) — 이름 자리에 「무가중」을 끼워 넣으면 다시 두
가지가 된다.

지시서 §2 의 표기와 같다.

### Z-weighting 은 무엇인가

Z 는 "zero"에서 온 이름이고, 주파수에 따라 깎거나 올리지 않는 평탄한
응답을 뜻한다. 이 앱의 Z 는 필터를 아예 거치지 않는 통과다
(`Z 가중은 아무것도 바꾸지 않는다` 시험 — 시험 이름도 함께 고친다).
규격의 Z 는 10Hz~20kHz 대역 제한이 붙지만 폰 마이크는 그 밖을 내지
못하므로 실질적으로 같다. 다른 점은 이것뿐이다.

## 3. 표기

`Weighting` 의 두 값만 고치면 화면 11군데가 따라온다.

```kotlin
enum class Weighting(val labelKo: String, val unitSuffix: String) {
    A("A-weighting", "dB(A)"),
    C("C-weighting", "dB(C)"),
    Z("Z-weighting", "dB(Z)"),
}
```

| 가중 | 이름: 지금 → 바꿀 것 | 단위: 지금 → 바꿀 것 |
|---|---|---|
| A | `A 가중` → **`A-weighting`** | `dBA` → **`dB(A)`** |
| C | `C 가중` → **`C-weighting`** | `dBC` → **`dB(C)`** |
| Z | `무가중 (Z)` → **`Z-weighting`** | `dB(Z)` (그대로) |

Leq 와 PEAK 은 L 기호 꼴을 함께 쓴다. 계산에 쓴 가중에서 글자가 나오므로
**표기와 실제가 어긋날 수 없다**(지시서 §10).

| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| Leq 타일 이름 | `Leq (1분)` | `LAeq 1분` / `LCeq 1분` / `LZeq 1분` |
| Leq Session | (없음) | `LAeq Session` |
| PEAK 타일 이름 | `PEAK` | `LZpeak` / `LCpeak` / `LApeak` |
| PEAK 타일 단위 | `dB · 가중없음` | `dB(Z)` (PEAK 줄의 가중을 따름) |
| RTA 「그 레벨」 단위 | `dB · 가중 없음` | `dB(Z)` (분석 줄의 가중을 따름) |
| FR 화면 | (표시 없음) | `dB(Z) 고정` |

기호 조립은 한 함수에서 한다:

```kotlin
/** LAeq · LZpeak 처럼 L 기호 꼴로 적는다. */
fun Weighting.leqLabel(windowKo: String): String   // "LAeq 1분"
fun Weighting.peakLabel(): String                  // "LZpeak"
```

## 4. 가중을 고르는 자리 — 세 줄

설정 「측정 설정」 아래에 세 줄. 각 줄에 `[A] [C] [Z]` 와 「기본값으로」.

| 줄 | 이름 | 걸리는 곳 | 기본 |
|---|---|---|---|
| **음압** | `splWeighting` | SPL 큰 숫자 · Leq · MIN · MAX | **A** |
| **순간최고(PEAK)** | `peakWeighting` | PEAK 타일 | **Z** |
| **주파수 분석** | `analysisWeighting` | RTA · Spectrum · Spectrogram | **Z** |

**저장 열쇠는 `splWeighting` 만 지금 것(`"weighting"`)을 이어받는다.** 쓰던
사람이 C 로 맞춰 뒀다면 그대로 남아야 한다. 나머지 둘은 새 열쇠이므로 없으면
각자의 기본값이다.

**권장 범위 판정은 `splWeighting` 을 본다.** 지금 「A 일 때만 판정한다」는
규칙이 그대로이고, 보는 값이 음압 줄로 바뀔 뿐이다.

FR 은 **목록에 넣지 않고 Z 로 고정**한다. FR 은 예배당·시스템의 응답
자체를 재는 화면이라, A 를 걸면 저역이 깎인 곡선이 나와 「이 공간은 저음이
부족하다」고 잘못 읽게 된다(지시서 §7). 고를 수 없는 것이 아니라 **고를
까닭이 없는 것**이므로, 화면에 `dB(Z) 고정`이라 적어 숨기지 않는다.

### 왜 셋으로만 나누는가

더 잘게 나누면 **같은 소리인데 탭마다 값이 달라진다.**

- **Leq 를 SPL 과 묶는 까닭**: `dB(C)` 큰 숫자 밑에 `LAeq` 가 적히면 화면이
  스스로 모순된다. 읽는 사람이 매번 「어느 쪽이 맞나」를 풀어야 한다.
- **RTA·Spectrum·Spectrogram 을 묶는 까닭**: 셋이 **같은 FFT 장**을 나눠
  쓴다(`RtaEngine` 하나가 밴드와 연속 스펙트럼을 같이 낸다). 따로 두면
  RTA 의 63Hz 막대와 Spectrum 의 63Hz 봉우리가 다른 값이 된다.
- **PEAK 을 떼는 까닭**: 지시서 §16 이 「Peak 를 SPL Weighting 에 무조건
  종속시키지 않는다」고 못박았다. 킥·스네어의 저역이 A-weighting 에 깎여 순간
  음압을 놓치는 일을 막자는 것이다.

### 설명 줄

고른 칸 **바로 아래 한 줄이 바뀐다.** 창을 띄우지 않는다 — 고르면서
읽어야 뜻이 있다.

| 가중 | 문구 |
|---|---|
| A | `A-weighting — 사람 귀가 저음에 둔한 것을 흉내 냅니다. 소음 규제·청력 기준이 쓰는 잣대이고, 권장 범위 판정은 A 에서만 합니다.` |
| C | `C-weighting — 저음을 거의 깎지 않습니다. 킥·베이스가 실제로 얼마나 센지 볼 때 씁니다. A 와의 차이가 크면 저음이 많다는 뜻입니다.` |
| Z | `Z-weighting — 깎지도 올리지도 않습니다. 들어온 소리 그대로라, 어느 대역에 에너지가 몰렸는지 보는 화면에는 이것이 기본입니다.` |

세 줄 모두 **같은 문구**를 쓴다. 줄마다 다른 설명을 적으면 「A 가 여기서는
이 뜻이고 저기서는 저 뜻인가」로 읽힌다.

## 5. 음압·PEAK — DSP

### 음압은 이미 셋을 나란히 돌린다

`MultiWeightEngine` 이 A·C·Z 세 `SplEngine` 을 동시에 돌린다. 가중을
바꿔도 Leq·MAX 가 비워지지 않는다. **음압 줄을 바꾸는 것은 어느 결과를
집어 오느냐일 뿐이라 계산이 늘지 않는다.**

### PEAK 은 공짜가 아니다

지금 PEAK 은 **가중 필터 앞에서** 잰다(「클리핑은 입력단의 사건이다」).
그래서 A·C·Z 세 엔진의 PEAK 값이 **전부 같다.**

`SplFrame` 에 값을 하나 더한다:

```kotlin
data class SplFrame(
    val peakDbfs: Dbfs,          // 가중 전. 클리핑 판정용. 그대로 둔다.
    val peakClipped: Boolean,    // 그대로 둔다.
    val weightedPeakDbfs: Dbfs,  // 새로 — 필터 뒤 파형의 최고값
    ...
)
```

- **클리핑 판정은 `peakDbfs` 가 그대로 맡는다.** 클리핑은 ADC 에서 일어나는
  일이라 가중 뒤 값으로 재면 못 잡는다.
- **화면의 PEAK 타일은 `weightedPeakDbfs` 를 쓴다.** PEAK 가중이 Z 이면
  두 값이 같다(통과 필터라서) — 지금 동작과 한 치도 다르지 않다.

## 6. 분석 화면 — DSP

지시서 §18: 「UI에서 dBA/dBC/dBZ만 변경하고 실제 DSP 결과가 동일한 상태가
발생해서는 안 된다.」 그래서 **칸마다 실제로 건다.**

```
FFT 칸 전력
   ├─ × 마이크 곡선 보정 (이미 있음, binCorrection)
   └─ × 가중 W(f)        (새로 — 칸마다)
        ├→ 1/3 옥타브로 묶기 → RTA 막대
        └→ 화면 칸으로 줄이기 → Spectrum → Spectrogram
```

`RtaEngine` 이 이미 `binCorrection: DoubleArray?` 로 마이크 곡선을 **칸마다**
걸고 있고, RTA 밴드와 Spectrum 이 **같은 계수**를 쓴다. 가중치를 같은 자리에
곱한다.

```kotlin
/** 가중의 칸별 선형 이득. Z 면 null(곱할 것이 없다). */
fun weightBinGain(w: Weighting, fftSize: Int, sampleRate: Int): DoubleArray?
```

두 배열은 **미리 곱해 하나로 합쳐 둔다.** 뜨거운 반복문에 곱셈이 하나만
남게 하려는 것이고, 곡선이나 가중이 바뀔 때만 다시 만든다.

### 밴드 중심이 아니라 칸마다 거는 까닭

1/3 옥타브 대역은 ±11.6% 폭이다. 저역에서 A-weighting 의 기울기는 옥타브당
12dB 에 가까워 **한 대역 안에서 4dB 가 달라진다.** 대역 중심값 하나를
대역 전체에 걸면 대역 안의 소리 모양에 따라 1dB 가까이 어긋난다. 칸마다
걸고 나서 묶으면 근사가 아니다.

### 건드리지 않는 두 곳

- **하울링 탐지**(`SpectrumSink`)는 지금처럼 보정·가중 **전** 스펙트럼을
  받는다. 봉우리가 둘레보다 얼마나 솟았는지를 보는 것이라, 기울기를
  씌우면 솟은 정도가 달라져 판정이 흔들린다.
- **FR** 은 Z-weighting 밴드값을 받는다. FR 은 신호에서 잡음을 빼는 상대값인데,
  대역 안에서 두 소리의 모양이 다르므로 **가중이 빼기에서 지워지지 않는다.**

FR 이 받는 길은 이렇다. 분석 가중이 Z 이면 밴드가 하나뿐이므로 그것을
그대로 준다. A·C 이면 `RtaFrame` 에 **Z-weighting 밴드 배열을 하나 더 실어**
FR 수집기가 그쪽을 읽는다. 화면에 보이는 배열과 FR 이 읽는 배열의 이름을
갈라 둔다 — 같은 이름이면 언젠가 섞인다.

```kotlin
class RtaFrame(
    val bandsDbfs: DoubleArray,        // 화면용. 곡선 + 가중
    val bandsPlainDbfs: DoubleArray,   // FR 용. 곡선만. Z 면 위와 같은 배열
    ...
)
```

### 비용

가중이 Z 일 때(= 기본값) **계산이 하나도 늘지 않는다** — 곱할 배열이 null
이므로 지금 경로 그대로다. A·C 를 고른 동안만 밴드 묶기가 한 번 더 돈다
(FR 용 Z-weighting 밴드를 따로 내야 해서다). 4096점·48kHz 에서 한 장에
31×2049 번의 곱셈·덧셈이고 초당 20장이므로 폰에서 문제가 되지 않는다.

## 7. Leq 시간 — Session 추가

`LeqWindow` 에 `Session` 을 더한다. 값은 이미 `SplFrame.leqSessionDbfs` 로
나오고 있다 — **받는 곳만 만들면 된다.**

```kotlin
enum class LeqWindow(val labelKo: String, val millis: Long) {
    TenSeconds("10초", 10_000),
    OneMinute("1분", 60_000),
    FiveMinutes("5분", 300_000),
    Session("전체", SESSION_MILLIS),   // 측정 시작부터 지금까지
}
```

`Session` 은 시간 길이가 아니라 **「처음부터」**를 뜻한다. `millis` 를 열쇠로
쓰는 저장 코드가 있으므로 다른 값과 겹치지 않는 표시값을 둔다
(`SESSION_MILLIS = -1L`). 저장된 값이 알 수 없으면 기본값(1분)으로 돌아가는
지금 규칙이 그대로 지켜진다.

**엔진은 Session 을 창 길이로 받지 않는다.** `-1` 을 `leqLong` 의 창 길이로
넘기면 엔진이 상한다. 화면이 `Session` 일 때는 엔진에 **기본 창(1분)을 주고**
표시할 값만 `leqSessionDbfs` 에서 가져온다 — 세션 Leq 는 창이 아니라 누적
합계라 창 길이가 필요 없다.

기록 겉장의 `leqWindowMs` 는 `-1` 이 그대로 들어가고, 리포트는 그 값을
「전체」로 읽는다. **모르는 값이면 「기록 없음」이다** — 0 이나 1분으로
짐작하지 않는다.

30초는 넣지 않는다. 10초와 1분 사이라 실제로 다른 판단을 주지 않는다.

## 8. Spectrum 축 / FFT / Window

### 세로축

**세로축은 이미 로그다** — dB 자체가 로그 눈금이라 여기에 또 로그를
씌우면 이중이 된다. 가로(주파수)축도 이미 로그다(20Hz~20kHz).

「자동/고정」은 눈금의 **범위**를 정하는 것이지 성질이 아니다. 자동은 이미
구현되어 있고 튐 방지까지 들어 있다(천장에 닿으면 즉시 올리고, 내릴 때만
뜸을 들인다).

**기본값만 바꾼다:**

| 화면 | 지금 | 바꿀 것 | 까닭 |
|---|---|---|---|
| Spectrum | 고정 | **자동** | 봉우리가 몇 Hz 인지 찾는 화면이라 축이 값을 따라가야 보인다 |
| Spectrogram | 고정 | **자동** | 같은 장을 쓴다 |
| RTA | 고정 | 고정 (그대로) | 권장 범위 띠와 견준다. 축이 움직이면 판정이 흔들린다 |
| SPL | 고정 | 고정 (그대로) | 같은 까닭 |

### 차트 아래 한 줄

RTA·Spectrum·Spectrogram 차트 아래에 늘 적는다:

```
FFT 4096 · Hann 창 · 48000 Hz · dB(Z)
```

### FFT 크기

**고를 수 있게 한다** — 2048 / 4096 / 8192. 설정 「측정 설정」에 둔다.

| 크기 | 문구 |
|---|---|
| 2048 | `반응이 빠릅니다. 저역 대역이 뭉갭니다.` |
| 4096 | `기본. 예배당에 알맞은 균형입니다.` |
| 8192 | `저역이 또렷합니다. 반응이 느려집니다.` |

대역별 누설 보정표는 이미 (FFT 크기, 샘플레이트) 조합마다 캐시되므로
구조를 바꾸지 않는다. 처음 고를 때 60ms 쯤 걸리고 그다음은 공짜다.

### Window

**Hann 고정.** 차트 아래 줄에 적기만 한다.

창을 바꾸면 대역별 누설 보정표를 **창마다 다시 재야** 한다(지금은 FFT 93번을
돌려 잰다). 예배당에서 얻는 것은 거의 없고 틀릴 자리만 늘어난다.

## 9. 기록에 남는 것

리포트·CSV 가 지금 가중치를 **하나만** 적는다. 셋으로 갈라지면 PEAK 이 어느
잣대인지 알 수 없게 된다.

`SessionMeta` 에 값을 둘 더한다(**있으면 읽고 없으면 넘어가는** 선택 열쇠라
옛 기록이 그대로 읽힌다):

```
weighting          = A      # 지금도 있음 — 음압 가중
peakWeighting      = Z      # 새로
analysisWeighting  = Z      # 새로
```

리포트 「어떤 잣대로 쟀나」 마당에 세 줄로 적는다. 옛 기록은 `weighting`
하나만 있으므로 PEAK·분석 줄에 「기록 없음」이 뜬다 — **짐작해서 Z 라고
적지 않는다.**

## 10. 시험

### DSP

| 시험 | 무엇을 막는가 |
|---|---|
| A·C 응답이 31.5Hz~16kHz 열 지점에서 규격과 0.3dB·0.2dB 안 | 이미 있음. 유지 |
| 1kHz 에서 A·C 가 정확히 0dB | 이미 있음. 유지 |
| **Z 를 고르면 지금 값과 한 치도 다르지 않다** | 회귀 |
| **A 를 고르면 RTA 저역 대역이 실제로 내려간다** | 지시서 §18 — 표기만 바뀌는 일 |
| **칸마다 거는 것과 밴드 중심에 거는 것이 다르다** (62.5Hz 대역) | 「대충 걸어도 같다」는 착각 |
| **FR 은 분석 가중을 바꿔도 같은 곡선을 낸다** | 지시서 §7 |
| **하울링 후보가 분석 가중에 흔들리지 않는다** | 탐지 경로 오염 |
| **가중된 PEAK 이 Z PEAK 보다 낮고, 클리핑 판정은 그대로다** | 클리핑 탐지 손상 |
| **Session Leq 가 에너지 평균이다** (80dB 60초 + 90dB 60초 → 87.4dB) | 지시서 §13 — 산술평균 |
| **Session 을 골라도 엔진 창이 정상이다** (`-1` 이 창 길이로 새지 않음) | 엔진이 상하는 것 |

### 표기

| 시험 | 무엇을 막는가 |
|---|---|
| **세 가중의 단위가 같은 꼴이다** (`dB(?)`) | 이번에 고치는 어긋남의 재발 |
| **세 가중의 이름이 `?-weighting` 꼴이다** | 「무가중」·「Flat」이 다시 섞여 드는 것 |
| **화면 문구 어디에도 「무가중」·「가중 없음」이 없다** (문자열 훑기) | 한 낱말이 네 가지로 갈라지던 상태 |
| **Leq 이름의 가중 글자가 실제 가중을 따른다** | 지시서 §10 — 표기·계산 불일치 |
| **PEAK 이름의 가중 글자가 PEAK 가중을 따른다** | 음압 가중을 잘못 따라가는 것 |

### 설정

| 시험 | 무엇을 막는가 |
|---|---|
| **세 가중이 따로 저장되고 따로 읽힌다** | 한 값이 셋을 덮어쓰는 것 |
| **모르는 이름이 저장돼 있으면 각자의 기본값으로 돌아간다** | 판이 바뀔 때 측정이 멈추는 것 |
| **「기본값으로」가 그 줄만 되돌린다** | 옆 줄까지 지우는 것 |

## 12. 하지 않는 것

- **30초 Leq** — 10초와 1분 사이라 다른 판단을 주지 않는다
- **Window 고르기** — 누설 보정표를 창마다 다시 재야 한다
- **FR 가중 고르기** — 고를 까닭이 없다(§4)
- **가중치를 화면마다 따로** — 같은 소리가 탭마다 다른 값이 된다(§4)
- **세로축에 로그 옵션** — dB 가 이미 로그다(§8)

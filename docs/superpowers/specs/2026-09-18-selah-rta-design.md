# SELAH RTA — 설계 문서 (스펙)

- **작성일**: 2026-09-18
- **제작**: Jesus On Air (JOA)
- **상태**: 확정 (구현 계획 대기)

---

## 1. 무엇을 만드는가

**SELAH RTA — Real-Time Worship Audio Analyzer**

교회 예배당에서 **폰 브라우저로 여는 실시간 주파수 분석기**. 마이크로 소리를 받아
31밴드 막대로 보여주고, **하울링이 시작되면 「어느 EQ 슬라이더를 몇 dB 내릴지」**
알려준다.

### 이름의 유래
`Selah`(셀라)는 시편에 반복해 나오는 음악·예배 지시어다. 영어 표기가 전문 오디오
소프트웨어 브랜드처럼 읽히는 이점도 있다. 상표 혼동을 줄이기 위해 **항상 `SELAH RTA`
로 붙여 쓰고**, 시작 화면과 정보 화면에 `made by Jesus On Air (JOA)` 를 함께 표기한다.

## 2. 왜 만드는가 — 기존 제품과의 차이

| 제품 | 하는 일 | 값 |
|---|---|---|
| Smaart | 라이브 음향 정렬 표준 (데스크톱) | $895 |
| REW | 룸 음향 분석 (데스크톱) | 무료 |
| AudioTool · RTA Pro · Spectroid | 폰에서 막대 보여주기 | 무료~유료 |

**막대를 그려주는 앱은 이미 많다. 그러나 어느 것도 「당신 콘솔의 3.15k 슬라이더를
6dB 내리세요」라고 말해주지 않는다.** 전부 숫자를 읽을 줄 아는 사람을 전제한다.

SELAH RTA 의 자리는 여기다 — **읽는 앱이 아니라 조치하는 앱.**
사용자가 가진 그래픽 EQ 의 밴드 수에 맞춰 **실제로 손에 있는 슬라이더 이름으로**
말해준다. 이것이 만들 이유 그 자체이며, 다른 모든 결정이 여기서 나온다.

| 녹음 저장 | 예배 내용이 담긴다. 처음부터 만들지 않는 것이 안전하다. |
| 측정 마이크 보정 파일(.cal/.frd) 읽기 | 측정용 마이크에 딸려 오는 주파수 보정 곡선을 적용하는 기능. 값어치는 있지만 별개의 일이고, 우선 기기 선택부터 된다. 필요하면 그때 별도로 다룬다. |

### 예배 모드 공통 규칙
- **소리 알림 없음.** 진동과 색으로만 알린다. 예배 중 알림음이 울리면 그게 더 큰 사고다.
- **화면 꺼짐 방지**(Wake Lock). 감시 중에는 폰이 저절로 잠기지 않는다.
- **정지는 길게 누르기.** 짧은 탭으로는 안 꺼진다. 주머니 속 오작동을 막는다.

## 6. 기술 구조

### 6.1 두 덩어리로 자른다

**① 소리를 받는 부분 — 브라우저 의존** (`src/audio/`)

```
getUserMedia({ audio: {
  echoCancellation: false,
  noiseSuppression: false,
  autoGainControl: false,
}})
  → AudioContext → MediaStreamSource → AnalyserNode
```

| 설정 | 값 | 이유 |
|---|---|---|
| `fftSize` | 16384 | 48kHz 기준 bin ≈ 2.93Hz. 하울링 주파수를 짚기에 충분하다. |
| `smoothingTimeConstant` | 0 | 평활은 우리가 직접 한다. 브라우저가 미리 뭉개면 지속성 판정이 흐려진다. |
| 분석 주기 | ~33ms (초당 30프레임) | 0.5초 지속 판정에 15프레임이 쌓인다. |

**세 개의 `false` 가 이 앱 신뢰성의 절반이다.** 자동 음량 조절이 켜져 있으면 큰 소리가
날 때 폰이 알아서 감도를 낮춰 그래프가 거짓말을 한다.

**② 판단하는 부분 — 순수 계산** (`src/analysis/`)

브라우저도 화면도 마이크도 모른다. 숫자 배열만 받아 답을 낸다.

| 모듈 | 하는 일 |
|---|---|
| `bands.ts` | 스펙트럼(2.93Hz 단위) → N밴드 레벨 |
| `howl.ts` | 하울링 판정 |
| `advice.ts` | 컷 권고 산출 |

**이 분리가 이 프로젝트의 핵심이다.** ②는 브라우저 없이 노드에서 그냥 실행된다.
합성 신호를 넣어 실제로 검증할 수 있다 — 화면만 보고 짐작하다 헛도는 길을 구조적으로 막는다.

### 6.2 데이터 흐름

```
마이크
  → AnalyserNode.getFloatFrequencyData()  : Float32Array (dBFS, 8192 bin)
  → toBands(spectrum, bandPlan)           : number[N]        → 막대 화면
  → detectHowl(spectrum, history)         : HowlCandidate?   → 경고
  → toCutAdvice(candidate, bandPlan)      : CutAdvice        → 권고 문구
```

### 6.3 모듈 구성

```
src/
  audio/capture.ts      마이크 열기, AnalyserNode 설정, 프레임 공급
  audio/constraints.ts  제약 조건 + 실제 적용 여부 확인
  analysis/bands.ts     ISO 밴드 정의, 스펙트럼→밴드
  analysis/howl.ts      피크 검출 · 5가지 판정 기준
  analysis/advice.ts    컷 권고량 산출
  analysis/types.ts     공용 타입
  storage/sessions.ts   localStorage 읽기·쓰기
  storage/settings.ts   설정 저장
  content/sources.ts    소스별 가이드 데이터 (7종)
  ui/                   화면 7개
```

## 7. 밴드 계획

ISO 표준 중심 주파수를 쓴다. **사용자의 그래픽 EQ 슬라이더와 이름이 일치해야 하기 때문이다.**

| 밴드 수 | 간격 | 중심 주파수 (Hz) |
|---|---|---|
| **31** (기본) | 1/3 옥타브 | 20, 25, 31.5, 40, 50, 63, 80, 100, 125, 160, 200, 250, 315, 400, 500, 630, 800, 1000, 1250, 1600, 2000, 2500, 3150, 4000, 5000, 6300, 8000, 10000, 12500, 16000, 20000 |
| 15 | 2/3 옥타브 | 25, 40, 63, 100, 160, 250, 400, 630, 1000, 1600, 2500, 4000, 6300, 10000, 16000 |
| 10 | 1 옥타브 | 31.5, 63, 125, 250, 500, 1000, 2000, 4000, 8000, 16000 |

각 밴드 레벨 = 해당 밴드 경계(중심 × 2^(±1/6) 등) 안의 bin 들을 **전력 합산** 후 dB 변환.

**밴드가 적을수록 하울링 대응은 원리적으로 불리하다.** 10밴드에서 4k 를 6dB 내리면
하울링만 죽는 게 아니라 2.8k~5.6k 전체가 내려가 보컬 명료도가 눌린다.
**15밴드 이하에서는 권고와 함께 이 사실을 화면에 띄운다.** 숫자만 주고 부작용을
감추면 앱이 사람을 속이는 셈이다.

## 8. 하울링 판정

### 8.1 왜 어려운가
**소프라노의 고음과 하울링은 둘 다 「좁고 높은 봉우리」다.** 크기만 보면 반드시 오탐한다.

### 8.2 다섯 기준

공개 학술 문헌(van Waterschoot & Moonen, *Comparative Evaluation of Howling Detection
Criteria in Notch-Filter-Based Howling Suppression*, JAES)에 정리된 기준을 직접 구현한다.
남의 코드가 아니라 공개된 방법이다.

| 약어 | 뜻 | 조건 (감도 「보통」 기준) |
|---|---|---|
| **PNPR** | 이웃 대비 솟은 정도 | 봉우리 − (±1/6 옥타브 이웃 중앙값) ≥ **15dB** |
| **PAPR** | 전체 평균 대비 | 봉우리 − 스펙트럼 평균 ≥ **20dB** |
| **PHPR** | 배음 관계가 없는가 | **위아래 모두** 본다 — 2f·3f 지점이 봉우리보다 15dB 이상 낮고, **f/2·f/3 지점도** 15dB 이상 낮을 것 |
| **IPMP** | 같은 자리에 머무는가 | 관찰 창 안에서 **60% 이상**의 프레임에서 같은 bin(±1)이 봉우리 |
| **IMSD** | 자라는가 | 관찰 창 안 레벨 추세 기울기 **≥ 0** |

**관찰 창의 길이는 감도 설정의 지속 시간과 같다** (8.3 참조). 초당 30프레임이므로
「보통」의 0.5초는 15프레임, 「낮음」의 0.7초는 21프레임, 「높음」의 0.35초는
약 10프레임이 된다.

**다섯 개를 모두 만족할 때만 경고한다.** 가르는 것은 뒤의 셋이다 —
사람과 악기는 **배음이 있고 음정이 움직인다.** 하울링은 **단일 주파수가 고정된 채 자란다.**

> **PHPR 은 반드시 아래쪽도 봐야 한다.** 위쪽(2f·3f)만 보면 220Hz 목소리의
> **440Hz 배음 자체**가 「그 위에 배음이 없다」는 이유로 하울링으로 통과한다.
> f/2·f/3 에 큰 봉우리가 있으면 이 봉우리는 **남의 배음**이므로 하울링이 아니다.

### 8.3 감도 설정

| 감도 | PNPR·PAPR 문턱 | 지속 시간 |
|---|---|---|
| 낮음 (오탐 적게) | 기본 +3dB | 0.7초 |
| **보통** (기본) | 기본값 | **0.5초** |
| 높음 (빨리 잡게) | 기본 −3dB | 0.35초 |

## 9. 컷 권고 산출

```
prominence = PNPR 값 (dB)
cutDb      = clamp( round((prominence − 12) / 3) * 3, 3, 6 )
```

**최대 6dB, 3dB 단위.** 앱은 실제 시스템의 여유(루프 게인)를 모른다. 과하게 깎으라고
하지 않는다. 한 번 깎고도 계속 나면 다시 경고가 뜨고, 그때 또 깎으면 된다.

### 출력 형태
- **그래픽 EQ (기본)**: 「**3.15k 슬라이더** → 약 **6dB** 내리기」
  탐지한 정확한 주파수를 설정된 밴드 수에 맞춰 가장 가까운 중심 주파수로 반올림한다.
- **파라메트릭 EQ (설정에서 켬)**: 정확한 주파수(예: 3,184Hz)와 `Q ≈ 8` 을 함께 표시.
  값은 이미 계산돼 있으므로 표시만 바꾼다.
- **15밴드 이하**: 위 문구 + 「이 대역 전체가 함께 내려갑니다」 경고.

## 10. 소스별 가이드 (7종)

### 10.1 카드 구성 (모든 소스 공통)
1. **주파수 지도** — 가로 띠. 어느 대역이 무슨 역할인지 한눈에
2. **먼저 할 것** — 하이패스 권장값
3. **흔한 문제 3가지** — 증상 → 대역 → 조치. 각 항목에 **「→ 이 대역 RTA 로 보기」**
4. **하울링 주의 대역** (마이크 소스) 또는 **자리 다투는 대역** (라인 소스)

**「→ 이 대역 RTA 로 보기」가 가이드를 읽을거리가 아니라 도구로 만든다.**
「먹먹하다」를 누르고 설교자가 말하는 동안 200~400Hz 가 실제로 솟는지 눈으로 확인한다.

### 10.2 모든 카드 하단 고정 문구
> 이 숫자는 **출발점이지 정답이 아닙니다.** 예배당마다 다릅니다 — 가이드를 보고
> 짐작한 뒤 RTA 로 확인하고, 맞으면 조정하십시오. 숫자만 보고 그대로 넣으면 더
> 나빠질 수 있습니다.

### 10.3 내용

#### ① 강대상 설교자 (구즈넥 · 핀마이크)
- **하이패스** 80~100Hz — 연단 진동·에어컨 저역. 말소리는 그 아래에 없다.
- **지도**: ~80 잘라냄 / 200~400 먹먹함 / 400~1k 기본 음색 / 1k~4k 말 또렷함 / 6~8k 치찰음
- **문제**: 먹먹함 → 200~400Hz 컷 · 말이 안 들림 → 2~4kHz 부스트(볼륨보다 낫다) ·
  「스-·츠-」가 쏨 → 6~8kHz, 조금만 또는 디에서
- **하울링 주의**: **250Hz · 1kHz · 3~4kHz.** 지향성 마이크가 모니터를 향할 때 가장 잦다.
  **각도부터 보고, 그래도 나면 깎는다.**

#### ② 찬양인도 보컬 (핸드마이크)
- **하이패스** 100~120Hz
- **지도**: ~100 잘라냄 / 150~250 근접효과 부풀음 / 250~1k 몸통 / 3~5k 존재감 / 6~8k 거침 / 10k+ 공기감
- **문제**: 웅웅거림 → 150~250Hz 컷(마이크에 가까이 붙을수록 심해진다) ·
  반주에 묻힘 → 3~5kHz · 거칠고 쏨 → 6~8kHz
- **하울링 주의**: **315Hz · 800Hz · 2.5~4kHz.**
  **핸드마이크는 움직이므로 예측이 어렵다.** 인도자가 모니터 앞으로 걸어갈 때 집중된다.

#### ③ 신디사이저 (라인 · DI)
- **하울링 없음** — 마이크를 쓰지 않으므로 원리적으로 나지 않는다.
- **지도**: 전 대역. 이 악기가 가장 넓다.
- **문제**: 저역이 탁함 → 100Hz 이하 컷해 **베이스에 자리를 내준다** ·
  보컬이 묻힘 → 1~3kHz 를 살짝 비운다 · 넓게 퍼져 산만 → 스테레오 폭 줄이기
- **자리 다툼**: 베이스(60~120Hz) · 보컬(1~3kHz)

#### ④ 어쿠스틱기타 (픽업 · DI)
- **하이패스** 80Hz
- **지도**: ~80 잘라냄 / 80~200 바디 공명 / 200~250 통울림 / 250~1k 몸통 / 3~5k 픽업 날카로움 / 8k+ 현 소리
- **문제**: **박스 소리·통울림 → 200~250Hz 컷 (가장 흔한 문제)** ·
  픽업 특유의 얇고 날카로운 소리 → 3~5kHz · 답답함 → 8kHz 이상
- **하울링 주의** (마이크를 함께 쓸 때만): **100~200Hz 바디 공명.**
  EQ 보다 **사운드홀 커버**가 먼저다.
- **자리 다툼**: 보컬(2~4kHz)

#### ⑤ 베이스기타 (DI)
- **하이패스** 40Hz — 그 아래는 스피커만 괴롭힌다.
- **지도**: ~40 잘라냄 / 40~120 무게 / 200~400 탁함 / 700~1k 손가락·현 소리 / 2k+ 거의 없음
- **문제**: 소리가 있는지 없는지 모름 → **700Hz~1kHz** (저역을 올리는 게 아니라 여기를 올린다) ·
  웅웅거림 → 200~400Hz 컷 · 킥드럼과 뭉침 → 아래 참조
- **하울링 없음**
- **자리 다툼**: **킥드럼.** 킥 60Hz / 베이스 100Hz 로 서로 자리를 나눈다.

#### ⑥ 일렉기타 (앰프 마이킹 또는 모델러 직결)
- **하이패스** 100Hz
- **지도**: ~100 잘라냄 / 100~400 저역 몸통 / 400~800 박스 소리 / 800~2k 몸통 / 2~4k 쏘는 소리 / 6k+ 거침
- **문제**: 먹먹하고 답답 → 400~800Hz 컷 · 귀를 찌름 → 2~4kHz ·
  보컬을 덮음 → 기타와 보컬이 2~4kHz 에서 겹친다. **「귀를 찌른다」와 같은 대역이니 이미 깎았다면 더 깎지 말고 볼륨을 내린다**
- **하울링 주의**: **앰프를 마이킹할 때만.** 모델러 직결이면 나지 않는다.
- **자리 다툼**: 보컬(2~4kHz) · 신디사이저(1~3kHz)

#### ⑦ 전자드럼 (라인)
- **하울링 없음**
- **지도**: 킥 50~80 / 스네어 몸통 200 · 때리는 소리 5k / 탐 100~300 / 하이햇·심벌 8k+
- **문제**: 킥이 안 느껴짐 → 50~80Hz · 스네어가 약함 → 5kHz(200Hz 가 아니다) ·
  심벌이 쏨 → 8kHz 이상 조금만
- **주의**: **전자드럼 내장 음원은 이미 EQ 가 되어 있다.** 라인이라 다루기 쉬운 대신,
  과하게 만지면 오히려 나빠진다. 조금씩.
- **자리 다툼**: **베이스.** 킥 60Hz / 베이스 100Hz.

## 11. 저장 데이터 (localStorage)

```ts
// key: "selah.settings"
type Settings = {
  bandPlan: 31 | 15 | 10;
  calibrationDb: number | null;   // 절대 SPL 보정 오프셋. null 이면 상대 레벨만 표시
  sensitivity: "low" | "normal" | "high";
  showParametric: boolean;
};

// key: "selah.sessions"  (최근 50개, 초과 시 오래된 것부터 삭제)
type Session = {
  id: string;
  startedAt: number;              // epoch ms
  endedAt: number;
  mode: "rehearsal" | "worship";
  bandPlan: 31 | 15 | 10;
  calibrationDb: number | null;
  bandPeak?: number[];            // 밴드별 세션 최고치 — 리허설 모드에서만
  bandAvg?: number[];             // 밴드별 평균 — 리허설 모드에서만
  howls: {
    hz: number;                   // 탐지된 정확한 주파수
    bandHz: number;               // 반올림된 슬라이더 이름
    atMs: number;                 // 세션 시작 기준 경과
    cutDb: number;
    prominence: number;
  }[];
  gaps: { atMs: number; durationMs: number }[];  // 백그라운드 등으로 끊긴 구간
};
```

**`gaps` 를 반드시 남긴다.** 측정이 끊긴 것을 모른 채 기록을 비교하면 틀린 결론에 이른다.

## 12. 오류 처리 — 조용히 실패하지 않는다

| 상황 | 앱이 하는 일 |
|---|---|
| 마이크 권한 거부 | 그 폰·브라우저에 맞는 허용 방법 안내 |
| HTTPS 가 아님 (`getUserMedia` 없음) | 「이 주소에서는 마이크를 열 수 없습니다」 + 올바른 주소 |
| **`autoGainControl` 등을 못 끄는 브라우저** | **화면 상단에 경고 배지를 계속 띄운다.** 숨기지 않는다 |
| 앱이 백그라운드로 감 | 측정 중단 표시. 복귀 시 「N초 비었음」 명시 + `gaps` 에 기록 |
| Wake Lock 미지원 | 「화면이 꺼질 수 있습니다」 안내 후 계속 진행 |
| 마이크가 갑자기 끊김 (이어폰 분리 등) | 즉시 정지 + 알림. **멈춘 채로 정상인 척하지 않는다** |
| localStorage 사용 불가 (시크릿 모드 등) | 측정은 되고 저장만 안 됨을 알린다 |

`constraints.ts` 는 `getSettings()` 로 **요청한 제약이 실제로 적용됐는지 확인**한다.
요청만 하고 확인하지 않으면 꺼진 줄 알고 넘어간다.

## 13. 테스트

판단하는 부분이 순수 함수이므로 **브라우저 없이 노드에서 합성 신호로 실제 실행한다.**

| # | 넣는 것 | 기대 |
|---|---|---|
| 1 | 1kHz 사인파 | `1000` 밴드가 최대 |
| 2 | 핑크노이즈 | 31밴드가 대체로 평탄 (밴드 묶기 검증) |
| 3 | 3,184Hz 좁은 봉우리, 커지며 지속 | 하울링으로 판정, `bandHz = 3150` |
| 4 | **배음이 있는 신호 (목소리 흉내: 220 + 440 + 660Hz)** | **하울링 아님** |
| 5 | 음정이 움직이는 좁은 봉우리 (글리산도) | 하울링 아님 (IPMP 불만족) |
| 6 | #3 을 밴드 수 10 으로 | 권고가 `4000` 슬라이더로 바뀜 |
| 7 | prominence 15dB / 21dB | `cutDb` 가 각각 3 / 6 |

**#4 가 이 앱의 생사다.** 소프라노가 고음을 낼 때마다 빨간 경고가 뜨면 아무도 쓰지 않는다.

## 14. 법적 · 윤리 검토 (2026-09-18 조사)

### 14.1 특허
하울링 관련 특허는 거의 전부 **자동으로 소리에 개입하는 것**에 걸려 있다.

| 기술 | 특허 | 상태 |
|---|---|---|
| Sabine FBX (자동 피드백 제거의 원조, 1991) | US 5,245,665 | 1993년 등록 → 만료 |
| Panasonic 하울링 검출·억제 | US9154874B2 | Expired – Fee Related |
| dbx AFS · Shure 등 | 자동 노치 필터 | 자동 억제가 청구 범위 |

**SELAH RTA 는 소리 경로에 끼어들지 않는다.** 듣고 사람에게 말해줄 뿐,
필터를 넣지 않고 게인을 만지지 않는다. 이 특허군의 사정거리 밖이다.
**3장의 「자동 EQ·자동 컷을 만들지 않는다」가 이 성격을 지키는 장치다.**

판정 기준(PAPR·PHPR·PNPR·IPMP·IMSD)은 공개 학술 문헌의 방법을 직접 구현한 것이다.

### 14.2 이름
- **Selah Audio** — 미국 커스텀 스피커 제조사가 실재한다 (하드웨어, 소프트웨어 아님)
- USPTO 에 SELAH 상표 다수 (음악 녹음물 Reg. 6249819, 음료, 유리, 웰니스, 종교 잡지 등).
  **소프트웨어 분야 단독 등록은 검색 범위에서 찾지 못했다**
- 앱스토어·플레이스토어에 SELAH 라는 오디오 분석 앱 없음

**위험은 낮다.** 완화책: 항상 `SELAH RTA` 로 붙여 쓰고 `by Jesus On Air (JOA)` 병기.

> **이 검토는 참고용이지 법적 판단이 아니다.** 교회 안에서 쓰고 무료로 나누는
> 수준이면 충분하지만, **판매·유료화 시에는 특허청 키프리스와 USPTO 정식 검색을
> 따로 해야 한다.**

### 14.3 라이선스
기존 RTA 코드를 가져오지 않고 직접 구현한다. 의존성은 React·Vite·Tailwind(전부 MIT)와
브라우저 내장 Web Audio API 뿐이며 외부 오디오 라이브러리를 쓰지 않는다.

### 14.4 앱에 넣을 문구 (정보 화면 + 첫 실행 시)
- **「이 앱은 소리에 개입하지 않습니다 — 듣고 알려줄 뿐입니다」**
- **「폰 마이크는 측정용 장비가 아닙니다. 참고용이며 소음 규제·안전 판단에 쓰지 마십시오」**

두 번째가 특히 중요하다. 누군가 이 앱의 숫자로 소음 민원에 대응하면 곤란해진다.

## 15. 측정 기준 — 상대 레벨과 절대 SPL

**기본은 상대 레벨.** 「250Hz 가 옆 대역보다 12dB 높다」처럼 비교만 보여준다.
하울링·문제 대역 찾기에는 이것으로 충분하고, 틀린 숫자를 보여주지 않아 안전하다.

**보정을 넣으면 절대 dB 표시.** 설정에서 소음계나 다른 기기와 비교한 차이를 한 번
입력하면 그만큼 더해 보여준다. **이때 화면에 「근사치」임을 명시한다.**

## 15.1 외부 연결 마이크

폰 내장 마이크의 한계(보정 안 됨, 저역 롤오프, 처리 개입)는 이 앱 전체 설계의
전제였다. **USB 등으로 외부 마이크를 꽂으면 그 전제가 바뀐다** — 측정용 마이크는
응답이 평탄하고 보정되어 있어 숫자를 훨씬 믿을 수 있다. 그래서 어떤 입력으로
재고 있는지를 **고를 수 있고, 화면에 보이게** 한다.

### 무엇을 하는가
- 설정에서 **입력 기기 목록**을 보고 고른다. 「시스템 기본」도 항상 선택지에 둔다.
- 고른 기기는 기억한다. 다음에 열 때 같은 기기가 있으면 그대로 쓴다.
- **측정 화면에 현재 입력 기기 이름을 띄운다.** 내장으로 재고 있는지
  외부로 재고 있는지 모른 채 숫자를 믿는 일이 없어야 한다.
- 측정 중 기기가 빠지면 즉시 알리고 멈춘다(이미 있는 「연결이 끊겼습니다」 경로).
- 기기가 꽂히거나 빠지면 목록을 자동으로 갱신한다(`devicechange`).

### 기기별 실제 동작 — 안 되는 것을 되는 척하지 않는다
| | 동작 |
|---|---|
| **안드로이드 크롬** | USB OTG 로 연결한 마이크·오디오 인터페이스가 목록에 뜨고 골라 쓸 수 있다 |
| **아이폰 사파리** | 기기 목록을 제대로 내주지 않는다. iOS 는 **연결하면 알아서 그쪽으로 넘어가는** 방식이라 고르는 화면이 무의미할 수 있다 |

목록이 하나뿐이거나 이름이 비어 있으면 **그 사실을 화면에 적는다** —
「이 브라우저는 입력 기기를 고를 수 없습니다. 연결한 기기로 자동 전환됩니다.」

### 기기 이름이 처음엔 안 보이는 문제
브라우저는 **마이크 권한을 한 번 허용하기 전까지 기기 이름을 빈 문자열로 준다.**
그래서 처음 열면 「마이크 1·마이크 2」로만 보인다. 이름을 지어내지 말고,
번호로 표시하면서 「한 번 허용하면 실제 이름이 보입니다」를 함께 띄운다.

### 고른 기기가 사라졌을 때
저장해 둔 기기가 더 이상 없으면 `deviceId: { exact }` 요청이 실패한다.
**조용히 내장 마이크로 넘어가면 안 된다** — 사용자는 외부 마이크로 재고 있다고
믿은 채 다른 숫자를 보게 된다. 기본 기기로 넘어가되 **반드시 화면에 알린다.**

| 기본 31밴드, 설정 가능 | 권고가 실제 손에 있는 슬라이더 이름으로 나와야 쓸모가 있다 |
| 폰 안에만 저장 | 서버 없이 완결된다. 예배 소리를 서버에 올리지 않는다 |
| 예배 모드 압축형 (막대 유지) | 하울링은 갑자기 나지 않는다. **터지기 전에 조짐을 본다** |

| 가이드 + RTA 연동 | 가이드가 읽을거리가 아니라 도구가 된다 |
| **자동 EQ 를 만들지 않음** | 성격이 달라지고 특허군에 들어간다. **처음부터 선을 긋는다** |
